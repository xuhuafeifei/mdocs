> **本次变更：已同意（2026-08-06）** — ① 仿 Claude 合成 tool 往返 ② hydrate 去重且越新越先 ③ 前端本轮结束后清空标签  
> **本次变更：已同意（2026-08-06）** — Agent 管理 tools（list/create/update/delete）；create/update 出表单卡+倒计时；**name 为本访客唯一索引键**（英文数字下划线）  
> 依据：[`需求分析.md`](./需求分析.md)

## 方案摘要

私人 **用户 skill**：配置 CRUD → 两入口引用 → 请求带 `skillNames` → jsonl 只存引用 → hydrate 时 **合成 `load_user_skill` tool 往返**（去重、新优先）→ `prompt(原文)`；前端本轮结束后清空选中。Agent 也可通过 tools 管理 skill（list 无卡；delete 按名；create/update 出表单卡）。

```text
chat body: { message, skillNames[] }
        ↓
appendUser（message_end）：{ content, skillNames }   ← 无全文、无假 tool 轨迹
        ↓
hydrate / toPiMessages（仅内存）:
  从新到旧标定每个 name 的「展开点」（越新越先）
  再从旧到新组 messages；仅展开点灌全文
  形态：assistant toolCall + toolResult，再接该轮 user 原文
        ↓
本轮：预置「本轮展开点」的假 tool 对 → prompt(原文)
        ↓
前端：本轮 SSE 正常结束后清空 skill 标签
```

### 命名与唯一性

| 项 | 约定 |
|----|------|
| 唯一键 | `(owner_visitor_id, name)` |
| name 字符 | 仅 `[A-Za-z0-9_]`，≤64 |
| 简介 | 可用中英文，≤200 |
| 交互 / 索引 | **一律用 name**；id 仅库内主键；旧 jsonl `skillIds` 读取兼容 |

### 与手册 skill 的边界

| | 手册 skill | 用户 skill |
|--|-----------|------------|
| 存储 | 包内 `agent-skills` | SQLite `agent_user_skills` |
| 进入模型 | `mdocs_manual_*`（真调用） | 合成 `load_user_skill`（不进真实 `tools[]`） |
| 配置 | 发版构建 | 设置页 CRUD |

### 三层职责

| 层 | 做 | 不做 |
|----|----|------|
| 前端 | 引用 UI；发 `skillNames`；**本轮结束后清空选中**；响应 `skill_form_card` | 不展开、不传正文 |
| 传输 / 落盘 | `content` + `skillNames` | 不存展开结果 / 假 tool 轨迹 |
| Agent | 用时查库、合成往返、去重新优先；CRUD tools | 不把正文拼进 `systemPrompt` |

## 展开形态（已同意）

### 单 skill 合成对（Pi 消息）

```text
{ role: "assistant", content: [
    { type: "toolCall", id: "uskill-…", name: "load_user_skill",
      arguments: { id, name } }
  ], stopReason: "toolUse", ... }

{ role: "toolResult", toolCallId: "uskill-…",
  content: [{ type: "text",
    text: "[user skill loaded]\n<skill id=\"…\" name=\"…\">\n…body…\n</skill>" }],
  isError: false, ... }
```

- tool 名固定 `load_user_skill`，**不**注册进真实 `tools[]`。
- 用户原文仍由 **`prompt(message)`** 追加（与假 tool 对分离，避免原文写两遍）。
- 禁止原地把原文里的 tag 换成全文。

### 去重与顺序（已同意）

| 规则 | 含义 |
|------|------|
| **去重** | 单次请求的 hydrate 内，同一 `skillId` 全文最多展开一次 |
| **越新越先** | 从新到旧扫描各轮 `skillIds`，每个 id 的展开点 = **最新一次出现**；更早同 id 跳过 |
| **本轮优先** | 本轮若带该 id，展开点落在本轮（贴在 `prompt` 原文前） |
| **历史展示** | 旧轮 `skillIds` 仍可给 UI「Skill×N」；未轮到展开点则不灌正文 |

组 messages 仍按时间 **从旧到新**；只是「谁有资格带假 tool 对」由新优先标定。

### 本轮与 prompt 的关系（已澄清）

```text
messages = [ ...历史 hydrate（含其展开点上的假 tool 对）...,
             ...本轮假 tool 对（若本轮是展开点）... ]
prompt(用户原文)     ← 唯一追加本轮原文；落盘靠 message_end → appendUser
```

- 同一句用户原文：**只走 `prompt`，不预置进 initialState。**
- 假 tool 对：只预置进 `messages`，**不落盘**（无对应 message_end 落盘逻辑）。

### system 补充（已同意）

`NORMAL_RULES` / `CODING_RULES` 增加：

> 若上下文出现 `load_user_skill` 的 tool 结果（或 `<skill>` 块），表示宿主已加载的私人 Skill，必须遵照执行；不得声称未激活或「只是粘贴」。

## 前端选中态（已同意）

| 项 | 约定 |
|----|------|
| 选中含义 | **本轮附件**：随下一次发送带上 `skillNames` |
| 选择 UI | 点击 **Skill** → **向上弹出**列表面板（名称 + 简介，类 Cursor）；多选；**无 slash** |
| 清空时机 | 本轮 chat **SSE 正常结束**后清空输入区标签 |
| 取消发送 / 出错 | 可保留选中，方便重发 |
| 叉掉单个 chip | 从当前选中移除；若已发送则不影响已落盘历史 |
| 历史气泡 Skill×N | 只读展示，不是输入区状态 |

不采用「跨话题 sticky 常驻」；「聊完本轮就清空」= 发完并成功结束后清。

## 落盘（不变）

```ts
{ role: "user"; content: string; skillNames?: string[]; ts: string }
```

assistant 行不变。对外 session API 带回 `skillNames`（旧行 `skillIds` 读入时并入）。

## 配置与 API

CRUD + chat `skillNames`；body ≤32KiB；单轮最多 5 个；缺失 name 静默跳过；name 非法 → `skill_name_invalid`；重名 → `skill_name_taken`。

## 风险与回滚

| 风险 | 缓解 |
|------|------|
| 合成 tool 不在 tools[]，provider 挑剔 | DeepSeek 实测；失败则退回 user `<skill>` + system |
| 去重后历史轮「看似引用但无正文」 | 预期行为；本轮仍带则本轮有全文 |
| 回滚 | hydrate 开关切旧逻辑；前端可不清空 |

## 测试要点

- [ ] 本轮 1 个 skill：假 toolCall + toolResult + prompt 原文；jsonl 仅 content+ids。
- [ ] 连续两轮同 skillIds：context 中该 skill **全文只出现一次**（落在较新轮）。
- [ ] 前端：成功 `done` 后选中清空；历史气泡仍可有 Skill×N。
- [ ] 无 skillIds：与改前一致。
- [ ] 验证类提问应遵从 skill，而非否认未加载。
