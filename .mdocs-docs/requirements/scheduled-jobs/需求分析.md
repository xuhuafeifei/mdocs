# scheduled-jobs — 需求分析

> **状态**：草案  
> 一句话：

## 背景

用户想要mdocs能够长时间监控某款产品的价格，并进行记录。当价格跌破某个阈值，能够及时提醒用户。采集的数据需要以可视化面板的形式渲染。

## 目标

能力拆分：
上述业务背景，要求 mdocs 提供一下几种能力。

1. 定时任务能力。mdocs 需要能后台运行并进行数据的处理
2. 数据采集与可视化能力。定时任务采集得到的数据需要持久化，并可以依据沉淀数据进行可视化的渲染
3. 数据监控与通知。mdocs 可监控 后台任务采集得到的数据，当满足一定条件，可以触发通知能力

目前 mdocs 提供的能力入口通过创建文档的文档类型区分，新能力不同于已有的md, html, sheet，因此新增入口 后台定时任务，以此提供定时相关能力。

### 定时任务能力

用户通过点击创建文档按钮后，出现 4 种类型，Job 类型是新增能力。

在 UI 设计上，比起 md, sheet, html这类偏向文本编辑 + 数据渲染的能力，Job 文档在 UI 呈现上更偏向于操作面板。

一个 后台定时任务 文档等于一个后台运行的 定时 任务，任务产生的数据可以在用户创建的 后台定时任务 文档中可视化显示。

对于运行 定时任务 产生的数据，用户可以按照一定规则进行监控配置，当数据满足用户配置的监控规则后，mdocs 系统触发告警能力，单独通知创建 Job 的用户。

> 为了方便叙述，后台定时任在概念上等同于定时任务

### 配置 定时任务 功能

用户创建 定时任务 文档后，整体 UI 上可分为三大板块。第一个板块是 定时任务 运行配置能力。用户的配置决定 定时任务 的运行时机以及运行方式。

- 运行时间配置。一期，用户输入 cron 表达式来控制 定时任务 触发时间。二期可以通过 AI ，让用户通过描述，让 AI 配置具体的 定时任务 触发时间。
- 运行任务配置。
  - 目前支持的任务类型是 智能助手类型。具体含义是，定时任务触发时，启动 智能体处理用户任务需求。
  - 智能助手类型
    - 提示词配置。定时任务启动后，会更具用户配置的提示词启动智能体。智能体输出的数据可以在定时任务配置界面显示。
    - 智能体输出数据配置。用户需要规定横坐标的含义，以及纵坐标的含义。智能体运行时会读取输出配置来产出不同类型的数据，产出的数据最终会在定时任务栏目的第二板块可视化渲染。一期不支持不配置智能体输出数据配置

定时任务模块第二个板块，是可视化数据呈现，他的数据来源是定时任务智能体产生的数据。在联动关系上，用户必须配置了智能体类型 + 配置输出数据配置后才会呈现，一期只能这么配置。所以数据呈现板块一期常驻。

- 数据板块通过二维坐标系的方式呈现，横坐标对应板块一用户配置的坐标，纵坐标对应用户配置的纵坐标，其中数据来自于智能体产出的输出。一期数据全量显示，不做截取处理。

监控配置是定时任务模块第三个板块，对智能体产出的数据做出监控处理。用户可以配置系统支持的监控规则，当数据满足告警要求后，mdocs 系统会触发通知用户，通知能力由邮箱通知系统

智能体产生增量数据，会触发监控规则校验。如果满足监控条件，触发告警。告警通知能力借助邮箱系统通知系统实现。

- 目前只支持增量数据的规则配置，只支持设置阈值。规则当增量数据<=某个数值时，符合规则触发告警。配置的规则必须触发告警，一期只能提醒自己。

### 邮箱通知能力

邮箱通知能力，沟通的双方是系统和用户。可以说，mdocs 的邮箱一期只是单向沟通，发送方是 mdocs 系统，接收方是用户。目前只适配于 定时任务告警通知场景，该场景下，邮箱默认只通知创建配送任务的用户。

- 邮箱系统不对外提供能力，调用方只有内部系统
- 收到邮箱的用户，可以在左下角用户头像右侧的邮箱按钮查看。未读信息会以未读数量的形式显示，阅读后数量消失
- 点击邮箱按钮后，出现新的弹框，弹框以横向列表的形式，按照时间顺序从上到下降序排序，显示消息，如果未读，则在信息右上角加上红色未读标记。点击后，红色标记消失
