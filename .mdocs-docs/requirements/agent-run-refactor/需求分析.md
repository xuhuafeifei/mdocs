# Agent run 拆分（tool-registry + pi-run）— 需求分析

> 一句话：Phase 1 已把 tool→SSE 挪出 `run.ts`；本期（Phase 2）按「纯 tool → template 注册 → registry 按 mode 取」重整装配，`run.ts` 只调 registry。

## 背景

`run.ts` 里仍手写 `mode === coding ? createCodingTools : createAccountTools`，再拼 `createSkillTools`。  
`tools-account.ts` / `createCodingTools` 已是拼装层，和「每个 tools-*.ts 只定义纯 function tool」目标冲突。

举证：`run.ts` ~103–115；`tools-account.ts`；`tools-coding.ts` `createCodingTools`；`context-usage.ts` `estimateToolsTokens`。

## 目标（Phase 2）

- **纯 tool 文件**：`tools-documents` / `domains` / `visitors` / `choice` / `overwrite` / `coding` 写 tools / `tools.ts`（手册）只导出 `createXxxTools(deps)`，**不再**互相拼 mode。
- **`tools-template`**：把上述纯工厂统一登记成可引用的组（catalog / group id）。
- **`tools-registry`**：对外 `createToolsForMode(mode, ctx)`（名可微调）；按 mode 从 template 取组合；**`run.ts` / `context-usage` 只调 registry**。
- 行为与现网一致：Ask = 手册 + 账号结构 + choice + overwrite；Coding = 手册 + 账号结构 + choice + 帮写 buffer，**无** overwrite。

## 非目标（本期不做）

- 不抽 `pi-run`、不改 tool→SSE（已落地）、不改产品语义 / 前端
- 不重写各 tool 的 `execute` 业务逻辑（除非为拆拼装所必需的 import 调整）

## 验收标准

- [x] `run.ts` 无直接 import `createAccountTools` / `createCodingTools` / `createSkillTools` 做拼装
- [x] `tools-account.ts` 已删除
- [x] Ask / Coding 挂载的 tool 名集合与现网一致（`tools-registry.test.ts`）
- [x] 相关单测通过；context usage 估算走 registry
