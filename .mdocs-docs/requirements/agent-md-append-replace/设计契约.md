# Agent MD append / replace + 写后提示重读 — 设计契约

> **状态**：已同意（2026-10-21）

## 方案摘要

| 项 | 约定 |
|----|------|
| Session | **不**持久化写工具全文；成功写后落一条**短** tool 交换，文案明确「正文已更新，请重新 get_document」 |
| 新工具 | `append_document`、`replace_document_markdown` |
| 文本层 | 一律在 **Markdown 字符串**上操作：`get_document` 默认 `format=md`（`lexicalJsonToMarkdown`）；`replace` 同层找换后再 `markdownToLexicalJson` 写回 |
| 范围 | **一期仅 `fileType=md`**；html/sheet/graph 拒绝 |
| 确认卡 | append / replace：**不出**「直接覆写/帮写」卡（局部、可预期）；overwrite：**保持**现有卡 |
| 发布 | 与 overwrite 相同：线性 `updateDocument` + `localBaseCommitId = 当前 head` |

## 1. 写后「请重读」信号（反增肥）

### 为何不用「把新正文写进 session」

旧 `get_document` 全文已在历史里；再存一份新全文 → token 翻倍，且模型仍可能混用两份。

### 做法

成功写库后（`overwrite_document` / `append_document` / `replace_document_markdown`），调用与 `get_document` 相同的 `appendToolExchange`，但：

| 字段 | 值 |
|------|-----|
| `toolName` | 实际工具名（如 `append_document`） |
| `arguments` | **精简**：`{ documentId }`（replace 可加 `findPreview` 截断前 80 字；**禁止**整篇 content） |
| `resultText` | 固定短模板，例如：`DOCUMENT_CHANGED documentId=<id> headCommitId=<id> displayName=<name>\n正文已在服务端更新。此前 get_document 结果已过期；若还要基于正文继续，必须重新调用 get_document。` |

实现：扩展 `shouldPersistToolResult`，对上述三工具返回 true；**落盘前**用专用 `extractWritePersistPayload` 把 `arguments`/`resultText` 收成短文本（即使模型侧 tool result 含更多字段，session 只存瘦身版）。

同轮内：模型已看到完整 tool result（可含 status）；跨轮靠这条短提示 + 旧 get 仍在，但文案强制重读。

**不做**一期：hydrate 时涂改/删除旧 `get_document`（若仍不够再开增量）。

## 2. `append_document`

- **label**：追加文档正文  
- **description**：在 `.md` 文档末尾追加 Markdown。不覆写已有内容。写后直接发布。写后请重新 get_document。整篇替换用 overwrite_document；替换片段用 replace_document_markdown。  
- **parameters**：
  - `documentId: string`
  - `content: string`（追加的 Markdown）
  - `separator?: string`（默认 `"\n\n"`；若已有正文非空则先拼 separator 再拼 content；原文为空则不加 separator）
- **流程**：edit 权 → get text + head → 仅 md → `next = plain + (plain.trim() ? sep : "") + content` → `updateDocument` 线性写  
- **返回**：`status, documentId, displayName, headCommitId, appendedChars`（可含；session 落盘仍用短模板）
- **上限**：单次 `content` 建议 ≤ 100_000 字符（与常识一致即可）

## 3. `replace_document_markdown`

- **label**：替换文档片段  
- **description**：在 Markdown 源码上精确查找并替换片段（段落级改动）。`find` 必须在文中出现；默认要求恰好 1 次，否则失败。多次时传 `occurrence`（1-based）。写后直接发布。写后请重新 get_document。  
- **parameters**：
  - `documentId: string`
  - `find: string`（非空）
  - `replace: string`（可为 `""` 表示删除该段）
  - `occurrence?: number`（默认要求唯一；传则替换第 n 次出现）
- **流程**：
  1. 读 md 正文 + head  
  2. 统计 `find` 出现次数；0 → 错误；>1 且无 occurrence → 错误并返回 `matchCount`；有 occurrence 越界 → 错误  
  3. 只替换目标那一次 → `updateDocument`  
- **不做**：正则、模糊匹配、按标题自动扩选区（需要时 Agent 先 get 再自己组 `find` 字符串）
- **返回**：`status, documentId, headCommitId, matchCount, occurrence, replaced`

## 4. 系统提示（摘录）

在表格/`overwrite` 指引旁补充：

- **优先**文末追加 → `append_document`
- **优先**改某一段/几句 → `replace_document_markdown`（`find` 用 get 到的原文精确子串；多处连续 replace）
- 仅整篇重写 / 空文 / html → `overwrite_document`（禁止用整篇覆写代替片段替换）
- 任一写成功后，该文旧读结果作废，继续改前先 `get_document`

## 风险与回滚

| 风险 | 处理 |
|------|------|
| 模型仍迷信旧 get | 短提示措辞强硬；不够再开「hydrate 标注 stale」增量 |
| `find` 太短误伤 | description 要求用足够唯一的原文；可文档约定 `find.length < 8` 警告（不强拦） |
| append 无限涨 | 单次上限；不做跨次合并 |
| 与选择卡混淆 | append/replace 明确不出卡 |

## 测试要点

- append 空文 / 非空文 separator 行为  
- replace 唯一命中；0 命中；2 命中无 occurrence 失败；occurrence=2 成功  
- 写成功后 session jsonl 有短 `DOCUMENT_CHANGED` 行，且不含完整长文  
- 非 md 拒绝
