# Agent MD append / replace + 写后提示重读 — 需求分析

> 一句话：新增 `append_document` / `replace_document_markdown`（纯 MD 字符串层）；写成功后只往 session 插**短提示**「正文已变，请重新 get_document」，**不把全文塞进 session**。

## 背景

1. Session 只持久化 `get_document` / `web_*`。`overwrite_document` 不落盘 → 跨轮仍看到旧读文结果。
2. 若把 write 全文写入 session，会快速增肥 context。
3. 现有 md/html 写只有整篇 `overwrite_document`；日记追加、改一节都要重吐全文，贵且易错。

## 目标

1. **写后轻量提示**：任一成功的服务端正文写工具后，session 留下短信号，要求 Agent **重新 `get_document`**，勿沿用旧正文。
2. **`append_document`**：在文档末尾追加 Markdown（可选分隔符）。
3. **`replace_document_markdown`**：在 MD 文本层做 `find` → `replace`（段落/片段级），不解析 AST。
4. 系统提示写清：局部改用 append/replace；整篇换血仍用 overwrite；写后若还要讨论该文须重读。

## 非目标（本期不做）

- 不把覆写/追加/替换的**全文**写入 session
- 不做 Lexical/HTML DOM 级段落 API（html 若支持，也只对**磁盘文本**做字符串操作；默认 **仅 md**）
- 不做 sheet 的 append/replace（已有 `sheet_*`）
- 不做帮写 buffer 的段落 tool（coding 仍整篇 `set_markdown_document`）
- 不做回收站式 UI；不改选择卡产品规则（overwrite 有正文仍出卡）

## 验收标准

- [ ] overwrite / append / replace 成功后，session 有短「请重读」记录；体积不随正文增长
- [ ] append：末尾追加，`headCommitId` 前进；同轮/下轮提示可触发模型再 get
- [ ] replace：精确匹配替换；0 次或歧义失败，不写库
- [ ] 非 md（或契约规定之外的类型）拒绝
- [ ] 单测：append / replace 成功与失败；写后 persist 文本短且含 documentId

## 依据

- `session-tool-persist.ts`：白名单；overwrite 当前不落盘
- `tools-overwrite.ts`：整篇覆写 + 选择卡
- 待确认：html 是否一期支持字符串 append/replace（默认 **仅 md**）
