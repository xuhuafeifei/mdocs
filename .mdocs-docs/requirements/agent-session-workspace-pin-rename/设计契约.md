# agent-session-workspace-pin-rename — 设计契约

> **状态**：已同意（2026-10-12）

## 方案摘要

在现有 `session.json` 索引上扩展字段，不改 jsonl、不改锁/队列模型。normal 助手历史：带工作空间、可改名、可置顶；打开面板仍用全局 `lastOpened`。

### 元数据扩展（`SessionMetaEntry`）

| 字段 | 类型 | 说明 |
|------|------|------|
| `domainId` | `string \| null` 可选 | 创建（或首写补记）时的工作空间；旧条目缺省 = 未归类 |
| `title` | 已有 | 支持手动 rename；自动标题规则见下 |
| `pinned` | `boolean` 可选 | `true` = 置顶；缺省/false = 普通 |
| `pinnedAt` | ISO string 可选 | pin 时写入，unpin 清除；同区排序辅助 |
| `documentId` | 已有 | coding 用；本期不改语义 |
| `updatedAt` | 已有 | 打开/发言仍 touch；**rename / pin 不强制当「最近活跃」**（见下） |

`SessionMeta` 的 `lastOpenedSessionId` / `lastOpenedByDocument` **不变**。

### 写入时机

| 动作 | 行为 |
|------|------|
| `POST /sessions` 新建 | body 可带 `domainId`；写入 entry |
| `appendUser` 首写且 entry 无 `domainId` | 若请求上下文有 domain，可补记一次（chat 路径把 domainId 传入 touch）；已有则不改 |
| 切换工作空间后继续在旧 session 聊天 | **不改**该 session 的 `domainId`（归属=创建时） |
| rename | 只改 `title`；设内部标记 `titleLocked: true`（或约定：非「新会话」且曾 PATCH 过则 auto-title 跳过） |
| pin / unpin | 改 `pinned` / `pinnedAt`；**不**改 `updatedAt`（避免 pin 一下就顶到「最近」普通区） |

**自动标题**：现有 `titleIfEmpty` 仅在标题为空或等于「新会话」时写入。手动 rename 后标题不再是「新会话」，自然不会被首条消息覆盖。无需额外 `titleLocked`，除非产品要「改回新会话后还能再自动命名」——本期不做。

### API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/agent/sessions` | summary 增加 `domainId`、`pinned`（及可选 `pinnedAt`） |
| POST | `/api/agent/sessions` | body 增加可选 `domainId` |
| POST | `/api/agent/session/rename` | `{ sessionId, title }`；title trim，1–80 字，空则 400 |
| POST | `/api/agent/session/pin` | `{ sessionId, pinned: boolean }` |

仍走 `AgentSessionManager` 的 `runSerialized` / `mutateMetaUnlocked`，与 [agent-session-meta-integrity](../agent-session-meta-integrity/设计契约.md) 一致。

### 列表排序（normal）

1. **Pinned** 区：`pinned === true`，按 `pinnedAt` 降序（无则按 `updatedAt`）。
2. **其余**：按 `updatedAt` 降序（与现网一致）。
3. UI 筛选项：`当前工作空间`（默认）| `全部` |（可选）`未归类`。  
   - 当前工作空间：`domainId === 当前 domainId`  
   - 未归类：无 `domainId`  
   - Pinned **仍受筛选约束**（当前空间下只显示该空间的 pinned）；选「全部」时 pinned 跨空间汇总在顶区。

coding：`listSessions` 仍按 `documentId` 过滤；可返回 `domainId`/`pinned`，UI 若复用同一历史组件则同样支持 rename/pin，筛选以文档为准。

### 前端（`AgentChatPanel` 历史页）

- 顶栏：返回 + 工作空间筛选（当前 / 全部）；列表分区标题「Pinned」+ 其余无标题或「最近」。
- 条目：标题、相对时间；右侧 ⋯ 或长按/右键菜单：`Pin`/`Unpin`、`Rename`。
- Rename：行内 input 或小弹层；Enter 提交，Esc 取消。
- 「+」新建：`createAgentSessionApi` 传入当前 `domainId`。
- 打开面板 / lastOpen：**不改**现有 `fetchAgentSessionApi` → `lastOpened` 逻辑。

### 兼容

- **不改目录结构**：仍是 `…/agent/session/session.json` 索引 + `{uuid}.jsonl` 正文；只在索引条目上增加字段。
- 旧条目无 `domainId`：`listSessions` 时懒迁移为 `default` 并写回。
- 新建无 domain 时也落 `default`。

| 层 | 路径 / 符号 |

| meta 模型 + 方法 | `session-manager.ts`：`SessionMetaEntry`、`AgentSessionSummary`、`createSession`、`ensureSessionEntry`、`sortSummaries`、新增 `renameSession` / `setSessionPinned`；必要时 `appendUser`/`touch` 补 `domainId` |

| 测试 | `session-manager` 单测：rename / pin / domain 过滤排序；不破坏 meta 锁语义 |
| 契约索引 | 本夹 `代码索引.md`；增厚 `map/backend.md` session 关键词 |

## 风险与取舍

| 点 | 选择 | 理由 |
|----|------|------|
| lastOpened 是否按 domain | **否** | 你明确要求保持现 lastOpen |
| 聊天中途换工作空间是否改归属 | **否** | 归属=创建语境；避免列表乱跳 |
| pin 是否更新 updatedAt | **否** | 置顶区独立；普通区仍按真实活跃 |
| 是否拆文件存 pin | **否** | 字段够用，少动完整性契约 |
