# agent-session-workspace-pin-rename — 需求分析

> **状态**：待人审  
> **场景**：新需求

## 背景

助手历史会话目前是一条扁平列表（标题多来自首条 user 内容截断），没有工作空间归属、不能手动改名、不能置顶。工作空间一多，历史很难找；参考 Cursor 侧栏「Pinned + Rename」交互。

## 范围

| 做 | 不做（本期） |
|----|--------------|
| 新建 / 首写时记录 `domainId`（工作空间） | 按工作空间拆分物理目录或拆 `session.json` |
| 历史列表按工作空间筛选 / 区分展示 | 改 coding 会话的「按文档分桶」语义 |
| 手动 rename 会话标题 | 会话删除 / 归档 / Fork / 未读 |
| Pinned 置顶区（pin / unpin） | 跨访客共享会话 |
| 打开面板仍走全局 `lastOpened` | 按工作空间各自维护 lastOpened |

## 验收

1. 在某工作空间下「+」新建或发首条消息后，该 session 元数据带有当时的 `domainId`。
2. 历史列表能按当前工作空间筛出对应会话；无 `domainId` 的旧会话归入「未归类」，在「全部」可见。
3. 可重命名会话标题，刷新后仍保留；首条消息的自动标题**不覆盖**已手动改过的标题。
4. 可 Pin / Unpin；Pinned 固定在列表顶部（区内仍按 `updatedAt`）。
5. 打开助手面板仍加载 `lastOpenedSessionId` 对应会话（与现网一致），不因切换工作空间被强制换会话。

## 非目标说明

- coding（帮写）会话已按 `documentId` 分桶；本期可顺带写入 `domainId` 字段，但列表过滤仍以文档维度为准。
- 不引入 Cursor 同款的 Edit Icon / Mark unread / Fork / Move to 等。
