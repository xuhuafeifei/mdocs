# 删除文章可恢复 — 需求分析

> 一句话：删文时把恢复所需快照写入既有 `audit_logs.metadata_json`；提供按审计记录恢复文档（同 documentId + head 正文），不改表结构。

## 背景

删文是硬删：`documents` 行删除后 `document_commits` CASCADE 清空；工作区文件删除。`files/commits/` 内容寻址 blob 会留下，但审计 `document.delete` 只记 `relativePath`，无法从「删了哪篇」找回 hash，产品侧无法恢复。

## 目标

1. **丰富删除审计 metadata**：写入重建文档行 + 读回 head 正文所需字段（含 `contentHash` / `blobRef` / `headCommitId`）。
2. **支持恢复**：所有者可根据某条 `document.delete` 审计把文章找回（同 `documentId`，正文取 head blob）。
3. 文件夹级联删除时，**每个被删文档**各自写完整 recovery metadata（与单篇删除同形）。

## 非目标（本期不做）

- 不新增审计表列（继续用 `metadata_json`）
- 不恢复完整 commit DAG / merge 历史（只恢复 head 一条 commit）
- 不恢复邀请 / 评论（删时本就无 CASCADE；同 id 恢复后孤儿行若仍在会自然挂回，但不保证）
- 不做回收站 UI（可后做）；本期至少 **HTTP API**（可选 CLI）
- 不清理 / 不 GC commits 孤儿 blob
- 不恢复「审计写新格式之前」已删的旧记录

## 验收标准

- [ ] 单篇删除审计含完整 `recovery` 对象，可用 blob 读出删前 head 正文
- [ ] 目录删除时每个非 dir 文档审计同样带 `recovery`
- [ ] `POST` 恢复：同 documentId 重建 + 写工作区 + 插 head commit；路径冲突 → 409
- [ ] 非所有者 / 无 recovery / blob 缺失 → 明确错误
- [ ] 恢复后写 `document.restore` 审计
- [ ] 单测覆盖：删 → metadata → restore → get 正文一致

## 依据

- schema：`audit_logs.metadata_json`；`document_commits` ON DELETE CASCADE
- 代码：`removeDocument` / 文件夹级联删除；`writeCommitBlob` / `readCommitBlob`
- 待确认：恢复入口仅 API，还是设置页「最近删除」也要一期做（默认 **仅 API**）
