# desktop-webview-shell — 设计契约

> **状态**：已同意（2026-09-13）  
> 用户要求 macOS + Windows；薄壳对齐 Android。

## 方案摘要

和 Android 一样：**壳 = 系统 WebView + 填写页**，不内置 mdocs 前端。

1. 工程放 **`desktop/`**（Tauri 2），与 `src/web` / npm `files` 解耦。
2. 地址存在本机应用配置目录（trim、补 `http://`、仅 http(s)）。
3. 窗口用系统标题栏（Mac 红黄绿 / Windows 系统按钮），**不**再画一条应用顶栏。
4. 回前台读剪贴板：同源且带文章 id → `origin/#/doc/<id>`。
5. 主色 `#4CAF50`，图标用仓库 `src/web/assets/mdocs-logo.svg` 栅格化后的应用图标。
6. 「更换服务器 / 刷新」放在**系统菜单**（Mac 菜单栏；Windows 窗口菜单），不占用内容区。

## 已拍板

| 项 | 决议 |
|----|------|
| 平台 | **macOS + Windows**（本期不做 Linux） |
| 技术 | **Tauri 2**（系统 WebView：WKWebView / WebView2） |
| 分发 | 本地构建侧载：Mac `.app`/`.dmg`；Windows NSIS `.exe`。不上架 |
| 服务器 | **用户填写**，不写死 |
| 前端 | **不改** mdocs Web；壳不向业务页注入 JS |
| npm | **不进** `@fgbg/mdocs`；不影响 `pnpm build` |

未选 Electron（安装包带 Chromium，体积大）。未选纯 Swift（无法覆盖 Windows）。

## 用户流程

```text
启动
  → 无保存 URL：填写页（绿主色 + mdocs logo）
  → 有保存 URL：WebView 加载该源站
菜单「更换服务器」→ 填写页（不清各源站 WebView 存储）
窗口获得焦点 → 剪贴板同源 + 文章 id → 跳转该文
下载 → 本机「下载」目录；上传走系统文件选择（WebView 自带）
```

填写规则与 Android 相同。外链：不同 origin 用系统浏览器打开。

## 工程结构

| 路径 | 职责 |
|------|------|
| `desktop/setup/` | 填写页静态 HTML（唯一内置前端） |
| `desktop/src-tauri/` | Rust 壳：存 URL、导航、剪贴板、菜单、下载 |
| `desktop/README.md` | macOS / Windows 构建与安装 |
| `.gitignore` | 忽略 `target/`、`node_modules/`、安装包 |

剪贴板解析与 Android `clipboardDocTarget` 对齐（scheme+host+port，认 `#/doc/<id>` 与 `/doc/<id>`）。

Windows 运行依赖系统 **WebView2**（Win10/11 通常已有）。本仓库在 Mac 上只验证 macOS 包；Windows 用同一源码在 Windows 上 `npm run tauri build`。

## 风险

| 风险 | 缓解 |
|------|------|
| Rust 工具链占磁盘 | rustup `--profile minimal`；不装 Visual Studio / 整套 Xcode |
| WKWebView / WebView2 与 Chrome 差异 | 上传下载作为验收，不宣称 100% |
| 自签 HTTPS | 跟随系统 WebView；失败则换可信任证书或 http 局域网 |
| ICP 拦截页 | 壳无法绕过；换可访问的入口 URL |
| Mac 交叉编 Windows | 不支持；文档写明在 Windows 本机构建 |

回滚：不合并 `desktop/`。

## 测试要点

1. 冷启动填地址 → 打开 mdocs
2. 重启直达
3. 剪贴板本站文档链接 → 切回窗口打开该文
4. 其它网站链接忽略
5. 附件下载能落到本机「下载」
6. 菜单「更换服务器」回到填写页
