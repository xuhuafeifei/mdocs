# 工作空间文案与开始写作 — 设计契约

> **状态**：已同意（2026-09-19）

## 概念

对人说的隔离单元叫 **工作空间**（英文 Workspace）。以前产品文案叫「域」，指的是同一件事，不再对用户使用。

对机器仍叫 **domain**。表、字段、路径、错误码、CLI 参数都不改名。旧契约、更新日志里的「域」是当时的叫法，不回头改写；**新写给人看的句子用工作空间**。

| 层 | 用什么 | 例子 |
|----|--------|------|
| 界面、助手口吻、文档站、CLI 说明 | 工作空间 | 设置里的「工作空间」、错误「不能跨工作空间移动文档」 |
| 代码、API、库、命令 | domain | `domain_id`、`domainId`、`--domain`、`domains`、`DOMAIN_NOT_FOUND`、`domain_read` |
| 磁盘目录名 | 仍是 id | `~/.mdocs/files/docs/{domain_id}/` |
| 个人空间的库存名 | 后缀仍是「个人域」 | 界面用 `localizeDomainName` 显示成「某某个人工作空间」 |
| 用户自己起的名字 | 不改库 | 「公开测试域」这种历史名称原样显示 |
| 公网地址 | 仍叫域名 | 「从 API 地址提取域名」「域名绑定」不是这个概念 |

文档站概念页：`mdocs-site` 的 `docs/docs/core-concepts/domain.md`（URL 保持 `/docs/core-concepts/domain`，标题是「工作空间」）。更新日志页首注明现行用语，各版本正文保持当时的「域」。

## 主界面

空态只留两个按钮：

- **开始写作**：仍打开新建文档弹窗（`openNewDocumentModal`）
- **AI 帮写**：非窄屏、非演示模式保留；窄屏继续隐藏

去掉「新建文件夹」入口（欢迎页、侧栏图标、树右键）。已有文件夹仍显示，仍可在里面新建文档。后端建目录接口和助手 `create_folder` 工具保留，只是界面和系统提示不再教这个操作。

## 风险与回滚

- 不迁移库数据。回滚只还原文案与按钮。
- 助手若仍引用旧手册章节，可能说出「域」；手册以文档站为准，站点更新后 `skills:build` 才会进运行时 skill。
