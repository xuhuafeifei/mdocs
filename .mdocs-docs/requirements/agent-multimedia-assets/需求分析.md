# Agent 多媒体资产 — 需求分析

> 一句话：聊天可上传图片/文件；统一 Asset 落盘与引用；解析与接入 Agent 分层；**不依赖 MarkItDown / 外部转换服务**，解析在 mdocs 内用自有代码实现。

## 背景

助手要支持图像识别与文件理解。DeepSeek Vision 原生吃 `text + image`；PDF/docx 等需先变成文本（或图）再进模型。此前讨论过 MarkItDown，但官方仅 Python，JS 仅为社区移植，**不作为 mdocs 依赖**。

对照 DSH：图片进 AttachmentStore（提交 prompt 时持久化）、会话只存 Ref、发请求前物化；非图文件不走统一 attachment 处理器。mdocs 产品上要统一「聊天附件」体验，故自建三层能力。

## 目标

1. **资产管理**（有状态）：SQLite 管状态 + `~/.mdocs/files/agent-attachments/objects` 管字节（DSH 式全局目录，不进 session）；Store 管 staging→persisted。
2. **资产解析**（FP）：能力表策略函数 → TypedResult。
3. **资产接入**（FP）：统一 `LlmContentPart[]`（text | image_url）。
4. **上传门禁**：能力表未注册后缀拒传。
5. **懒清理**：过期 staging；不做 GC / watchdog / MarkItDown。

## 非目标（本期）

- MarkItDown / Python 侧车 / 社区 JS port
- 引用计数 GC、压缩后资产回收策略（压缩以后再说）
- 通用 watchdog + listener 总线
- Azure Document Intelligence / 云端 OCR SaaS
- 扫描件 PDF 高质量 OCR（可后续加；v1 文本型 PDF / 纯文本优先）
- 把 base64 写入 `messages.jsonl`

## 验收标准

- [ ] 聊天可选文件上传，得到 `assetId`；发送 chat 携带 `assetIds`
- [ ] 发送后资产为 `persisted`，user 消息含 refs；刷新会话可显示附件卡片/缩略图
- [ ] 小图：请求 content 含 `image_url`（data URL），模型可识图
- [ ] 小文本（txt/md/csv 等）：抽文本嵌入 content 或等价 text part
- [ ] 超阈值 / 重格式：prompt 短说明 + Agent 可 `read_attachment` 分段取内容
- [ ] 未发送的 staging 可被懒清理；正式 persisted 本期不因「无引用」删除
- [ ] 依赖树无 markitdown / markitdown-js / markitdown-node
