# Agent 多媒体资产 — 设计契约

> **状态**：已同意（2026-10-14）

## 方案摘要

三层能力；**状态层与转换层用不同风格**；禁止 MarkItDown；解析/接入禁止继承树：

| 层 | 形态 | 职责 |
|----|------|------|
| **1. 资产管理** | **有状态模块**（`AssetStore`：显式状态机 + 落盘） | staging ↔ persisted、读写、懒清理 |
| **2. 资产解析** | **FP 策略表** `后缀\|mime → parse → ParseResult` | 纯数据转换，无业务状态 |
| **3. 资产接入** | **FP 策略表** `ParseResult.kind → inject` | 纯数据转换 → content / tool 提示 |

原则：

- **有生命周期状态的**用 Store 说清楚（状态字段、合法迁移、落在哪）；**只做 bytes→结构 / 结构→模型输入的**用策略函数
- Session / jsonl **只存 Ref + 元数据**，不存 base64
- 正式持久化与 **user prompt 落盘同刻**（staging → persisted）
- 解析懒做；接入层看 `kind` 再决定嵌/tool
- 懒清理 staging；无 GC / 无 watchdog

## 风格约定：状态 vs 转换

### 资产管理 = 状态明确（Store）

资产有真实生命周期（`staging` → `persisted`，过期清理），全用散落纯函数容易让「谁改状态、何时合法」变糊。这里用 **小而明确的 Store**（一个模块 / 一个对象即可，**不是**解析器继承体系）：

```ts
// 合法迁移写在 Store 里，外面不准直接改 meta.status
type AssetStatus = "staging" | "persisted";

interface AssetStore {
  saveStaging(input: SaveStagingInput): Promise<AssetMeta>;      // → staging
  persist(ids: string[]): Promise<AssetMeta[]>;                 // staging → persisted
  read(id: string): Promise<{ meta: AssetMeta; data: Uint8Array }>;
  purgeExpiredStaging(now?: Date): Promise<number>;             // 删过期 staging
}
```

实现可以是 `createAssetStore(rootDir)` 返回上述 API（闭包持有根路径），或薄 class；**要点是状态迁移集中、可测**，而不是为 OOP 而 OOP。

### 解析 / 接入 = FP 策略（赞成）

无持久状态，输入 → 输出，策略表最清楚：

```ts
type ParseStrategy = (input: {
  meta: AssetMeta;
  data: Uint8Array;
  limits: ParseLimits;
}) => Promise<ParseResult>;

const parseStrategies: Record<string, ParseStrategy> = {
  ".png": parseImage,
  ".jpg": parseImage,
  ".jpeg": parseImage,
  ".webp": parseImage,
  ".gif": parseImage,
  ".txt": parsePlainText,
  ".md": parsePlainText,
  ".csv": parsePlainText,
  ".pdf": parsePdfText, // 内置轻量；禁止 markitdown
};

type InjectStrategy = (ctx: InjectCtx, result: ParseResult) => Promise<void>;

const injectStrategies: Record<ParseResult["kind"], InjectStrategy> = {
  image: injectImagePart,
  text: injectTextPart,
  deferred: injectDeferredHint,
  unsupported: injectUnsupportedHint,
};
```

新增文件类型 = 加解析策略挂表；不改 Store、不改 chat 主链路。

## 端到端流程

```text
1. 上传 → store.saveStaging(bytes) → assetId（staging）
2. 发送 → chat({ message, assetIds })
3. store.persist(ids) + appendUser(text, refs)   // 与 prompt 落盘同刻
4. 对每个 ref：store.read → resolveParseStrategy → ParseResult
5. 对每个 result：injectStrategies[kind](…)
6. run Agent；大文件可 read_attachment → 再走同一套 parse 策略（可带 offset）
```

## 1. 资产管理（有状态 Store）

### 存哪：SQLite 管状态 + 全局 attachment 目录管字节（对齐 DSH）

| 层 | 位置 | 说明 |
|----|------|------|
| **元数据 / 状态** | SQLite 表 `agent_attachments` | staging/persisted、归属、并发用事务 |
| **字节** | `~/.mdocs/files/agent-attachments/objects/{sha256}` | 内容寻址；**不在** session 目录下 |
| **会话引用** | `messages.jsonl` 里只写 `assetId` 等 Ref | 与 DSH「日志只留 Ref」一致 |

不占用编辑器的 `files/assets` + `attachments` 表（文档附件）；agent 独立命名。

```text
~/.mdocs/
  sqlite/data.sqlite          # 含 agent_attachments
  files/
    agent-attachments/
      objects/{sha256}        # 全局共享内容寻址
    assets/                   # 既有：编辑器附件（不动）
  tenant/.../agent/.../session/{id}/
    messages.jsonl            # 仅 Ref，无二进制
```

### 表结构（草案）

```sql
CREATE TABLE IF NOT EXISTS agent_attachments (
  attachment_id   TEXT PRIMARY KEY,
  owner_visitor_id TEXT NOT NULL,
  session_id      TEXT NOT NULL,
  sha256          TEXT NOT NULL,
  name            TEXT NOT NULL,
  mime            TEXT NOT NULL,
  byte_size       INTEGER NOT NULL,
  status          TEXT NOT NULL CHECK (status IN ('staging', 'persisted')),
  created_at      TEXT NOT NULL,
  persisted_at    TEXT
);
CREATE INDEX IF NOT EXISTS idx_agent_att_session ON agent_attachments(session_id, status);
CREATE INDEX IF NOT EXISTS idx_agent_att_staging_created ON agent_attachments(status, created_at);
CREATE INDEX IF NOT EXISTS idx_agent_att_sha ON agent_attachments(sha256);
```

### 并发

- **写路径**：`saveStaging` / `persist` / `purgeExpiredStaging` 用 **SQLite 事务**（必要时 `BEGIN IMMEDIATE`）
- **字节**：先写 `objects/.tmp-…` 再 rename/link 到 `objects/{sha256}`（内容寻址，相同 sha 可复用）
- **读**：按 id 查行 → 按 sha 读文件；文件缺失当错误

### 状态机

```text
saveStaging:  (new) → staging
persist:      staging → persisted（校验 visitor + session）
purgeExpired: staging 且超时 → DELETE 行；objects 本期可不删（无 GC）
```

| Store API | 行为 |
|-----------|------|
| `saveStaging` | 能力表校验 → 写 object → INSERT staging |
| `persist` | 事务内 UPDATE status |
| `read` | SELECT + 读 object |
| `purgeExpiredStaging` | DELETE 过期 staging 行 |

## 1b. 能力表（上传门禁 = 已注册类型）

**是：未注册能力不允许上传。** 与解析策略共用一份注册，避免「能传不能懂 / 能懂不能传」分裂。

```ts
type AssetCapability = {
  /** 后缀，小写，含点，如 ".png" */
  ext: string;
  mime?: string[];
  /** 解析策略（必有；上传允许 ⟺ 能解析或至少能 deferred） */
  parse: ParseStrategy;
  maxBytes?: number;
};

const assetCapabilities: AssetCapability[] = [
  { ext: ".png", parse: parseImage, … },
  { ext: ".pdf", parse: parsePdfText, … },
  // 未出现在本表 → 上传直接 400 unsupported_type
];

function assertUploadAllowed(filename: string, bytes: number): void { /* 查表 */ }
function resolveParseStrategy(filename: string): ParseStrategy { /* 查表 */ }
```

| 情况 | 行为 |
|------|------|
| 后缀在能力表 | 允许上传 → staging |
| 不在表 | **拒绝上传**（前端也不展示该类型 / 选后报错） |
| 在表但单次太大 | 可上传后 parse 得 `deferred`，或上传时按 `maxBytes` 拒 |

以后加 docx = **只加一条 capability（含 parse 策略）**，上传与解析自动打通。

## 2. 资产解析（按类型策略）

### 时机

发送 chat、对本轮 `assetIds`：**先 persist，再逐个 parse**（本轮「初次调用前」完成解析）。  
超大 → 策略返回 `deferred`，不在此时塞全文；等 tool 再 parse 切片。

### ParseResult

```ts
type ParseResult =
  | { kind: "image"; mime: string; data: Uint8Array }
  | { kind: "text"; text: string; truncated?: boolean }
  | { kind: "deferred"; reason: "too_large" | "needs_tool"; hint?: string }
  | { kind: "unsupported"; reason: string }; // 理论上上传已拦截；兜底仍保留
```

### v1 策略清单（= 能力表条目）

| 键 | 策略 | 行为 |
|----|------|------|
| 图片后缀 | `parseImage` | → `image`；过大 → `deferred` |
| txt/md/csv/json | `parsePlainText` | → `text`；超长 → `deferred` |
| pdf | `parsePdfText` | 抽文本或 `deferred`/`unsupported` |

### 阈值（草案）

- 图 / data URL 体积；嵌入文本字符上限 → `deferred`
- 策略失败不拖死 chat

## 3. 资产接入：统一成 ContentPart[]（不是改 header）

**纠正：图片不进 HTTP header。** DeepSeek / OpenAI-compat 与文本一样，都在 **request body → `messages[].content` 数组**。

统一抽象：

```ts
type LlmContentPart =
  | { type: "text"; text: string }
  | { type: "image_url"; image_url: { url: string } }; // data URL 或 https

// 接入层只做一件事：往 parts 里 push
async function buildUserContentParts(
  userText: string,
  results: ParseResult[],
): Promise<LlmContentPart[]> {
  const parts: LlmContentPart[] = [{ type: "text", text: userText }];
  for (const r of results) {
    await injectStrategies[r.kind]({ parts }, r);
  }
  return parts;
}
```

| kind | 注入策略往 `parts` 加什么 |
|------|---------------------------|
| `image` | `{ type: "image_url", image_url: { url: "data:image/…;base64,…" } }` |
| `text` | `{ type: "text", text: "【附件名】\n…" }` |
| `deferred` | `{ type: "text", text: "[附件] … 请用 read_attachment" }` |
| `unsupported` | `{ type: "text", text: "[附件] … 暂不支持解析" }`（上传门禁后少见） |

对调用方只有一种形状：`LlmContentPart[]` → 再交给 pi / fetch。  
「不统一」只存在于 **part 的 type 字段**（text vs image_url），这是协议本身，用策略表消化，而不是两套入口（更不是 header vs body）。

`read_attachment`：再走能力表 parse，返回文本（或日后 image part）给 tool result。

### 注入（统一 ContentPart[]）

```ts
// inject.ts
export type LlmContentPart =
  | { type: "text"; text: string }
  | { type: "image_url"; image_url: { url: string } };

export async function buildUserContentParts(
  userText: string,
  results: Array<{ meta: AssetMeta; result: ParseResult }>,
): Promise<LlmContentPart[]> {
  const parts: LlmContentPart[] = [{ type: "text", text: userText }];
  for (const { meta, result } of results) {
    await injectByKind[result.kind](parts, meta, result);
  }
  return parts;
}

const injectByKind: Record<
  ParseResult["kind"],
  (parts: LlmContentPart[], meta: AssetMeta, r: ParseResult) => Promise<void>
> = {
  async image(parts, _meta, r) {
    if (r.kind !== "image") return;
    const b64 = Buffer.from(r.data).toString("base64");
    parts.push({
      type: "image_url",
      image_url: { url: `data:${r.mime};base64,${b64}` },
    });
  },
  async text(parts, meta, r) {
    if (r.kind !== "text") return;
    parts.push({ type: "text", text: `【${meta.name}】\n${r.text}` });
  },
  async deferred(parts, meta, r) {
    parts.push({
      type: "text",
      text: `[附件] ${meta.name} (${meta.id}) 未内嵌；请用 read_attachment。${r.hint ?? ""}`,
    });
  },
  async unsupported(parts, meta, r) {
    parts.push({ type: "text", text: `[附件] ${meta.name} 不支持：${r.reason}` });
  },
};
```

### Chat 编排（一轮）

```ts
// prepare-turn.ts
export async function prepareUserTurn(input: {
  store: AttachmentStore;
  visitorId: string;
  sessionId: string;
  message: string;
  assetIds: string[];
}): Promise<{ parts: LlmContentPart[]; metas: AssetMeta[] }> {
  const metas =
    input.assetIds.length === 0
      ? []
      : await input.store.persist({
          visitorId: input.visitorId,
          sessionId: input.sessionId,
          ids: input.assetIds,
        });

  const parsed = [];
  for (const meta of metas) {
    const { data } = await input.store.read({
      visitorId: input.visitorId,
      id: meta.id,
    });
    const parse = resolveParseStrategy(meta.name);
    const result = await parse({ meta, data, limits: DEFAULT_LIMITS });
    parsed.push({ meta, result });
  }

  const parts = await buildUserContentParts(input.message, parsed);
  return { parts, metas };
}

```

## 风险与回滚

| 风险 | 缓解 |
|------|------|
| 与编辑器 `files/assets` 混淆 | 目录名 `agent-attachments` + 独立表 |
| pdf 质量差 | 策略降级 deferred |
| data URL 过大 | 限额 → deferred |
| 孤儿 object 文件 | 本期不 GC；以后按 sha 引用计数再清 |

回滚：关上传；旧消息无 assets 仍可读。
