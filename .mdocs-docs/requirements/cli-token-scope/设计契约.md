# CLI Token 作用域与审计 — 设计契约

> **状态**：草案（待同意） · 2026-09-16
> 未经「已同意」不得开始写代码。

## 方案摘要

两件事，都收敛在 `/api` 入口：

```
请求 → [cliTokenGate]  ← 新增，挂在最前（前置路由之前）
         │ 无 x-cli-token → 放行（浏览器/公开路由不受影响）
         │ 有 → 解析 token → 查白名单(method+path) → 不在则 403
         │      通过则挂 req.visitor + req.cliToken
         ↓
       [/api/health · /api/assets/:id · GET comments]   ← 改为带读权限校验
         ↓
       [authMiddleware]  ← 已解析过就不重复解析
         ↓
       业务路由
```

### 一、白名单（默认拒绝）

名单内容**只覆盖 mdocs-cli 现有命令**，逐条从 `~/.mdocs-cli/mdocs.mjs` 抓出：

| Method | Path | 对应命令 |
|--------|------|---------|
| POST | `/documents/search` | search |
| GET | `/documents` | list |
| POST | `/documents` | create |
| GET | `/documents/:id` | get / 引用解析 |
| PUT | `/documents/:id` | update |
| POST | `/documents/:id/move` | move |
| GET | `/documents/folder/:id/children` | 目录浏览 |
| POST | `/folders` | mkdir |
| GET | `/domains` | domains |
| GET | `/visitors/me` | 身份自检 |

**明确拒绝**（不列入即拒绝，此处仅为可读性列出重点）：

- **所有 `DELETE`**（文档 / 目录 / 邀请 / 评论 / 书签 / token）
- **`/cli/tokens` 全部**（POST 签发 / GET 列表 / DELETE 吊销）—— 否则 Agent 可自我续期：即使你在设置页吊销，它也能再签发一个把自己复活
- `/agent/*`（站内助手，属网页会话）
- `/documents/:id/invites`（权限管理）
- `/documents/:id/comments`、`/bookmarks`、`/graph`、`/domain-member-templates`
- 域的创建 / 改名 / 删除；访客的注册 / 登录 / 恢复（本就在豁免名单）

### 二、匹配规则

```ts
// 注意：必须 method + path；必须 /i（Express 路由大小写不敏感，实测 /API/HEALTH → 200）
const CLI_ALLOWED: ReadonlyArray<{ method: string; re: RegExp }> = [
  { method: "POST", re: /^\/documents\/search\/?$/i },
  { method: "GET",  re: /^\/documents\/?$/i },
  { method: "POST", re: /^\/documents\/?$/i },
  { method: "GET",  re: /^\/documents\/[^/]+\/?$/i },
  { method: "PUT",  re: /^\/documents\/[^/]+\/?$/i },
  { method: "POST", re: /^\/documents\/[^/]+\/move\/?$/i },
  { method: "GET",  re: /^\/documents\/folder\/[^/]+\/children\/?$/i },
  { method: "POST", re: /^\/folders\/?$/i },
  { method: "GET",  re: /^\/domains\/?$/i },
  { method: "GET",  re: /^\/visitors\/me\/?$/i },
];
```

- `req.path` 在 `authMiddleware` 里**不含 `/api` 前缀**（`EXEMPT_PATHS` 写 `/visitors/register` 可证），白名单用同形态
- `req.path` 已剥离 query（CLI 用 `?format=text`、`?domainId=` 等），无需额外处理
- 尾部斜杠容错（`/?$`）
- **默认拒绝是刻意的**：将来新增路由自动对 CLI Token 不可达，不会像黑名单那样漏

### 三、拦截点：`cliTokenGate`

新建 `src/server/identity/cli-token-gate.middleware.ts`，在 `app.ts` 中**注册于所有 `/api` 路由之前**（含 health / assets / comments）——这样"带 CLI Token 就一定过白名单"，不给绕过留口子。

```
无 x-cli-token          → next()                    // 完全不影响浏览器与公开路由
有 x-cli-token:
  token 无效/已吊销/访客停用 → 401 INVALID_TOKEN
  (method, path) 不在白名单 → 403 CLI_SCOPE_DENIED   ← 也要落审计
  通过                     → 挂 req.visitor + req.cliToken={tokenId,visitorId} → next()
```

配套调整 `authMiddleware`：若 `req.visitor` 已挂（gate 解析过）则跳过重复解析，避免一次请求两次查库。

`req.authMethod` 不引入——`req.cliToken` 有值即等价于 CLI 请求，无需额外字段。

### 三之二、两种凭证同时出现时（优先级）

请求可能同时带 `x-visitor-token`（或 cookie）与 `x-cli-token`。现行 `tryResolveVisitor` 是**先试 visitor token**，照此逻辑，同持两种凭证者可靠 visitor token 胜出而**绕开白名单**。

**定为失败关闭：只要出现 `x-cli-token`，整个请求就按 CLI 语义处理**（过白名单 + 落审计），不再回退到 visitor token。

- 浏览器从不发 `x-cli-token`，故对网页无可用性代价
- 「持有 visitor token」本身已等于完整账号权限，作用域对那种情形本就不构成边界——但仍不应留含糊路径
- 推论：带**无效** `x-cli-token` + 有效 visitor token → `401 INVALID_TOKEN`（宁可拒，不猜）

**错误响应**：`403 { error: { code: "CLI_SCOPE_DENIED", message: "该操作不被 CLI Token 允许" } }`，便于 CLI 打出人话而不是泛泛的 403。

### 四、审计：`cli_token_requests`

新增表（`schema.ts` 追加，`CREATE TABLE IF NOT EXISTS` 幂等，无需迁移脚本）：

```sql
CREATE TABLE IF NOT EXISTS cli_token_requests (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  token_id   TEXT NOT NULL,
  visitor_id TEXT NOT NULL,
  method     TEXT NOT NULL,
  path       TEXT NOT NULL,
  status     INTEGER NOT NULL,
  allowed    INTEGER NOT NULL,   -- 1 放行 / 0 被白名单拒绝
  created_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_cli_token_requests_token
  ON cli_token_requests (token_id, created_at);
```

- 在 `res.on("finish")` 落库，**拿真实状态码**（含 403 被拒的）
- 「写不写到 token」落实为：记录 `token_id` 外键 + `visitor_id`，可按 token 追溯
- 登录/页面请求（visitor token）**不记**——只记 CLI Token 调用，即"所有外部 Agent 的请求"
- **不配 UI**：用途是事后取证，直接查表（如
  `SELECT * FROM cli_token_requests WHERE token_id = ? ORDER BY id DESC`）。
  与既有 `audit_logs` 一致都不做界面——避免为"看审计"引出管理员角色

### 五、顺带修：评论接口越权

`GET /api/documents/:id/comments` 从 `app.ts` 的前置区**移到 `authMiddleware` 之后**，并加 `requireDocumentAccess("read")`。

- 影响：未登录不能再读评论；无读权限者 403
- 前端同源同会话，带 cookie，不受影响
- 这是**独立于 Token 的越权修复**，请确认是否纳入本次

## 风险与回滚

| 风险 | 缓解 |
|------|------|
| 白名单写错 → mdocs-cli 直接不可用 | 表驱动单测逐条覆盖；**并逐个命令实测** `~/.mdocs-cli/mdocs.mjs` |
| 大小写/尾部斜杠导致误拒 | 正则 `/i` + `/?$`；单测含 `PUT /DOCUMENTS/x` |
| 一次请求两次解析 token | gate 解析后 `authMiddleware` 跳过 |
| 审计写库失败拖慢请求 | `res.on("finish")` 内 try/catch 吞异常，只记日志 |
| 破坏性收紧影响现有 Agent | 属预期；CLI 6 命令全部保留，升级说明写清"超范围接口将 403" |

**回滚**：拆掉 gate 注册即可恢复原行为；`cli_token_requests` 表留着无害。

## 测试要点

1. **表驱动**：白名单 10 条 (method, path) 逐条放行；重点 `GET /documents/:id` 放行 vs `DELETE /documents/:id` 拒绝
2. **大小写**：`PUT /DOCUMENTS/x` 放行；`DELETE /DOCUMENTS/x` 仍拒
3. **`/cli/tokens`**：POST / GET / DELETE 三种方法全部 403
4. **visitor token 不受影响**：同样请求带 visitor token → 正常
5. **前置路由**：带 CLI Token 访问 `/health`、`/assets/:id` → 过白名单（不在名单 → 403）
6. **审计**：放行与拒绝各落一条；`status`/`allowed` 正确；按 `token_id` 可查
7. **吊销后**：请求 401 且不记为放行
8. **评论越权**：无 token 读评论 → 401；无读权限 → 403；有读权限 → 200
9. **mdocs-cli 端到端**：六个命令全跑一遍，确认未被收紧误伤
