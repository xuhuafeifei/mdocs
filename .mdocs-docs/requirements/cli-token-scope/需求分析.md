# CLI Token 作用域与审计 — 需求分析

> 一句话：给 CLI Token 加**默认拒绝的路由白名单**（method + path），并**记录每次调用**；同时堵上三处挂在鉴权之前、可完全绕过 Token 的 `/api` 路由。
> 状态：**草案（待同意）** · 2026-09-16

## 背景

起因是一次安全提问：Agent 拿着 Token 直接打 HTTP 接口能不能删文件？

查证结论：**能**。而且不是越权——是设计使然。

| 环节 | 现状 | 依据 |
|------|------|------|
| Token 与网页会话等价 | `x-cli-token` 与 `x-visitor-token` 都解析成 `req.visitor`，业务层不区分来源 | `src/server/identity/auth.middleware.ts:21` |
| Token 无作用域 | `resolveCliVisitor` 只查 hash / `revoked` / `disabled_at`，无 scope、无过期、无操作白名单 | `src/server/identity/cli-token.service.ts:100` |
| 删除只认创建者 | `delete` 分支不看域权限 / invite / 公开写 | `src/server/access/access-control.ts:230` |
| 删除不可逆 | 硬删 DB 行 + 删盘上文件，仅留一条 `document.delete` 审计 | `src/server/documents/document.service.ts:596` |

`mdocs-cli` 本身只暴露 6 个命令（search / get / create / update / domains / mkdir），**没有 delete**。但这不构成安全边界——Agent 可以绕过 CLI 直接 `curl`。

即：**Token 是完整账号凭证，CLI 的命令集不是权限约束。**

## 目标

1. **默认拒绝**：只有显式列入白名单的 (method, path) 才允许用 CLI Token 访问，其余一律 403
2. **无绕过**：携带 CLI Token 的请求都要过白名单，**包括**挂在 `authMiddleware` 之前的路由
3. **可追溯**：每次 CLI Token 调用落一条记录（方法 / 路径 / 状态 / 命中哪个 token），可按 token 审计

## 非目标

- **不加 Token 过期时间**（仍靠手动吊销；二期）
- **不做只读 / 可写 scope 分级**（当前是"全有或全无"，白名单本身已足够收敛；二期）
- **不开放任何写/删给 CLI Token**：白名单只覆盖 mdocs-cli 现有 6 个命令所需的路由
- **不改 `/api/assets/:assetId` 与 `/api/health` 的公开性**（见下）
- **不做审计 UI**（明确不做，非二期）：设置页不加"Token 活动"列表。理由：跨 token / 跨访客的视图会引出管理员概念，而 mdocs 是无账户的访客身份模型，不该为此另造一套权限；审计的用途是**事后取证**，直接查 `cli_token_requests` 表即可——与既有 `audit_logs` 一样，都不配 UI

## 关键约束（已实测）

### 1. 必须 method + path 一起判

```
GET    /documents/:documentId   ← CLI 的 get，要放行
DELETE /documents/:documentId   ← 要拦的删除
```

**同一个路径**。只按 URL 过滤等于没拦。

### 2. 必须大小写不敏感

实测 `GET /API/HEALTH` → 200，Express 路由默认大小写不敏感。白名单匹配须加 `/i`，否则 `PUT /DOCUMENTS/x` 会被误拒。

### 3. 三处路由挂在鉴权之前，当前零鉴权

`src/server/app.ts` 中在 `app.use("/api", authMiddleware)` 之前注册：

| 路由 | 实测（无 token） | 处置 |
|------|------------------|------|
| `GET /api/health` | 200 | **保持公开**（监控探活，无敏感信息） |
| `GET /api/assets/:assetId` | 404（UUID 校验） | **保持公开**（`<img src>` 无法带自定义头，靠 UUID 不可枚举） |
| `GET /api/documents/:documentId/comments` | **200 + 数据** | ⚠️ **需修**：无任何鉴权，也不校验文档读权限 |

### 4. 顺带发现：评论接口越权读取

`GET /api/documents/:id/comments` 直接调 `getCommentsByDocumentId(id)`，**不校验调用者能否读该文档**。任何知道 documentId 的人（或 Agent）都能读任意文档的评论，包括 private 域的。

documentId 是 UUID，但会出现在 URL、图谱数据、审计日志里，属"可知"而非"保密"。

## 验收标准

1. CLI Token 调白名单内路由 → 正常
   - 尤其：`mdocs-cli` 现有 6 个命令（search / get / create / update / domains / mkdir）全部照常工作
2. CLI Token 调白名单外路由 → `403 CLI_SCOPE_DENIED`
   - 重点：`DELETE /documents/:id` 被拒，而 `GET /documents/:id` 放行
   - `/api/cli/tokens` 全部被拒（含 POST 签发、DELETE 吊销）
3. 同样请求带 **visitor token（网页）** → 不受任何影响
4. 携带 CLI Token 访问前置路由（health / assets / comments）→ 同样过白名单
5. 每次 CLI Token 调用在 `cli_token_requests` 落一条（含被拒的），可按 `token_id` 查
6. 吊销 token 后：请求被拒，且不再记录为新 token 的调用
