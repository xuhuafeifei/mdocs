# ai-merge — 设计契约

> **状态**：已同意（2026-10-23）；**增量（同日）**：输入/输出改为完整 Markdown（git 冲突标记 → 定稿正文），不再要 JSON 选票。

## 方案摘要

### 分工

| 能力 | 阶段 | 产出 |
|------|------|------|
| **ai-merge（本需求）** | 自动消冲突 | **定稿 Markdown**（无 `<<<<<<<` 等标记） |
| **merge-message** | 已有 merged 后写说明 | 一句 message；见 `publish-commit-message` |

### 输入文本（完整一篇）

由 `MergeSegment[]` 序列化，**无冲突处原样保留**；未决议冲突用经典 git / diff3 标记（LLM 熟悉）：

```markdown
前文不变…

<<<<<<< local
我的版本
||||||| base
共同祖先（可选；无有意义 base 时可省略整段）
=======
别人的版本
>>>>>>> remote

后文不变…
```

已人手决议的冲突段：写入**已选正文**（不再打标记）。

截断上限约 24k 字符（优先保留冲突块）。

### HTTP

`POST /api/documents/:id/suggest-merge-resolutions`

```ts
// body
{ conflictMarkdown: string }
// response
{ data: { mergedMarkdown: string } }
```

逻辑：

1. 鉴权 `edit`；`canAiMerge` 否则 400。  
2. `completeSimple`：system 要求只输出定稿正文、保留非冲突原文、删光冲突标记。  
3. 去掉外层 \`\`\` 围栏；若仍含 `<<<<<<<` / `=======` / `>>>>>>>` / `|||||||` → 502，前端可重试或手选。  
4. 无模型 / LLM 失败 → 4xx/5xx。

### 前端

| 位置 | 行为 |
|------|------|
| Merge 工具栏「AI 合并」 | `serializeMergeMarkedText` → API → `editedMd = mergedMarkdown`，未决议 conflict 标 `manual`（占位），进入可编辑/可发布 |
| 成功后 | 不自动弹合并说明、不自动 PUT |

### Agent（增量）

| 入口 | 形状 | 说明 |
|------|------|------|
| Agent | `suggest_document_merge` / `suggest_document_merge_message` | 直调 `ai-merge.service`；不写库 |
| 本地稿通道 | `get_editor_draft`（见 `agent-get-editor-draft`） | SSE+requestId 取浏览器草稿作 `localContent` |
| CLI `ai-merge` | **不做** | 读不到浏览器 IndexedDB 草稿 |

Web Merge 页仍走 `suggest-merge-resolutions`（已有 conflictMarkdown）。  
`POST .../suggest-document-merge`（localContent 编排）可保留给 Agent 服务层复用，**不**作为 CLI 主入口宣传。

### 风险

- 模型可能改非冲突区：prompt 约束；严重时用户可取消重开 merge。  
- 长文截断 / maxTokens：可能截尾，可手改或分段。
