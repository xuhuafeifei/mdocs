# agent-get-editor-draft — 需求分析

> **状态**：已同意（2026-10-23）

## 背景

Agent 的 `get_document` 只读服务端 tip。本地草稿在浏览器 IndexedDB / 编辑器内存，服务端碰不到。  
因此 `suggest_document_merge` 缺必要输入 `localContent`——不是用户不肯 merge，是通道没有。

已否决：每轮 LLM 请求 body 塞完整 Lexical（浪费且难用）。

## 目标

提供 **按需** 通道：Agent 调用 tool → SSE 通知前端 → 前端回传**当前稿的 Markdown/HTML 文本**（禁止 Lexical JSON）→ tool 解冻返回。

供后续 `suggest_document_merge` / 说明冲突用；也可给「对比本地未发布改动」类问答。

## 非目标

- 每轮请求自动附带全文  
- 把草稿持久化到服务端  
- sheet 行级草稿拉取（与 ai-merge 能力表一致：sheet 不走行级 AI merge）  
- 替代帮写模式的 `workingMarkdown`（coding 仍走现有路径）

## 验收

- Agent 在打开某篇 md/html 且有本地稿时可拿到正文 + 可选 `localBaseCommitId`  
- 未打开 / 无草稿 / 超时 → 明确 `unavailable` / `timeout`，不编造  
- 回传绝不是 Lexical JSON  
- **不征求用户意见**：前端收到 SSE 立刻自动取稿回传；时间线仅见 tool_call  
- **不提供** CLI `ai-merge`（读不到浏览器草稿）
