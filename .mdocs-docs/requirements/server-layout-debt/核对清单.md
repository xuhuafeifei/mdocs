## 完成标准（总）

1. 业务代码只调 `modules/access/access.ts` 的 **id 门面**（及将来的批量门面）；不传 Row / `DomainAccessInfo`
2. 编排在 `application/`；拼装在 `mapper/`；`service` 薄封装；`application` **不** `import` Database
3. 登录鉴权是 Nest **Guard** + 白名单；不再靠 middleware 做强制登录
4. ADR / 活备注与代码现状一致

## 建议推进顺序

```text
D1/D2（薄 service）
  → D3a–D3i + D4（调用方迁 id 门面 / 批量）
  → D5（废弃 API 内收）
  → E1/E2/E3（documents + visitor mapper 试点）
  → E4/E5
  → F1–F3（auth Guard）
  → G1–G3（文档）
```

- **可并行**：E 与 D 在「新代码只走门面」前提下可交错；F 建议在 routes 已空的今天随时可开，不必等 E 做完。
- **不要做**：再开 Entity 表对齐项（已完成）；为扫尾去改搜索算法 / 权限语义本身（除非单独立项）。

- C3 已落地后的 embedding 模型 / 召回策略调优
- 把 `access` 拆成 controller/application/service 子目录（ADR 022：暂扁平）
