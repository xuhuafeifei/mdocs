# Agent normal / coding 模式 — 设计契约

> **状态**：开发中（2026-07-31：全屏层 + hunk 审阅已开工）  
> 依据：[`需求分析.md`](./需求分析.md)

## 方案摘要

把现有智能助手拆成两种 **Agent 模式**（同一套 chat SSE / session 基础设施）：

| 模式 | 类比 | UI | Tools | 正文 |
|------|------|-----|-------|------|
| **`normal`** | Cursor Ask | 现有浮层 `AgentChatPanel` | 手册 + 账号/结构（建空文档、文件夹、移动…） | **禁止**写库改正文 |
| **`coding`** | Cursor Coding | **帮写全屏层**：左 AI、右纯 MD + hunk Diff | normal 结构类可裁剪保留 + **MD buffer 编辑类** | 只改前端 MD；确认后写回 lobe |

**不**新增 `/api/ai-write`。写回使用现有 `create` / `update`（及草稿前端逻辑）。

### 端到端流（coding）

```text
文档页 lobe
  → 入口「帮写」
  → 全屏层：左 chat(mode=coding) / 右 MD + hunk Diff
       Agent tool set_markdown_document（吐全文）
       → SSE markdown_set → 更新 proposedMd
       → 前端对 currentMd vs proposedMd 算 hunk；每段可「接受 / 拒绝」
       → 接受后写入 currentMd（右侧可继续手改）
  →「完成并写回」：以 currentMd 为准 → MD→Lexical → lobe/草稿或新建
  →「取消」→ 丢 buffer，lobe 保持进场 snapshot
```

### P0 Tool（coding only）

| Tool（建议名） | 输入 | 行为 |
|----------------|------|------|
| `set_markdown_document` | `markdown: string`（完整正文） | **不写磁盘文档**；SSE `markdown_set` 交给前端，作为新的 **proposed** 全文 |

- 模型侧 **吐全文**；hunk 由前端 diff 算法计算（不要求模型按行号 patch）。
- P1 再议 `apply_markdown_patch`；本期不做。

### 读正文 Tool（normal / coding 共用，已落地）

| Tool | 行为 |
|------|------|
| `get_document` | `assertDocumentAccess(..., "read")` → `getDocument`；默认 `format=text`；超长截断 |

与 HTTP `GET /api/documents/:id` **同一读权限**；无 Agent 特权。

### normal 行为变更

- `buildSystemPrompt(mode)` / `createTools(mode)`：`normal` **不注册** `set_markdown_document`。
- Prompt：要求写作 → 拒绝并引导「使用帮写（coding 模式）」。
- 现有 `create_document`（空文档）保留在 normal（结构操作）；**不**在 normal 写 content。

### 危险与写回确认

| risk | 判定（P0） | 写回 UX |
|------|-----------|--------|
| `from0` | 无 `documentId` / 新文章入口 | 确认后 create + 打开 |
| `existing` | 带 `documentId` 进帮写 | **强确认**：「将修改你的文章」 |

`aiOwned` 精细血统 **不做 P0**。

### 权限不变量（已对齐）

> Agent **没有独立身份**；tool 使用当前登录访客的 `visitorId`。  
> 凡读写文档 / 域 / 树，必须复用与对应 `/api/*` **相同的** `assertDocumentAccess` / `canReadDocument`（及既有 domain 校验）+ **同一 service**；禁止直接查库或另开「Agent 可读」后门。

coding 写回 lobe：走用户 token 的现有 create/update（或同等 `edit` 断言），不静默升权。

### 会话（已拍板）

- coding 使用 **独立 session 空间**（`tenant/.../agent/coding-session/`），不与 Ask jsonl 混读。
- chat body：`mode: "normal" | "coding"`；缺省 `"normal"`。

### 前端聊天气泡（当轮时间线，已落地）

- 左栏复用 block 时间线；`markdown_set` 更新右侧，并可插折叠 notice「已更新提案正文」。
- Tool UI **不落盘**。

## 帮写壳子与 Diff（已拍板）

### 壳子：全屏层（非独立路由）

- 盖在当前 App 上；不改 URL（P0）。
- 顶栏：标题、完成并写回、取消；左 chat / 右 MD+Diff。
- 入口：文档工具栏「帮写」；可选欢迎区「AI 帮写」新建。

### Diff：VS Code Chat Editing 式 hunk 同意

产品心智对齐 VS Code **Chat Editing**（参考本地 `~/github/vscode-main`：
`src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingCodeEditorIntegration.ts` 中
`DiffHunkWidget` / `acceptNearestChange` / `rejectNearestChange`）：

| 能力 | P0 要求 |
|------|---------|
| 基准进场 | `baseMd`：进场快照（新建则为空） |
| 当前稿 | `currentMd`：已接受 + 手改，**写回以此为准** |
| 提案 | `proposedMd`：最近一次 `markdown_set` |
| 展示 | 右侧按 **hunk** 显示增删（绿/红）；每段 **接受 / 拒绝** |
| 接受 | 将该 hunk 合并进 `currentMd` |
| 拒绝 | 丢弃该 hunk 的提案片段 |
| 全部接受 / 全部拒绝 | Diff 工具条提供 |
| 手改 | 接受后可继续编辑 `currentMd` |

实现约束（干净室）：

- **参考交互与职责切分**，**不整文件抄** VS Code / Monaco 进仓库。
- 技术栈：已有 CodeMirror（`@codemirror/merge` / MergeView）；在 MD 字符串上算 line hunk，自研轻量「按段同意」UI。
- 特殊块（mermaid/markmap/meta2d）：整围栏尽量作为单 hunk，避免拆碎。

### 三份 MD 状态

```text
baseMd      进场快照（取消还原语义）
proposedMd  Agent 最新全文提案（可被下一次 markdown_set 覆盖）
currentMd   用户已接受 + 手改后的「将写回」正文
```

- 首次进场：`baseMd = currentMd = 导出 MD`；无 proposed。
- 收到 `markdown_set`：`proposedMd = 全文`；相对 **currentMd** 重算 hunks。
- 「完成」提交 `currentMd`；若仍有未处理 hunk → 确认后 **全部接受剩余**（默认）。

## SSE

- 推荐显式 `{ type: "markdown_set"; markdown: string }`；前端只信该事件更新 `proposedMd`。

## 进场 / 写回

- Lexical→MD：**优先** lobe `getDocument("markdown")`（`exportMarkdownRef`）；**禁止**把 `POST /convert` 的 lexical→markdown 当正式进场稿（那是 `extractPlainTextFromLexical` 纯文本近似）。
- 右侧默认 **整篇 inline diff**（绿/红 + 段内接受/拒绝）；无提案时可编辑 MD 源码。
- 取消：不写回。完成：`currentMd` → `markdownToLexicalJson` → 已有 doc 草稿；新文一次 create。

## 风险与回滚

| 风险 | 缓解 |
|------|------|
| Lexical↔MD 有损 | 进场官方 markdown 导出；特殊块整围栏；文案「帮写以 Markdown 为准」 |
| 长文全文吐出 | P0 接受；P1 patch |
| hunk UI 复杂度 | 先 line-based hunk + 接受/拒绝；不做完整 VS Code NES/无障碍全套 |
| 抄 VS Code 过重 | 只借鉴交互；自研 CM 层 |
| session 污染 | coding 独立目录 |
| 回滚 | 隐藏入口；chat 忽略 mode |

## 测试要点

- normal：无 `set_markdown_document`；要写作被引导去帮写。
- coding：`markdown_set` 后出现 hunk；接受/拒绝后 `currentMd` 正确；未完成前磁盘不变。
- 完成写回 / 取消行为正确；existing 强确认。
- 缺省无 mode ≡ 现网 normal。
