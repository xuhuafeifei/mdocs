# Agent normal / coding 模式 — 设计契约

> **状态**：已同意（2026-08-03）— **P0 先落地 `ask_user_choice`**；Ask 空文覆写 `overwrite_document` 随后  
> 依据：[`需求分析.md`](./需求分析.md)

## 方案摘要

把现有智能助手拆成两种 **Agent 模式**（同一套 chat SSE / session 基础设施）：

| 模式 | 类比 | UI | Tools | 正文 |
|------|------|-----|-------|------|
| **`normal`** | Cursor Ask | 现有浮层 `AgentChatPanel` | 手册 + 账号/结构 + **有条件覆写** | 见下「Ask 覆写」 |
| **`coding`** | Cursor Coding | **帮写全屏层**：左 AI、右纯 MD + hunk Diff | 结构类 + MD buffer 编辑类 | 只改前端 MD；确认后写回 |

**不**新增 `/api/ai-write`。写回使用现有 `create` / `update`。

## 本次增量（2026-08-03）：Ask 覆写 — 核心观点（待同意）

### 产品规则

1. **AI 覆写直接操作服务端数据**（走现有 `updateDocument` / documents API），**不是**「只写本地草稿」。
2. **不必先打开文章**：靠 `documentId` + 已有读文 tool（`get_document`）即可读、再覆写任意有权文档。
3. **风险分流**（以**服务端正文**为准，不依赖是否打开）：
   - **几乎空**（去空白无正文，或仅一行标题 / 标题+空段）→ Ask **允许直接覆写**服务端。
   - **已有实质正文** → Ask **不直接覆写**；询问用户是否进入 **帮写**（带上 `documentId` + 用户需求）。
4. **草稿 vs 服务端不一致：AI 不处理，一律靠现有 merge / 409 冲突流。**
   - 因此 **不需要**为一致性做「正在编辑则前端拦截覆写」。
   - 拦截若以后要做，只算 UX 锦上添花，**不是本契约的一致性方案**。

### 线性覆写的 commit 思路（与前端「无草稿发布」对齐）

Ask 覆写走 **linear publish**，**不走 merge 发布**，因此 **不会**产生规范里的 `localCommitId`（那是 merge 的 `r_local`）。

```text
1. GET / 读文 meta → 记下当前 headCommitId
2. PUT updateDocument(
     content,
     version.localBaseCommitId = 刚才的 headCommitId
   )
3. 服务端：assertNoVersionConflict
     → 一致：randomUUID() 生成新 commitId，父边挂旧 head，documents.head_commit_id = 新 commitId
     → 不一致：409 VERSION_CONFLICT（交给现有 merge；AI 不管草稿）
```

| 角色 | Ask 覆写里是谁 |
|------|----------------|
| `localBaseCommitId` | **覆写时刻**查到的服务端 **当前 head**（客户端传入） |
| 新 commit / 新 `headCommitId` | **服务端**在 `updateDocument` 里 `randomUUID()` 生成并写库 |
| `localCommitId` | **不用**（仅 merge 发布） |

对齐对象：前端 **无草稿时** `publishDocument` 用 `activeDocMeta.headCommitId` 作 base 的那条路径。  
**不对齐**：草稿里冻结的开编 `localBaseCommitId`（那是用户编辑会话，AI 不读、不改 IndexedDB）。  
**禁止**：不传 `localBaseCommitId`（服务端会跳过冲突校验，等于强行盖 head）。

举证：`document.service.ts` → `updateDocument`（线性分支：`commitId = randomUUID()` → `updateDocumentHeadCommit`）；命名规范：[`archive/commit-naming-and-merge-base.md`](../../archive/commit-naming-and-merge-base.md)。

### `headCommitId` 谁生成？

**服务端生成。** 每次成功的 create / 线性 update / merge 完成，服务端新建 commit 节点并把 `documents.head_commit_id` 指过去。客户端只 **读取** `headCommitId`（或把它当作本次发布的 `localBaseCommitId`），**不**自己造 head。

### 与草稿的关系（刻意不管）

```text
AI 覆写成功推进 head
  → 某访客本地仍有该文草稿（base 可能已落后）
  → 用户再发布该草稿 → 409 → 现有 Merge UI
  → AI 不删草稿、不阻编辑、不自动清 IndexedDB
```

「不允许出现草稿」**不做**服务端强制；一致性只认 **commit + merge**。

### 交互缺口与 P0 基建：用户选择 Card（**已同意，本轮实现**）

现有 Ask **没有**「Agent 出选项、用户点选」协议；靠自然语言问「是否打开帮写」不可靠。

**先做通用 tool + UI**，帮写分流复用它；不要只为帮写写死一套。

#### 产品形态

| 项 | 约定 |
|----|------|
| 选项 | **不固定**；tool 入参为 **内容字符串 List**（`string[]`，模型自填） |
| 表现 | Card：选项按钮 + **可自由输入**一段文字 |
| 发起 | Agent 调用 `ask_user_choice` |
| Pending | 一调用即 pending，直到 choose / 超时 / 取消 |
| 解冻 | **只传内容字符串**；**不用 id** |
| 超时 | 默认 **15s** → `{ status: "timeout" }`；Card 失效；前端倒计时条 |
| 取消 | 关面板 / 断 SSE → `{ status: "cancelled" }` |

前后端超时：**双保险**。服务端 `setTimeout(15s)` 必有；前端倒计时归零时 `POST /choice { expire: true }` 主动解冻（不必干等 SSE）。任一方先到即可，后到的 expire 对已结束的 request 幂等忽略。

#### Tool / API 入参

**`ask_user_choice`**

```ts
{
  title?: string;
  options: string[]; // 内容 List，至少 2 项；按钮文案即内容
  timeoutMs?: number; // 默认 15000
}
```

**`POST /api/agent/choice`**

```ts
{
  requestId: string;
  choice: string; // 点选原文或自定义输入；非空
}
```

tool 返回：`{ status: "selected", choice: "<内容字符串>" }`。无 id。

#### 时序

```text
Agent 调 ask_user_choice({ title, options: string[] })
  → pending
  → SSE choice_card { requestId, title, options, expiresAt }
  → 用户点按钮或自由输入
  → POST /choice { requestId, choice: 内容字符串 }
  → 解冻；tool result.choice = 该字符串
  → Agent 继续

超时 / 取消 → 同样解冻，status 标明原因
```

#### 服务端要点

- 进程内 `Map<requestId, { visitorId, resolve, timer }>`（单实例够用；多实例以后再 Redis）
- `requestId` 与当前 chat 的 visitor 绑定，禁止替别人选
- tool **禁止**在未点选时瞎猜；超时后由模型说明「未收到选择」

#### 与 Ask 覆写的关系

有实质正文、不能直写时：

1. 调 `ask_user_choice`：例如「打开帮写审阅」/「取消」  
2. 选帮写 → SSE 或 tool 结果带 `open_coding`；前端开 `AiWriteWorkbench`  
3. 选取消 / 超时 → 不覆写、不打开帮写  

空文覆写仍走 `overwrite_document`，**不需要**先出 Card。

#### 非目标（本期）

- 多轮问卷 / 表单  
- 跨机器 session 恢复未完成的 Card  
- 把所有确认都改成 Card（仅 Agent 主动 ask 时用）

### Tool 草案（normal）

| Tool（建议名） | 行为 |
|----------------|------|
| `ask_user_choice` | 推选择 Card，阻塞等待点选或超时（见上） |
| `overwrite_document` | 入参 `documentId` + 完整 markdown；先读判空；有正文 → 调 `ask_user_choice`（打开帮写 / 取消）；空文 → `updateDocument` + **`localBaseCommitId = 读时 head`** |

### 权限

与既有不变量相同：当前访客 `edit`；`assertDocumentAccess` + 同一 `updateDocument`；无 Agent 特权。

## 既有：coding 帮写（已部分落地）

### 端到端流（coding）

```text
文档页 lobe
  → 入口「帮写」
  → 全屏层：左 chat(mode=coding) / 右 MD + hunk Diff
       Agent tool set_markdown_document（吐全文）
       → SSE markdown_set → 更新 proposedMd
       → 前端对 currentMd vs proposedMd 算 hunk；每段可「接受 / 拒绝」
       → 接受后写入 currentMd（右侧可继续手改）
  →「完成并写回」：以 currentMd 为准 → MD→Lexical → lobe/草稿或新建
  →「取消」→ 丢 buffer，lobe 保持进场 snapshot
```

### P0 Tool（coding only）

| Tool（建议名） | 输入 | 行为 |
|----------------|------|------|
| `set_markdown_document` | `markdown: string`（完整正文） | **不写磁盘文档**；SSE `markdown_set` 交给前端，作为新的 **proposed** 全文 |

- 模型侧 **吐全文**；hunk 由前端 diff 算法计算（不要求模型按行号 patch）。
- P1 再议 `apply_markdown_patch`；本期不做。

### 读正文 Tool（normal / coding 共用，已落地）

| Tool | 行为 |
|------|------|
| `get_document` | `assertDocumentAccess(..., "read")` → `getDocument`；默认 `format=text`；超长截断 |

与 HTTP `GET /api/documents/:id` **同一读权限**；无 Agent 特权。

### normal 行为变更

- `normal` **不注册** `set_markdown_document`（那是 coding buffer）。
- **待同意后**：注册空文覆写 tool（见上文 Ask 覆写）；有正文则引导帮写，不在 Ask 强盖。
- 现有 `create_document`（空文档）保留在 normal（结构操作）。

### 危险与写回确认

| risk | 判定（P0） | 写回 UX |
|------|-----------|--------|
| `from0` | 无 `documentId` / 新文章入口 | 确认后 create + 打开 |
| `existing` | 带 `documentId` 进帮写 | **强确认**：「将修改你的文章」 |

`aiOwned` 精细血统 **不做 P0**。

### 权限不变量（已对齐）

> Agent **没有独立身份**；tool 使用当前登录访客的 `visitorId`。  
> 凡读写文档 / 域 / 树，必须复用与对应 `/api/*` **相同的** `assertDocumentAccess` / `canReadDocument`（及既有 domain 校验）+ **同一 service**；禁止直接查库或另开「Agent 可读」后门。

coding 写回 lobe：走用户 token 的现有 create/update（或同等 `edit` 断言），不静默升权。

### 会话（已拍板）

- coding 使用 **独立 session 空间**（`tenant/.../agent/coding-session/`），不与 Ask jsonl 混读。
- chat body：`mode: "normal" | "coding"`；缺省 `"normal"`。

### 前端聊天气泡（当轮时间线，已落地）

- 左栏复用 block 时间线；`markdown_set` 更新右侧，并可插折叠 notice「已更新提案正文」。
- Tool UI **不落盘**。

## 帮写壳子与 Diff（已拍板）

### 壳子：全屏层（非独立路由）

- 盖在当前 App 上；不改 URL（P0）。
- 顶栏：标题、完成并写回、取消；左 chat / 右 MD+Diff。
- 入口：文档工具栏「帮写」；可选欢迎区「AI 帮写」新建。

### Diff：VS Code Chat Editing 式 hunk 同意

产品心智对齐 VS Code **Chat Editing**（参考本地 `~/github/vscode-main`：
`src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingCodeEditorIntegration.ts` 中
`DiffHunkWidget` / `acceptNearestChange` / `rejectNearestChange`）：

| 能力 | P0 要求 |
|------|---------|
| 基准进场 | `baseMd`：进场快照（新建则为空） |
| 当前稿 | `currentMd`：已接受 + 手改，**写回以此为准** |
| 提案 | `proposedMd`：最近一次 `markdown_set` |
| 展示 | 右侧按 **hunk** 显示增删（绿/红）；每段 **接受 / 拒绝** |
| 接受 | 将该 hunk 合并进 `currentMd` |
| 拒绝 | 丢弃该 hunk 的提案片段 |
| 全部接受 / 全部拒绝 | Diff 工具条提供 |
| 手改 | 接受后可继续编辑 `currentMd` |

实现约束（干净室）：

- **参考交互与职责切分**，**不整文件抄** VS Code / Monaco 进仓库。
- 技术栈：已有 CodeMirror（`@codemirror/merge` / MergeView）；在 MD 字符串上算 line hunk，自研轻量「按段同意」UI。
- 特殊块（mermaid/markmap/meta2d）：整围栏尽量作为单 hunk，避免拆碎。

### 三份 MD 状态

```text
baseMd      进场快照（取消还原语义）
proposedMd  Agent 最新全文提案（可被下一次 markdown_set 覆盖）
currentMd   用户已接受 + 手改后的「将写回」正文
```

- 首次进场：`baseMd = currentMd = 导出 MD`；无 proposed。
- 收到 `markdown_set`：`proposedMd = 全文`；相对 **currentMd** 重算 hunks。
- 「完成」提交 `currentMd`；若仍有未处理 hunk → 确认后 **全部接受剩余**（默认）。

## SSE

- 推荐显式 `{ type: "markdown_set"; markdown: string }`；前端只信该事件更新 `proposedMd`。

## 进场 / 写回

- Lexical→MD：**优先** lobe `getDocument("markdown")`（`exportMarkdownRef`）；**禁止**把 `POST /convert` 的 lexical→markdown 当正式进场稿（那是 `extractPlainTextFromLexical` 纯文本近似）。
- 右侧默认 **整篇 inline diff**（绿/红 + 段内接受/拒绝）；无提案时可编辑 MD 源码。
- 取消：不写回。完成：`currentMd` → `markdownToLexicalJson` → 已有 doc 草稿；新文一次 create。

## 风险与回滚

| 风险 | 缓解 |
|------|------|
| Lexical↔MD 有损 | 进场官方 markdown 导出；特殊块整围栏；文案「帮写以 Markdown 为准」 |
| 长文全文吐出 | P0 接受；P1 patch |
| hunk UI 复杂度 | 先 line-based hunk + 接受/拒绝；不做完整 VS Code NES/无障碍全套 |
| 抄 VS Code 过重 | 只借鉴交互；自研 CM 层 |
| session 污染 | coding 独立目录 |
| 回滚 | 隐藏入口；chat 忽略 mode |

## 测试要点

- normal：无 `set_markdown_document`；要写作被引导去帮写。
- coding：`markdown_set` 后出现 hunk；接受/拒绝后 `currentMd` 正确；未完成前磁盘不变。
- 完成写回 / 取消行为正确；existing 强确认。
- 缺省无 mode ≡ 现网 normal。
