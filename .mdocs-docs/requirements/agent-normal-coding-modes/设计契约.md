# Agent normal / coding 模式 — 设计契约

> **状态**：草案  
> 未经「已同意」不得开始写业务代码。  
> 依据：[`需求分析.md`](./需求分析.md)

## 方案摘要

把现有智能助手拆成两种 **Agent 模式**（同一套 chat SSE / session 基础设施）：

| 模式 | 类比 | UI | Tools | 正文 |
|------|------|-----|-------|------|
| **`normal`** | Cursor Ask | 现有浮层 `AgentChatPanel` | 手册 + 账号/结构（建空文档、文件夹、移动…） | **禁止**写库改正文 |
| **`coding`** | Cursor Coding | **帮写工作台**：左 AI、右纯 MD | normal 结构类可裁剪保留 + **MD buffer 编辑类** | 只改前端 MD；确认后写回 lobe |

**不**新增 `/api/ai-write`。写回使用现有 `create` / `update`（及草稿前端逻辑）。

### 端到端流（coding）

```text
文档页 lobe
  → 入口「帮写」
  → 帮写页：左 chat(mode=coding) / 右 MD buffer
       Agent tool set_markdown_document（吐全文）
       → 前端更新右侧 MD；与进场 snapshotMd 做 diff 展示（P0）
  →「完成并写回」
       → markdownToLexicalJson（服务端 convert 或同逻辑）
       → 已有 doc：setDocument + 草稿；新文：create + 打开
  →「取消」→ 丢 buffer，lobe 保持进场 snapshot
```

### P0 Tool（coding only）

| Tool（建议名） | 输入 | 行为 |
|----------------|------|------|
| `set_markdown_document` | `markdown: string`（完整正文） | **不写磁盘文档**；经 SSE/tool_result 把全文交给前端，覆写帮写页 MD buffer |

- 模型侧 **吐全文**；line diff 由前端 `snapshotMd` vs `currentMd` 计算。
- P1 再议 `apply_markdown_patch`（按行/段 patch）；本期不做。

### 读正文 Tool（normal / coding 共用，已落地骨架）

| Tool | 行为 |
|------|------|
| `get_document` | `assertDocumentAccess(..., "read")` → `getDocument`；默认 `format=text`；超长截断 |

与 HTTP `GET /api/documents/:id` **同一读权限**；无 Agent 特权。

### normal 行为变更

- `buildSystemPrompt(mode)` / `createTools(mode)`：`normal` **不注册** `set_markdown_document`。
- Prompt：要求写作 → 拒绝并引导「使用帮写（coding 模式）」。
- 现有 `create_document`（空文档）保留在 normal（结构操作）；**不**在 normal 写 content。

### 危险与写回确认

| risk | 判定（P0 可简化） | 写回 UX |
|------|-------------------|--------|
| `from0` | 帮写入口为「新文章」或无 `documentId` | 确认后 create + 打开 |
| `aiOwned` | 待确认字段/启发式（见下） | 常规确认 |
| `userOwned` | 默认打开已有非 AI 文，或用户曾编辑 | **强确认**：「将修改你的文章」 |

P0 可先：`from0` | `existing`（凡带 documentId 进帮写均强确认或中等确认）；`aiOwned` 精细血统 **可二期**。

### 权限不变量（已对齐）

> Agent **没有独立身份**；tool 使用当前登录访客的 `visitorId`。  
> 凡读写文档 / 域 / 树，必须复用与对应 `/api/*` **相同的** `assertDocumentAccess` / `canReadDocument`（及既有 domain 校验）+ **同一 service**；禁止直接查库或另开「Agent 可读」后门。

| 入口 | 链路 |
|------|------|
| HTTP | `authMiddleware` → `requireDocumentAccess` → service |
| Tool | `visitorId`（来自同一 visitor）→ `assertDocumentAccess` → **同一** service |

说明：不必在 tool 内再 HTTP 打本地 controller；复用的是 **鉴权函数 + service**，保证与 controller 结果一致。  
新增 `get_document` 时：先 `assertDocumentAccess(id, visitorId, "read")`，再 `getDocument`（因 `getDocument` 本身不鉴权）。  
coding 写回 lobe：走用户 token 的现有 create/update（或同等 `edit` 断言），不静默升权。

### 会话

- coding 与 normal **可共用** visitor agent session 体系，或 coding **单独 session 前缀/目录**（待确认）。
- 建议 P0：coding 使用独立 session 空间或 `mode` 写入 meta，避免 Ask 历史与帮写改稿 transcript 混读污染。
- chat body 增加 `mode: "normal" | "coding"`；缺省 `"normal"`。

### 前端聊天气泡（当轮时间线，已试做）

- 当轮 assistant 用有序 `blocks`：`text` / `document_table` / `document_card` / `tool_notice` / `sources`，按 SSE 到达顺序 append。
- `text_delta`：若末块是 text 则拼接，否则新开 text（自然形成「说 → tool UI → 再说」）。
- Tool 可视化：`search` / `list_my` / `list_tree` → table（含空结果）；`get_document` → 正文预览卡；创建/移动 → notice。
- **不落盘**；历史重开只有 jsonl 纯文本，无 table/sources UI。
- 实现：`AgentChatPanel.tsx` + `run.ts` tool_execution_end → SSE。

## SSE / Tool 结果约定（草案）

任选其一（实现时定一种，写进代码索引）：

1. **Tool result 仅 JSON**：前端在 coding 页订阅 tool 事件（若 Pi 流可透出）或由 run 层把成功的 `set_markdown_document` 转成 SSE：  
   `{ type: "markdown_set"; markdown: string }`
2. **Assistant 约定围栏**：弱，不推荐作唯一通道。

推荐 **显式 SSE `markdown_set`**，与 `tree_changed` 同级，前端只信该事件更新右侧。

## 前端 MD 工作台（P0）

- 右侧：Markdown 文本编辑器（可用 CodeMirror；与 MergeView 技术栈对齐更佳）。
- Diff：P0 可用整页切换「进场稿 / 当前稿」或简易 line diff 高亮；不要求完整 VS Code NES。
- 进场：若有 `documentId`，`GET` 或编辑器导出 → **Lexical→Markdown**（`/api/documents/convert` 或前端 `getDocument("markdown")`）作为 `snapshotMd` 与初始 buffer。
- 取消：不写回；完成：convert MD→Lexical 后写回。

## 风险与回滚

| 风险 | 缓解 |
|------|------|
| Lexical↔MD 有损（meta2d 等） | 进场用编辑器官方 markdown 导出；特殊块整围栏保留；文案提示「帮写以 Markdown 为准」 |
| 长文全文吐出费 token | P0 接受；P1 patch tool |
| mode 伪造（客户端乱传 coding） | 可接受（仅多给改 buffer 的 tool，仍不直写库）；写回始终要用户点完成 |
| 与 normal 会话互相污染 | coding 独立 session 或隔离 transcript（待确认） |
| 回滚本需求 | 隐藏帮写入口；chat 忽略 mode，恒按 normal 组 tools |

## 测试要点

- normal chat：无 `set_markdown_document`；要写作被拒或引导。
- coding chat：tool 调用后前端收到全文并更新右侧；磁盘文档 content 不变直至「完成」。
- 完成写回已有 doc：编辑器内容变为转换结果；取消后与进场一致。
- 完成新建：创建成功并可打开；不强制先有空草稿。
- 缺省无 mode：行为与现网 normal 一致。
- Agent tool 与 HTTP：同一访客；无读权限文档 `get_document` / 结构工具应失败；禁止绕过 assert。

## 待确认

| # | 项 | 建议默认 |
|---|-----|----------|
| 1 | coding 与 normal 是否共用同一 jsonl session | **否**，coding 独立（如 `agent/coding-session/`） |
| 2 | 进场 Lexical→MD：只用前端 `getDocument("markdown")` 还是必须走 convert API | **优先前端导出**，失败再 convert |
| 3 | P0 diff UI：双缓冲切换 vs 简易 line diff | **双缓冲切换 + 可选简易 diff** |
| 4 | `aiOwned` 精细血统是否进 P0 | **否**，P0 用 from0 / existing |
| 5 | 帮写路由形态 | 全屏层或 `/doc/:id/write` / `/write`（新建） |

## 与既有契约关系

- **不替代** [`onboarding-ai`](../onboarding-ai/)：在其上增加 mode 与帮写 UI。
- ADR-010「无写作」修正为：**normal 无写作；coding 允许写 MD buffer，确认后写回**。落地后可补短 ADR 或在本契约同意时注明废止范围。
