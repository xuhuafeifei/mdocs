# Agent normal / coding 模式 — 需求分析

> 一句话：智能助手拆成 **normal（Ask）** 与 **coding（帮写）** 两种模式；改正文只在 coding 的纯 Markdown 工作台完成，确认后再写回 lobe。

## 背景

当前助手（`onboarding-ai`）已支持手册问答、账号/结构工具（建空文档、建文件夹、移动等），且 **system prompt 禁止代写正文**。产品上需要「AI 帮写」，但不能在 Lexical 主编辑器上硬做 VS Code 行级 inline diff（JSON 树 + mermaid/markmap 等特殊块成本过高）。

讨论结论（2026-07-30，**2026-07-31 修订壳子与 Diff**）：

- 类比 Cursor：**normal ≈ Ask**，**coding ≈ Agent/Coding**
- 帮写进入 **全屏层**（非独立路由）：左 AI、右纯 MD
- Diff：**VS Code Chat Editing 式**——按 hunk **接受 / 拒绝**（参考 `~/github/vscode-main` chatEditing，自研 CodeMirror 实现，不整抄）
- 完成后退出，将用户确认后的 MD 转为 Lexical 写入 lobe
- **不新增** `/api/ai-write`；复用 Agent chat + 既有 create/update
- 改正文类 tool **仅在 coding 模式注册**


危险分层（产品约束）：

| 场景 | 含义 | 危险 |
|------|------|------|
| 从 0 写 | 新建文章 | 低 |
| 改 AI 血统文 | 续写/改 AI 已写且用户未接管的文 | 中 |
| 改用户文 | 动用户主权正文 | 高（须强确认） |

## 目标

1. Agent 请求带 **mode**：`normal` | `coding`；服务端按模式切换 **system prompt + tool 列表**。
2. **normal**：保持现能力（手册 + 结构操作）；**禁止**改正文 / 吐可粘贴长文进库。
3. **coding**：进入帮写 **全屏层**（左对话、右 MD + hunk Diff）；挂载只改 MD buffer 的 tool；用户按段接受提案后点完成写回 lobe。
4. P0 tool 对模型侧 **吐完整 Markdown**；hunk 由前端 diff（相对 `currentMd`）计算，每段可接受/拒绝。
5. 新建文完成路径：**一次 create（可带 content）**，不必为帮写先建空文档再绕草稿。
6. 改已有文完成路径：写入当前文档的编辑器/草稿（不静默 publish）。

## 非目标（本期不做）

- 在 lobe / Lexical 上做 VS Code 式行内绿红 hunk（帮写只在纯 MD 侧做）
- Lexical 树级 / inline 节点级审阅
- 模型侧 patch「改某几行」tool（可列为 P1）
- 独立 `/api/ai-write` 会话资源或跨端恢复未完成帮写稿
- 帮写内 mermaid/markmap 所见即所得预览（MD 源码即可；回 lobe 再渲染）
- 整文件移植 VS Code/Monaco chatEditing 实现（只借鉴交互）
- AI 覆写时主动清草稿 / 前端拦截编辑中的文档（一致性交给 merge；见契约）

## 本次变更（2026-08-03）— Ask 可覆写服务端

> 一句话：空文可直写；有正文须用户同意后才能覆写，或改走帮写；冲突靠 merge；选择卡默认 2 分钟。

| 做 | 不做 |
|----|------|
| 空文：Ask 直写服务端 | 有正文时静默强盖 |
| 有正文：选择卡（直接覆写 / 打开帮写 / 取消） | AI 专门处理草稿一致性 |
| 覆写带读时的 `headCommitId` 作 base | 不传 base 强行跳过 409 |
| 冲突走现有 409 + merge | 为 AI 单独做编辑锁/拦截 |

## 本次变更（2026-08-06）— 流式中可编修改稿

> 一句话：三份 MD 是数据设计（非三栏 UI）；流式与默认均源码编辑 `currentMd`；diff 只读审阅（点「查看 diff」）；**diff 内直接编辑本期不做**。

| 做 | 不做 |
|----|------|
| 流式 `sending` 时整篇可编 `currentMd` | 改成原文/提案/修改三栏 UI |
| 有 hunk 时默认源码可编；「查看 diff」进只读审阅 | **diff 界面内直接打字**（延期） |
| `sending` 不锁右栏编辑 | 流式中边收边改 `proposedMd` |

## 验收标准

- [ ] `POST /api/agent/chat`（或等价）可传 `mode`；缺省为 `normal`（兼容现客户端）。
- [ ] `mode=normal`：几乎空可直写；有正文经选择卡同意后可覆写，或打开帮写；选择卡默认超时 2 分钟。
- [ ] `mode=coding` 时具备至少一种「设置右侧完整 MD」的 tool；调用后前端右侧更新，**不**直接改服务端文档 head。
- [ ] 存在「帮写」入口；进入后为 **全屏层**（左 AI、右 MD + hunk 接受/拒绝）。
- [ ] 用户可对 Agent 提案按 hunk 接受/拒绝；「完成并写回」提交 `currentMd`：MD → Lexical → lobe/草稿或新建；「取消」：lobe 保持进入前状态。
- [ ] 改已有文写回时有明确确认文案（高危）；从 0 可简化确认。
- [ ] 无新专用写库 API；建文/更新走现有 documents API。
- [ ] 帮写流式进行中：右栏可编辑 `currentMd`。
- [ ] 有 hunk 时默认可编源码；「查看 diff」进入只读审阅，可「编辑我的稿」返回。
