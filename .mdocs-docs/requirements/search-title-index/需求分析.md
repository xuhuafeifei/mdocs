# 搜索标题索引 — 需求分析

> 一句话：给标题单独建短索引；召回时先标题后正文、标题权重大；结果带 `document_id` 可跳转；可按工作空间过滤；权限只在业务层做。

## 背景

现网 `documents_fts` 里 **`display_name` 是 `UNINDEXED`**：标题不参与 MATCH，BM25 只看正文。搜「文章名」时，若正文很少出现同词，会排很后甚至搜不到。用户体感是「标题权重拉垮」，实质是 **标题权重 = 0**。

既有能力（保留）：

- 正文 FTS5 + jieba 分词 + BM25
- 可选 `domainId` 过滤（UNINDEXED 列）
- 结果含 `documentId`，前端 / Agent 可跳 `/doc/:id`
- 权限在 `search.service` 用 `canReadDocument`，SQLite 不做 ACL

## 目标

1. **标题可检索**：`display_name` 进入独立标题索引（标题短，重建便宜）。
2. **两路召回**：每次搜索先查标题索引，再查正文索引；按 `document_id` 合并。
3. **标题权重大**：合并分时标题贡献明显高于正文（默认建议见设计契约）。
4. **可跳转**：每条结果仍带 `documentId`（及展示用 `displayName`、`domainId` 等）。
5. **可按工作空间查**：继续支持 `domainId` 限定召回范围。
6. **权限仍在业务层**：FTS 只产出候选；能否看仍走 `canReadDocument`。

## 非目标（本期不做）

- 向量 / 语义检索、embedding
- 在 SQLite 里实现权限或 invite 规则
- 改搜索 API 响应字段形状（可增可选字段，不破现有客户端）
- 路径全文当第二标题源（可选后续；本期只用 `display_name`）
- 向量 / 语义 UI、跨工作空间默认搜、搜索历史 / 最近打开（均可后续）

## UI 入口（与索引同期交付）

主界面 **目录册（侧栏）加搜索按钮**；可选全局快捷键（如 `⌘K` / `Ctrl+K`）。  
点击后屏幕中部 **悬浮搜索横幅**，输入时下方即时列出匹配文章；默认 **当前工作空间**（`domainId`）。  
点结果用 `documentId` 打开文章并关闭浮层。不另做独立「搜索页」。

## 验收标准

- [ ] 标题含关键词、正文几乎不含 → 能搜到，且明显排在「仅正文偶发提及」之前
- [ ] 仅正文命中 → 仍能搜到（标题路空不拖死）
- [ ] 传 `domainId` → 候选与结果均限于该工作空间
- [ ] 无权限文档不出现在最终 topN（与现网一致）
- [ ] 结果含可跳转的 `documentId`
- [ ] 改 `display_name` 后，经 dirty 重建（或同步路径）能按新标题搜到
- [ ] 存量库升级后标题索引可用（迁移 / 全量 dirty 策略见设计契约）
- [ ] 侧栏有搜索入口；打开后默认限定当前工作空间；结果可跳转打开文章
