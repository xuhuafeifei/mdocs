# 搜索标题索引 — 设计契约

> **状态**：已同意并实现（2026-09-24）  
> 配套：[需求分析](./需求分析.md)

## 方案摘要

1. **物理两路索引**：正文继续用现有 `documents_fts`（只索引正文）；**新增**标题专用 FTS 表（只索引短标题）。  
2. **召回顺序**：先查标题索引 → 再查正文索引 → 按 `document_id` 合并打分 → 业务层权限过滤 → 截断 `topN`。  
3. **标题权重大**：合并分默认 `score = W_TITLE * titleHit + W_BODY * bodyHit`（见下）；仅一路命中时另一路按 0。  
4. **载荷列**：两路都带 `document_id`、`domain_id`、`display_name` 等 UNINDEXED 字段，供过滤与跳转；**不做权限列运算**。  
5. **domain 过滤**：两路 MATCH 均可 `AND domain_id = ?`（与现网一致）。  
6. **权限**：仍只在 `search.service` 调 `canReadDocument`；SQLite / FTS 不实现 ACL。

```text
query (+ optional domainId)
        │
        ├─► documents_fts_title  MATCH  →  { document_id, title_bm25, … }
        └─► documents_fts        MATCH  →  { document_id, body_bm25, … }
                    │
                    ▼
            merge by document_id
            final = W_t * norm(title) + W_b * norm(body)
                    │
                    ▼
            canReadDocument 过滤
                    │
                    ▼
            topN + snippet + documentId
```

## 现状问题（确认）

| 项 | 现网 |
|----|------|
| 标题 | `display_name UNINDEXED`，**不参与 MATCH** |
| 排序 | 仅正文 `bm25(documents_fts)` |
| document_id | 已有 UNINDEXED，结果可跳转 |
| domain | `searchDocuments({ domainId })` + FTS `domain_id = ?` |
| 权限 | 业务层 `canReadDocument`，FTS 多取 `topN*4` 再滤 |

## 存储设计

### 新增 `documents_fts_title`（FTS5）

| 列 | 说明 |
|----|------|
| `title` | **可索引**：jieba `cutForSearch` 后的 `display_name` |
| `document_id` | UNINDEXED，跳转与合并键 |
| `display_name` | UNINDEXED，原始标题（展示；与 title 分词前一致时可只存一份策略见实现） |
| `relative_path` | UNINDEXED |
| `domain_id` | UNINDEXED，工作空间过滤 |
| `owner_visitor_id` / `permission` | UNINDEXED，供构造 `DocumentRow` 做权限（与正文表对齐） |

tokenize 与正文表一致：`unicode61` + 写入前 jieba。

### 新增 `documents_fts_title_rowid`

与现网 `documents_fts_rowid` 同构：`document_id` → `fts_rowid`，便于删改标题条目。

### 现网 `documents_fts`

- **保持**只索引 `content`（正文）。  
- **不要**把标题再拼进 `content` 糊弄（避免 snippet 污染、权重复计）。  
- `display_name` 可继续 UNINDEXED 作展示载荷，或逐步只从 title 表读展示名（实现自选，行为对外一致即可）。

### 索引维护

| 事件 | 行为 |
|------|------|
| 正文变更 / dirty 重建 | 写/更新 **正文** FTS；标题若 `display_name` 未变可跳过 title 表 |
| 仅改 `display_name` | 必须更新 **标题** FTS；可标 dirty 或同步写 title 表 |
| 删文档 | 两路 FTS + 两张 rowid 映射都删 |
| 哪些 file_type | 与现网 `ftsIndex` 策略一致（md / 已纳入 FTS 的类型）；html 若已进正文索引则标题同样进 title 表 |

定时 dirty 扫描：一次重建应 **同时**保证该文档 title + content 两路与 DB/`display_name`/磁盘一致（实现可同事务或先 title 后 content）。

## 召回与打分

### 查询

1. `escapeFts5Query` 复用现网。  
2. `titleLimit` / `bodyLimit`：建议各取 `topN * 4`（或标题 `topN * 2`、正文 `topN * 4`，实现可调）。  
3. 若传入 `domainId`：两路 SQL 都加 `AND domain_id = ?`。

### 合并

FTS5 的 `bm25()`：**越小越好**（现网 `ORDER BY bm25_score ASC`）。合并前先对两路分数做同向归一，避免量纲混乱。推荐：

```text
# 对单路候选集：rank_score = 1 / (1 + max(0, bm25))
# 未命中该路：rank_score = 0
final = W_TITLE * title_rank + W_BODY * body_rank
# 最终排序：final 降序
```

**默认权重（可配置常量，先写死再视效果调）：**

| 常量 | 建议默认 | 含义 |
|------|----------|------|
| `W_TITLE` | `3.0` | 标题命中 |
| `W_BODY` | `1.0` | 正文命中 |

仅标题命中应稳定压过「正文弱命中」；两路都强命中应排最前。

### 输出

保持 `SearchResult`：

```ts
{ documentId, displayName, relativePath, domainId, snippet, bm25Score }
```

- `documentId`：合并键，供跳转。  
- `bm25Score`：对外可改为报告 **合并后的 final**（或保留正文 bm25 并另加字段——**优先**：用 `bm25Score` 表示合并分，避免破客户端；文档注明语义变更）。  
- `snippet`：优先从正文抽；若仅标题命中且正文无词，snippet 可用标题或「标题命中」短说明（实现选一种，测试写清）。

## API / 调用方

| 入口 | 行为 |
|------|------|
| `POST /api/documents/search` | body 仍支持 `query`、`domainId?`、`topN?`；语义变为两路合并 |
| `searchDocumentsTool`（Agent） | 自动吃到更好的标题召回，无需改 tool 契约 |
| 前端搜索 | 仍用 `documentId` 跳转文章；见下「主界面浮层」 |

**不在 SQLite 做**：访客是否成员、invite、private/restricted 细则。

## 主界面浮层（UI）

与标题索引同期交付；**不新建搜索路由页**。

| 项 | 约定 |
|----|------|
| 入口 | 侧栏「目录册」区域 **搜索按钮**；另支持全局快捷键 `⌘K` / `Ctrl+K`（与按钮同一浮层） |
| 形态 | 屏幕中部 **悬浮横幅输入框** + 下方结果列表；半透明遮罩；`Esc` / 点遮罩 / 选中结果后关闭 |
| 默认范围 | **当前工作空间**：请求始终带当前 `domainId`（与 `searchDocuments({ domainId })` 对齐） |
| 请求 | 防抖后调现网 `POST /api/documents/search`；吃两路合并后的排序 |
| 结果行 | `displayName` + 可选 `relativePath` / `snippet`；点击 → 打开该 `documentId` 并关浮层 |
| 空 query | 不请求或清空列表（一期不做最近打开） |
| 手机 | 同浮层；结果区可滚动 |

跨工作空间搜索、历史记录：**本期不做**（入口与默认范围先钉死当前空间）。

## 迁移

1. schema 增加 `documents_fts_title` + `documents_fts_title_rowid`。  
2. 启动或迁移末尾：对所有 `ftsIndex` 文档 **`is_dirty = 1`**（或专用全量重建标题索引任务），避免「新库有标题、老库没有」。  
3. 重建完成前：标题路可能偏空，正文路仍可用（降级可接受，须在测试中确认不 500）。

## 风险与回滚

| 风险 | 缓解 |
|------|------|
| 两路 LIMIT 过大拖慢 | 限制倍数；domain 过滤尽早下推 |
| bm25 量纲合并不当导致乱序 | 单测固定语料锁序；权重可调 |
| 迁移漏 dirty | 启动强制扫一遍 ftsIndex 文档 |
| 回滚 | 查寻改回只查 `documents_fts`；title 表可留着不用 |

## 测试要点

- 标题含「恢复码」、正文无 → 能命中且靠前。  
- 正文含、标题不含 → 仍命中。  
- 两篇都命中时，标题强命中排序高于正文弱命中。  
- `domainId=A` 搜不到 B 域文档。  
- 无读文档不进结果。  
- 改名后 dirty 重建，旧标题搜不到 / 新标题能搜到。  
- 删除文档后两路均无残留。

## 明确不做（再强调）

- SQLite 内权限  
- 向量搜索  
- 把标题重复拼进正文 `content` 当永久方案
