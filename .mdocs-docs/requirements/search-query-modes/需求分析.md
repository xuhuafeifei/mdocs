# 搜索查询模式与表格检索 — 需求分析

> 一句话：把已有的搜索接口接进设置页「我的文章」表格，搜索接口增加检索模式入参（关键词 / 语义 / 默认混合、可限定域），并把语义索引的查询与构建暴露为 Agent function tool。

## 背景

- 「我的文章」表格已有分页、域/创建者筛选、分组（`domain-permission-and-doc-table` 已落地），但搜索框是死的：`myDocumentSearch` 只参与空态文案判断，不过滤任何数据。
- 搜索服务（`search.service.ts`）已实现标题+正文两路 FTS 合并、并"尽力"并入语义近邻；语义是否参与**不可控**，调用方没有选择权。
- 语义索引已有 HTTP 管理口（`GET /embedding-index`、`POST /embedding-rebuild`，设置页 Tab 使用），但 Agent 侧没有 function tool：助手无法检索语义、无法帮用户建索引。
- 语义构建权限现状：`rebuildEmbeddingIndex` 逐篇 `canReadDocument` 校验——"能查到（可读）就能索引"已成立，本期固化为明确规则写进契约。

## 目标

1. **表格接入真实查询**：设置页「我的文章」搜索框接 `POST /api/documents/search`；有搜索词时表格显示搜索结果（**所有可读文档**，已拍板 D2），清空后回到分页列表。只影响该表格，不动全局 ⌘K 浮层。
2. **搜索接口模式入参**：`mode?: "auto" | "keyword" | "semantic"`（默认 `auto` = 现网混合逻辑）；`domainId` 沿用。
3. **语义索引 function tool**（Agent）：
   - 查询：`search_documents` 增加 `mode` 参数；
   - 构建：新 tool 包 `rebuildEmbeddingIndex`（按 documentIds）；
   - 状态：新 tool 包 `listEmbeddingIndex`（查哪些文档已建/未建，辅助构建决策）。
4. **索引权限规则**：凡当前访客**可读**的文档即可被其构建索引；不可读一律 skipped。工具与 HTTP 同一套服务层权限。

## 非目标（本期不做）

- 不做远程 Embedding / 换模型 / 维数配置（沿 `search-embedding` 契约的"明确不做"）。
- 不改全局 ⌘K 搜索浮层的交互（浮层仅随响应包装做适配）。
- 不做搜索结果高亮、搜索历史、跨表持久化搜索态。
- 不在 SQLite / FTS 内做权限运算（权限仍在服务层 `canReadDocument`）。

## 验收标准

1. 「我的文章」输入关键词（防抖后）→ 表格显示搜索结果；清空 → 恢复分页列表；域筛选与搜索叠加生效。
2. 模式选择器三档可用：默认（混合）/ 关键词 / 语义；`keyword` 不触发语义；`semantic` 在模型未就绪时返回空结果且带 `modelReady: false`，表格出现"语义模型未就绪"提示而非空白。
3. 搜索结果覆盖所有当前访客可读文档（不限定创建者，D2 已拍板）。
4. Agent：`search_documents` 可传 `mode`；`rebuild_semantic_index` 对不可读文档返回 skipped；`list_semantic_index` 返回已建/未建状态。
5. `pnpm typecheck` 无新增错误；`pnpm vitest run src/server/search/` 通过。
