# 搜索查询模式与表格检索 — 设计契约

> **状态**：已同意（2026-09-30）
> 决策点已拍板：D1 采用响应包装；**D2 表格搜索不限定创建者，搜所有可读文档**；D3 语义路按现网域下推；D4 SearchResult 加 createdAt。
> **增量（同日用户追加）**：⌘K 全局搜索浮层（DocSearchOverlay）同享检索模式选择（默认/关键词/语义），语义未就绪时空结果给明确提示。
> **增量 2（同日用户追加）**：浮层搜索结果**命中高亮 + 命中来源标注**——响应新增 `tokens`（服务端 jieba 分词，与 FTS MATCH 同源，前端 `<mark>` 高亮标题/路径/摘要）；`SearchResult` 新增 `titleHit`/`bodyHit`/`semanticHit`，结果行标题旁标注命中来源小标签，回答"凭什么定位到这篇"。
> 配套：[需求分析](./需求分析.md) · 依据：[search-embedding 契约](../search-embedding/设计契约.md)（已实现）

## 方案摘要

1. **检索模式入参**：`searchDocuments` 增加 `mode?: "auto" | "keyword" | "semantic"`（默认 `auto`）。
2. **表格接查询**：设置页「我的文章」搜索框防抖 300ms → `searchDocumentsApi`；有词 = 结果集渲染（无分页脚），无词 = 现网分页列表。
3. **响应包装**：`POST /search` 响应从裸 `SearchResult[]` 改为 `{ results, modelReady }`（唯一破坏性变更，仓内 2 个调用方同改，见决策点）。
4. **Agent 工具**：`search_documents` 加 `mode`；新增 `rebuild_semantic_index`、`list_semantic_index`，全部直调服务层（与 HTTP 同权限，不走 HTTP）。
5. **索引权限规则**：可读即可索引——`rebuildEmbeddingIndex` 现网逐篇 `canReadDocument` 即此规则，固化为契约条款；工具/HTTP 不得放宽。

```text
我的文章表格
  ├─ 无搜索词 → GET /visitors/me/documents（分页，现网不动）
  └─ 有搜索词（防抖 300ms）
       └─ POST /api/documents/search { query, domainId?, mode?, ownerVisitorId: self, topN: 50 }
            ├─ mode=auto    → FTS 两路 + try 语义 → 合并（现网逻辑）
            ├─ mode=keyword → 仅 FTS 两路
            └─ mode=semantic→ 仅语义近邻；模型未就绪 → { results: [], modelReady: false }

Agent（tools-documents / tools-template）
  ├─ search_documents      + mode 入参 → searchDocuments
  ├─ rebuild_semantic_index（新）      → rebuildEmbeddingIndex（逐篇 canReadDocument）
  └─ list_semantic_index（新）        → listEmbeddingIndex
```

## 决策点（已拍板 2026-09-30）

| # | 决策 | 结论 |
|---|------|------|
| D1 | 搜索响应包装 `{ results, modelReady }`（破坏性，仓内调用方仅 `DocSearchOverlay` + 本期表格） | **采用**：语义模式空结果需要 `modelReady` 区分"没建索引"与"真没有" |
| D2 | 表格搜索是否限定"我创建的" | **不限定：搜所有可读文档**，直接接现网接口；接口不加 `ownerVisitorId` |
| D3 | 语义路无 owner 过滤诉求（D2 后无此需求），域过滤沿用 `querySemanticNeighbors` 现网 `domainId` 下推 | 按现网 |
| D4 | `SearchResult` 增加可选 `createdAt?`（表格"创建时间"列在搜索结果下展示） | **加**：`loadDocumentSearchMeta` 已查 documents 主表，顺带取 `created_at`，不破客户端 |

## 接口变更

### `POST /api/documents/search`

请求体新增：

| 字段 | 类型 | 说明 |
|------|------|------|
| `mode?` | `"auto" \| "keyword" \| "semantic"` | 默认 `auto`；非法值按 `auto` |

响应：

```jsonc
// 旧：data: SearchResult[]
// 新：
{ "data": { "results": SearchResult[], "modelReady": boolean } }
```

- `modelReady`：语义模型是否可用（`keyword`/`auto` 恒为 `isEmbeddingReady()` 现值，供前端提示用）。
- `SearchResult` 增加可选 `createdAt?: string`（D4），其余不变。

### Agent 工具

| 工具 | 参数 | 行为 |
|------|------|------|
| `search_documents`（改） | + `mode?` 同 HTTP | 直调 `searchDocuments`，返回 `{ query, mode, modelReady, results }` |
| `rebuild_semantic_index`（新） | `documentIds: string[]`（必填，≤100） | 直调 `rebuildEmbeddingIndex`；返回 `{ modelReady, ok, skipped, failed }`；**不可读 → skipped** |
| `list_semantic_index`（新） | `domainId?` | 直调 `listEmbeddingIndex`；返回 `{ modelReady, items }`（chunkCount / embeddingUpdatedAt） |

注册位置：`tools-template.ts` `accountTools`（与现有文档工具同组）；`tools-registry.test.ts` 名单同步。

## 风险与回滚

| 风险 | 缓解 |
|------|------|
| 响应包装破坏外部调用方 | 仓内仅 2 处且同改；版本号 minor 提升；如有外部消费者按 major 处理 |
| 语义路域过滤 | 沿用 `querySemanticNeighbors` 现网 `domainId` 下推 |
| 搜索态与分页态状态机混乱 | 单一 `searchActive = query非空` 派生；两态互斥渲染，请求序号防竞态 |
| 模型未就绪时 `semantic` 全空被误读为无结果 | `modelReady` 字段 + 前端明确提示 |
| 回滚 | 前端模式选择回退 `auto`；服务层 `mode` 分支是纯增量，可整体 revert；新工具摘除注册即可 |

## 测试要点

- `mode=keyword`：模型就绪与否均不调 `querySemanticNeighbors`（spy 断言）。
- `mode=semantic`：不查 FTS；模型未就绪 → `{results:[], modelReady:false}`；就绪 → 仅语义命中。
- `mode` 缺省/非法 → 行为等同 `auto`（回归现网）。
- 表格：防抖只发一次；清空恢复分页；域筛选叠加；过期响应被丢弃；搜索态隐藏创建者/分组筛选。
- 工具：`rebuild_semantic_index` 不可读 → `skipped`；`list_semantic_index` 返回 chunk 统计；registry 名单含新工具。

## 明确不做

- 远程 embedding、换模型、维数配置
- SQLite / FTS 内权限运算
- 表格搜索限定创建者（D2 拍板不限定）
- 全局浮层交互重构
- chunk 表加 owner 列
