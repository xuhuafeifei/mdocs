# domain-member-role — 需求分析

> 一句话：受限工作空间成员区分只读 / 可写；默认可看不可写。

## 背景

`domain_members` 只有「在不在名单」。文档默认 `domain_read`，且前端 `canEdit` 不认域成员，成员实际永远只读。需要成员级读写角色。

## 目标

- 成员 `role`: `read` | `write`；默认 / 存量 `read`
- 读：仍靠「是成员」+ 文档档位
- 写：成员 `write` **且** 文档 `domain_write`（双闸门）
- 成员管理 UI 可选角色；创建者强制 `write`
- 文档 meta 带 `domainMemberWrite`，前端据此开放编辑

## 非目标（本期不做）

- 成员模板存角色
- 目录级 ACL
- 取消文档 `domain_read` / `domain_write` 档位
- 改 document invite 语义

## 验收标准

1. 新/老成员默认只读；标 `write` 后可在 `domain_write` 文档编辑
2. 成员 `write` + 文档 `domain_read` 仍不可写
3. GET/PUT members 带 role；创建者不可降为 read
4. invite 与成员仍互斥
