# domain-member-role — 设计契约

> **状态**：已同意（2026-10-29）
> 用户口头确认需求并「改改」后实现。

## 方案摘要

1. `domain_members.role TEXT NOT NULL DEFAULT 'read'`（`read` | `write`）
2. `DomainAccessInfo.domainMemberCanWrite`；`canEditDocument` 在成员写路径检查该标志
3. 文档 detail 增加 `domainMemberWrite?: boolean`；前端 `canEdit` 认它 + `DOMAIN_WRITE`
4. PUT `/api/domains/:id/members` 接受 `members: { visitorId, role }[]`（兼容旧 `visitorIds` → 全 read）；创建者强制 write
5. 成员模板仍只存 ids，套用默认 read

## 风险与回滚

- 存量默认 read，行为与现网「成员 UI 只读」一致，不突然放开写
- 回滚：忽略 role 列、恢复「是成员即可写 domain_write」（前端仍可能挡）

## 测试要点

- canEdit：member read + DOMAIN_WRITE → false；member write + DOMAIN_WRITE → true；member write + DOMAIN_READ → false
- PUT members 创建者始终 write
- 前端打开 DOMAIN_WRITE 文档时 write 成员出现编辑入口
