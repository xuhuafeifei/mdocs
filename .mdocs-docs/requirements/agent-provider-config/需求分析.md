# Agent 提供方配置扩展 — 需求分析

> **状态**：进行中（2026-08-26）

## 背景

当前 mdocs 智能助手 / 帮写仅支持 **DeepSeek 预设**：endpoint 写死、modelId 白名单、设置页 + 内嵌只填 API Key。

后续要扩展更多 LLM，但 **不复制 ds-harness 的多提供方 registry**（无提供方列表增删、无模型目录拉取、无 settings revision）。pi 运行时只需 **baseUrl + apiKey + modelId + apiType** 四元组；产品上拆成两条配置线即可。

## 目标

1. **线 A — DeepSeek（默认推荐）**：用户只填 API Key + 模型；**保存时**服务端把 baseUrl / apiType / providerId 等 **预设写入 DB**。
2. **线 B — 自定义**：用户填 **baseUrl、apiType、modelId、apiKey**；**providerId 选填**。
3. **运行时统一**：`createAgentModel` 只读库内字段，**不区分** deepseek / custom。

## 非目标（本期）

- 一访客多提供方并存、运行时切换 providerId
- 「获取可用模型」、模型目录维护、compat 高级项 UI
- 图谱 LLM 与访客配置合并（仍用服务端 env，另议）
- apiKey 迁 secrets 文件（可后续单独做；本期仍 SQLite + 抽象读写 seam）

## 验收

- [ ] 新用户默认走 DeepSeek 线；保存 Key 后助手 / 帮写可用
- [ ] 切换到自定义线后，可填 URL + 协议 + model + Key（providerId 可选）
- [ ] UI 展示：DeepSeek 线为 **Deepseek**；自定义线展示 providerId 或配置名称
- [ ] DeepSeek 保存后 GET 含落库的 `baseUrl`（非运行时补全）
- [ ] `run.ts` **无 kind 分支**，仅按 `apiType` + 行内 baseUrl/modelId 建 pi Model
- [ ] 已有 `deepseek-v4-*` 配置迁移后行为不变
