# 搜索语义索引 — 需求分析

> 一句话：在现有「标题 + 正文」关键词检索之上，用**本地固定** Embedding 模型做语义召回；与文章索引同生命周期构建；失败/未就绪永不挡 FTS 主链路。

## 背景

现网搜索（Web 浮层 / Agent `search_documents`）共用 `searchDocuments()`，只有 FTS5 关键词两路（标题 / 正文）。关键词没命中则空结果；用户体感是「明明域里有文章却毛都没有」。

本机已有可参考的本地栈（来自已下线的 agent-demo 设计，**非 mdocs 现网能力**）：

- `node-llama-cpp` + GGUF `nomic-embed-text-v1.5.Q4_K_M`（768 维）
- 模型文件习惯路径：`~/.fgbg/shared/embedding/`
- 向量侧曾用 `sqlite-vec`

mdocs 约束：**不接外部 Embedding API、不提供 provider 拓展**；语义是增强，不是核心。

## 目标

1. **语义召回**：查询向量与文档块向量做近邻，补关键词盲区。
2. **与文章检索同构构建**：文档 dirty / 重建时，在 FTS 之外同步维护语义索引（可同事务或紧随其后；失败只记日志）。
3. **本地固定模型**：仅 nomic GGUF；无 remote / 无换模 UI。
4. **启动异步下模型**：进程启动后**后台**下载 GGUF；禁止阻塞启动或首屏。
5. **降级安全**：磁盘无模型 / 文件损坏 / 推理失败 / 向量库异常 → 语义路跳过，FTS + 权限链路不变。
6. **同一 API**：仍 `POST /api/documents/search`；Web 与 Agent 自动受益。

## 非目标（本期不做）

- OpenAI / DeepSeek 等远程 embeddings
- 可插拔 provider、配置页选模型
- 同步阻塞下载或「没模型不许搜」
- 在 SQLite 内做 ACL
- 跨工作空间默认语义搜（浮层仍默认当前 `domainId`）
- 向量 UI 单独产品页

## 验收标准

- [x] 冷启动不因下模型而卡住 HTTP / Web
- [x] 下载过程有进度日志（可读百分比或字节）
- [x] 模型未就绪时，关键词搜索行为与现网一致
- [x] 模型可用后：与标题/正文无关但语义相近的查询能返回候选（经权限过滤；单测 stub 向量）
- [x] 人为弄坏/删除 GGUF 后搜索不 500，仍可走 FTS
- [x] 语义路抛错不影响 FTS 合并与 `canReadDocument`
- [x] 改文 / 删文后语义索引可随 dirty 重建清理（失败不挡 FTS dirty 清除策略见契约）
