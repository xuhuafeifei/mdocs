# 搜索语义索引 — 设计契约

> **状态**：已同意并已实现（2026-09-30）  
> 配套：[需求分析](./需求分析.md) · [代码索引](./代码索引.md)

## 方案摘要

1. **能力分层**：关键词（已有 FTS 标题+正文）是主链路；语义（本地 embedding + 近邻）是可选增强路。  
2. **同构构建**：`rebuildDocument` / dirty 扫描在写完 FTS 后，**尽力**更新该文档的向量块；失败只 `warn`，不回滚 FTS、不保留无意义的语义半态即可（见下）。  
3. **模型**：写死 `nomic-embed-text-v1.5.Q4_K_M`，维数 **768**；推理 **`node-llama-cpp`**。  
4. **启动**：`startIndexTimer`（或 server bootstrap）旁挂 **异步** `ensureLocalEmbeddingModel()`：缺文件则下载，**绝不 await 在 listen 之前**。  
5. **查询**：`searchDocuments` 先跑现网 FTS 合并；再 **try** 语义 topK；按 `document_id` 并入后统一 `canReadDocument` + topN。语义任一步失败 → 当语义结果为空。  
6. **简单优先**：少抽象、无 provider 接口、无远程模式、无配置页选模。

```text
启动
  └─► (async) 缺 GGUF？下载并打进度日志 → 就绪标记

文档 dirty 重建
  ├─► FTS 标题 + 正文（现网，必须成功才清 dirty 的规则保持）
  └─► try 切块 embed 写入向量表（失败仅日志）

searchDocuments(query, domainId?)
  ├─► FTS 两路合并（主）
  ├─► try 语义近邻（模型文件存在且可 load 才跑）
  ├─► merge by document_id
  └─► canReadDocument → topN
```

## 模型与磁盘

| 项 | 约定 |
|----|------|
| 文件名 | `nomic-embed-text-v1.5.Q4_K_M.gguf` |
| 默认目录 | `~/.fgbg/shared/embedding/`（与本机已有文件对齐）；可用环境变量覆盖目录，**不可换模型名** |
| 可用性 | 文件存在 + 非 0 字节 + 能被 `node-llama-cpp` 成功 load 一次（或缓存「已验证」标记，进程内即可） |
| 下载 | HTTP GET 固定 URL（实现时写死官方/镜像其一；契约不绑具体 CDN）；**仅后台任务**；日志打印进度（如已下/总长或 %） |
| 并发 | 全局一把下载锁，避免多处同时拉 |

**查询前门闩**（任一条否 → 跳过语义、不抛给调用方）：

1. 磁盘上有该 GGUF  
2. 当前认为「可用」（load 成功过，或即时 load 成功）  
3. 向量表/扩展可查询  

## 索引存储（从简）

- 表名建议：`document_embedding_chunks`（普通 SQLite 表即可；若引入 `sqlite-vec` 仅作加速，**不是**硬依赖——实现选更简单的一种并在代码索引写明）。  
- 最小字段：`document_id`, `domain_id`, `chunk_index`, `text`(可选短摘), `embedding` BLOB(Float32×768), `updated_at`。  
- **切块**：对 FTS 同源纯文本（Lexical 抽字后）按字符窗切，默认 `chunkMaxChars ≈ 500`、可轻微重叠；一篇文档多行。  
- **删文档**：与 `removeIndex` 同钩子删该 `document_id` 全部 chunk。  
- **dirty**：FTS 重建成功仍按现网清 `is_dirty`；语义失败**不**因此把文档永远钉在 dirty（避免拖垮主索引）。语义漏编可下次启动/下次 dirty 再补，或定时「无向量的 md 扫一遍」（实现二选一，保持简单）。

## 召回与合并

| 项 | 约定 |
|----|------|
| 查询 embed | 对用户 `query` 整句（或截断）embed 一次 |
| 近邻 | cosine / 内积；取 `topK`（建议 20～40，可常量） |
| domain | SQL/`domain_id` 与 FTS 一样可下推 |
| 合并 | 已有 FTS 命中保留；语义命中补入；可选给语义一个低于标题的权重常量；**无命中语义时行为 = 纯 FTS** |
| 权限 | 仍只在合并后 `canReadDocument` |
| 失败 | `try/catch` 包整段语义；吞掉错误，返回 FTS 结果 |

对外 `SearchResult` 可不加新必填字段；若加 `matchSource?: "fts" | "semantic" | "both"` 为可选，不破客户端。

## 风险与回滚

| 风险 | 缓解 |
|------|------|
| GGUF 大、首下慢 | 异步 + 进度日志；语义非阻塞 |
| native 依赖装不上 | 语义整路 disable；FTS 不受影响 |
| 内存占用 | 单例加载模型；查询侧超时/失败即跳过 |
| 回滚 | 查询侧关掉语义调用；表可留 |

## 测试要点

- 无 GGUF：搜索 = 纯 FTS；启动日志出现下载进度（可测 fake）。  
- GGUF 损坏：判定不可用，搜索不炸。  
- embed/查询抛错：仍返回 FTS 列表。  
- 有模型：语义可补出 FTS 搜不到的近义文档（可用 stub 向量测合并逻辑）。  
- 删文档后 chunk 无残留。

## 明确不做

- 远程 Embedding / provider 插件化  
- 同步下载挡启动  
- 语义失败拖死或回滚 FTS  
- 换模、配维数 UI（维数写死 768）
