## 方案摘要

### `dataDir` 是什么

运行时配置 **`MDOCS_DATA_DIR`**，未设时默认 **`~/.mdocs`**（见 `src/server/config`）。下文 `{dataDir}` 均指此处。其下已有 `sqlite/`、`files/`、`logs/`、`tenant/` 等。

### 分层

| 层 | 职责 |
|----|------|
| **流水线定义（YAML 文件）** | 步骤序列 + 元数据；路径字段由系统忽略/禁止用户乱填 |
| **解释器** | 按 `type` 分发；probe → skip；装完跑 **hooks**（含灵魂旁路） |
| **安装态 `plugins.json`** | 「哪些插件已对实例宣告安装成功」的索引，不是流水线正文 |
| **MCP / skill 出口** | `mcp-servers.json` / `agent_user_skills` |
| **灵魂目录** | 全局 + 个人各一目录；`mdocs.md` + 插件旁路同级；**整目录按规则注入 Agent** |
| **Engram 特判** | spawn 注入 visitor project；代调 `mem_session_start`；对 Agent 隐藏该 tool |

### 目录约定

```text
{dataDir}/                          # 默认 ~/.mdocs
  soul/                             # ★ 全局灵魂目录（非 dataDir 根裸奔）
    mdocs.md                        # 空壳
    engram.md                       # 插件旁路示例（安装 hook 写入；卸载删文件）
  plugins/
    system/                         # 系统自带；目录名 = 随机 id
      847291036512/
        pipeline.yaml
        pipeline.yaml.default       # 恢复初始用
    user/
      <randomId>/pipeline.yaml
    install/                        # 安装物，按随机 id
      847291036512/…
  plugins-data/                     # 按 data_key / runtime（如 engram），不跟随机 id
    engram/
  plugins.json
  mcp-servers.json
  tenant/{visitorId}/
    soul/
      mdocs.md
      …旁路
    plugins/
      <randomId>/pipeline.yaml
```

说明：

- **安装物** → `plugins/install/<随机id>/`。  
- **插件业务数据** → `plugins-data/<data_key>/`（Engram=`engram`）。  
- **流水线 YAML** → `plugins/system|user|tenant/…/<随机id>/`。  
- **认 Engram 特判** → YAML `runtime: engram`，不是 id。  
- **灵魂** → `soul/` 旁路同级独立文件；卸载删文件。

### 流水线格式：YAML

- **`id`**：创建时 **随机 roll**（数字字符串或 UUID），作目录名 / `plugins.json` / `plugins/install/<id>/` 主键。  
- **`runtime`**：稳定类型（如 `engram`），给宿主特判；**不要用可读名当 id**。  
- **`data_key`**：可选；`plugins-data/<data_key>/`，与随机 id 解耦。

完整 Engram 编排 DEMO（给人审样式）：  
[`demos/engram.pipeline.yaml`](./demos/engram.pipeline.yaml)

骨架：

```yaml
id: "847291036512"          # roll
name: Engram
kind: system                # system | user | tenant
runtime: engram             # 特判键
data_key: engram
outputs: [mcp]
probe:
  - type: file_exists
    path: root/bin/engram   # 相对 install/<id>/
steps:
  - type: download
    url_template: https://…/engram_{{version}}_{{goos}}_{{goarch}}.tar.gz
  - type: extract
  - type: exec
    command: root/bin/engram
    args: [init, mdocs-template, --force]
  - type: upsert_mcp
    transport: stdio
    command: "{{install_root}}/root/bin/engram"
    args: [mcp, --project=mdocs-bootstrap]
  - type: write_soul_sidecar
    scope: global
    file: engram.md
    content: |
      …
uninstall:
  - type: delete_soul_sidecar
    file: engram.md
  - type: remove_mcp
```

用户**不填** download dest；解释器写入 `plugins/install/<id>/…`。

### `plugins.json` 存什么

**安装态索引**（非流水线正文）。典型字段：

```json
{
  "installed": [
    {
      "id": "847291036512",
      "name": "Engram",
      "runtime": "engram",
      "installedAt": "ISO-8601",
      "mcpServerId": "mcp-847291036512",
      "source": "system"
    }
  ]
}
```

用于：已装列表、二次安装 skip、卸载撕 MCP / 旁路；特判 Engram 看 **`runtime`**，不看 id。

### 插件两类（对人，不抽象成「选一个插件」空壳）

| 类 | 定义位置 | 行为 |
|----|----------|------|
| **系统自带** | `plugins/system/<id>/` | 发版带默认 YAML；用户可改本地副本；提供 **恢复初始**（用 `.default` 或包内只读覆盖回写） |
| **用户自定义** | `tenant/{visitorId}/plugins/<id>/`（及可选实例 `plugins/user/`） | 用户自建/拖拽编排步骤；本期不做模板市场，契约预留「未来 MCP/skill 模板」 |

安装：对某条 YAML 跑解释器 → 写 install / MCP|skill / soul 旁路 → 更新 `plugins.json`。

### 步骤与勾子

步骤类型仍闭集：`download` | `extract` | `exec` | `upsert_mcp` | `upsert_skill` | `write_soul_sidecar` |（卸载）`delete_soul_sidecar`。

- **装完勾子**：把旁路文件写到**当前作用域** `soul/` 下，与 `mdocs.md` 同级 → 卸载只删该文件。  
- **不是**插入/打补丁 `mdocs.md`。  
- Agent **读取的是 soul 目录约定文件集合**，不是「整个 dataDir」。因此旁路会出现在提示词里，但 **不会**和 `sqlite/`、`files/` 混在同一层「裸露」；目录就是灵魂专用。

### 灵魂注入 Agent（本期要改主流程）

每轮 `run` 组装 system（或等价前缀）时追加：

1. `{dataDir}/soul/mdocs.md`（若存在）  
2. 同目录下已启用插件旁路（白名单扩展名 `.md`，单文件字节上限建议 32KiB，合计上限建议 64KiB——实现时可调）  
3. `tenant/{visitorId}/soul/mdocs.md` + 个人旁路  

顺序：全局 → 全局旁路 → 个人 → 个人旁路。

### Skill meta 注入（本期一并）

现网：skill **全文**仅在用户点选/`skillNames` 时 hydrate；模型主要靠工具 `list_user_skills`。  

本期在 system 侧增加 **只读目录摘要**（无正文）：当前访客 skill 的 `name` + `description`（及可选 updatedAt），让模型知道有哪些宏可 `get_user_skill` / 请用户点选。  
**不**把全部 body 塞进 system（避免爆 context、与「点选展开」重复）。

### Engram

- 系统流水线自带，**默认未安装**。  
- 安装物：`plugins/install/engram/`；数据：`plugins-data/engram/`（`ENGRAM_DATA_DIR` 指这里）。  
- Run：`loadMcpAgentTools(visitorId)` → project=`mdocs-<visitorId>`（UUID 可直接用，简单）→ 代调并 **隐藏** `mem_session_start`。  
- 旧库忽略。

## 对你列的疑问（对照答复）

1. **YAML？** → 是，`pipeline.yaml`。  
2. **灵魂裸露 dataDir？dataDir？** → dataDir=`MDOCS_DATA_DIR`≈`~/.mdocs`；灵魂进 **`soul/` 子目录**，不跟 sqlite/files 平铺抢根。  
3. **勾子 vs mdocs.md** → 旁路**独立文件**同级；卸载删文件。Agent 读 soul 目录，不是把插件正文合并进 `mdocs.md`。  
4. **engram-data** → 改为 `plugins-data/engram/`（上层 `plugins-data/`）。  
5. **plugins.json** → 已装插件索引（id、时间、mcpServerId…），非流水线内容。  
6. **download `<id>`** → 即插件 `id`（如 `engram`）。  
7. **选插件抽象** → 改为系统自带（可改+恢复初始）vs 用户自定义；模板后期。  
8. **Agent 主流程** → 必须加载 soul；并注入 skill **meta**（非全文）。

## 风险与回滚

| 风险 | 态度 |
|------|------|
| Tenant 可 exec/download | **已知接受**；后续白名单/Agent 危判收口 |
| 任意访客改系统流水线 / 装系统插件 | 与现网「任意访客改 MCP」同级；管理员模型后期再加 |
| 灵魂目录被塞爆 | 扩展名 + 体积上限 |
| 隐藏 session_start | 宿主代调失败要可见日志 |

## 测试要点

- YAML 安装 Engram → install + plugins-data + soul 旁路 + plugins.json + MCP。  
- 卸载 → 旁路文件删除；MCP 项删除。  
- 系统流水线改烂后「恢复初始」回到 default。  
- A/B visitor Engram project 隔离；tools 无 `mem_session_start`。  
- run 的 system 含 soul 文本 + skill meta 列表；未点选时无 skill 全文。  
- 未装 Engram → 不 spawn。

## 仍可微调（不挡框架开工的小项）

- 实例级 `plugins/user/` 要不要一期就做，还是只做 `system` + `tenant/.../plugins`。  
- skill meta 注入条数上限（如最多 50 条）。
