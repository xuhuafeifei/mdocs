# 按目录取子树 — 需求分析

> 一句话：用目录的 `folderId` 拉取该目录下的嵌套结构，节点只带 id + 标题，并区分目录与文章。

## 背景

已有：

- `GET /api/tree?domainId=`：整域递归树（字段较多）
- `GET /api/documents/folder/:folderId/children`：仅**一层**子节点扁平列表

调用方需要：**给定某个目录 id**，拿到其下完整结构 + 文章 id/标题，便于局部展示或 Agent/脚本消费，而不必拉整域树。

## 目标

1. 新增 HTTP：按 `folderId`（目录的 `document_id`）返回子树。
2. 保留树形嵌套；节点区分 `folder` / `document`。
3. 每节点至少：`id`、`title`；目录另有 `children`。
4. 权限与现网树一致：不可见节点裁掉；非目录 id → 明确错误。

## 非目标（本期不做）

- 按 path / domainId+path 定位
- 返回正文、`relativePath`、`updatedAt`、owner 等扩展字段
- `depth` 限制（默认全递归；一层继续用现有 `children`）
- Agent tool（可后续加）
- 废弃或改语义现有 `children` / `/api/tree`

## 验收标准

- [ ] `GET .../folder/:folderId/tree`：目录存在且可读时返回嵌套子树（不含自身，或其约定见契约）。
- [ ] 节点含 `type`、`id`、`title`；`folder` 含 `children`。
- [ ] 传入普通文章 id → `400`（不是目录）。
- [ ] 无权 / 不存在 → 与现网 children 策略一致（见契约）。
- [ ] 不返回 markdown 正文。
