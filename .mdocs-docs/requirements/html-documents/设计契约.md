# HTML 文档支持 — 设计契约

> **状态**：草案  
> 未经「已同意」不得开始写业务代码。  
> 配套：[需求分析](./需求分析.md)

## 方案摘要

1. 新增用户可见文档类型 `file_type = html`，磁盘路径以 `.html` 结尾，与 `md` 平级（权限 / commit / move / 树）。
2. **内容形态分流**：`md` 磁盘与草稿仍为 Lexical JSON；`html` 磁盘与草稿存 **HTML 原文**。
3. **草稿 / 发布壳复用**（讨论结论 B）：同一套 IndexedDB 草稿键（`documentId`、`localBaseCommitId`、publish）；用 `contentKind`（或等价字段）区分 payload。
4. **冲突 merge（结论 C）**：共用 `merge-plan` 行级三路；`md` 仍走 Lexical↔MD 桥；`html` **直通原文**（跳过 `LexicalMarkdownBridge` / `convertContentApi`）。
5. **不进 FTS、不进图谱抽取**；CLI `format=text` 按类型抽文本（html 不走 Lexical）。
6. **收口**：在 `src/shared` 落地 **file_type 政策表 + 派生查询**；热点路径（tree / move / FTS / graph include / path / textExtract）改为读表；少量管道用策略键派发。本期顺手迁现有 `md` 相关硬编码，不另开「策略基建」大 PR。
7. 预览：`iframe` + `sandbox=""`（初版禁 JS）；编辑：textarea 左右分栏 + 实时预览。

## file_type 政策表（请 review）

> 权威落点：新建 `src/shared/file-type-policy.ts`（或扩展现有 `file-types.ts`，二选一，建议 **旁挂 policy 文件**，`file-types.ts` 只保留常量 + 薄委托）。  
> 前后端 **共用一份表**；后端强制执行安全/数据政策，前端消费编辑器/草稿/merge 键。

### 字段含义

| 字段 | 含义 |
|------|------|
| `treeVisible` | 侧栏树是否作为独立节点展示（`folder_desc` 为 false，挂到目录） |
| `treeInclude` | `buildDocumentTree` / `buildFolderSubtree` 的 `includeTypes` 是否包含 |
| `movable` | 是否走「文章 move」（`POST .../move`）；目录另路径 |
| `ftsIndex` | 是否进入 `documents_fts` |
| `graphExtract` | 图谱构建是否当文章抽取（`readMarkdown` 路径） |
| `graphWalkStruct` | 是否作为图谱 walk 的结构节点（dir / folder_desc） |
| `pathExt` | 创建/规范化允许的后缀；`null` 表示目录无后缀 |
| `textExtract` | `GET ?format=text` / CLI 纯文本：`lexical` \| `raw` \| `none` |
| `writeNormalize` | 写入前：`md-lexical`（可 markdown→Lexical）\| `raw` \| `none` |
| `draftKind` | 本地草稿：`lexical` \| `html` \| `none` |
| `mergePipeline` | `lexical-md-bridge` \| `raw-text` \| `none` |
| `editor` | `lobe` \| `html` \| `none` |

### 全量表（本期目标态）

| file_type | treeVisible | treeInclude | movable | ftsIndex | graphExtract | graphWalkStruct | pathExt | textExtract | writeNormalize | draftKind | mergePipeline | editor |
|-----------|:-----------:|:-----------:|:-------:|:--------:|:------------:|:---------------:|---------|-------------|----------------|-----------|---------------|--------|
| `md` | ✅ | ✅ | ✅ | ✅ | ✅ | ❌ | `.md` | lexical | md-lexical | lexical | lexical-md-bridge | lobe |
| `html` | ✅ | ✅ | ✅ | ❌ | ❌ | ❌ | `.html` | raw | raw | html | raw-text | html |
| `dir` | ✅ | ✅ | ❌ | ❌ | ❌ | ✅ | — | none | none | none | none | none |
| `folder_desc` | ❌ | ✅ | ❌ | ❌ | ❌ | ✅ | `.md` | lexical | md-lexical | none | none | none |
| `graph_file` | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ | `.json` | none | none | none | none | none |
| `graph_dir` | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ | — | none | none | none | none | none |

### 派生查询（调用方应使用这些，而不是字面量数组）

```ts
treeIncludeTypes()       // treeInclude === true
  // → md, html, dir, folder_desc

graphWalkIncludeTypes()  // graphWalkStruct || graphExtract
  // → md, dir, folder_desc   （html 不在）

ftsIndexTypes()          // ftsIndex === true
  // → md

movableDocTypes()        // movable === true
  // → md, html
```

### 策略键派发（少量，按「操作」收拢）

| 键 | 实现位置（示意） | 行为 |
|----|------------------|------|
| `textExtract: lexical` | server：`extractPlainTextFromLexical` | 现逻辑 |
| `textExtract: raw` | server：原文返回（可选后续 strip 标签） | html / CLI |
| `writeNormalize: md-lexical` | `normalizeDocumentContent` / create 的 contentFormat | 现逻辑 |
| `writeNormalize: raw` | 禁止当 Lexical 解析；原样写盘 | html |
| `mergePipeline: lexical-md-bridge` | `MergeView` + Bridge + convert | 现逻辑 |
| `mergePipeline: raw-text` | 三份字符串直进 `buildThreeWayMergePlan`；发布不 convert | html |
| `editor: lobe` / `html` | `App.tsx` 分支 | DocumentEditor / HtmlEditor |

**不加**「每个 file_type 一个全能 Strategy 类」。`graph_file` 的 `draftKind=none` 表示不实现草稿，不是空方法。

## 现状 → 怎么改（按模块）

### A. shared

| 文件 | 现状 | 改成 |
|------|------|------|
| `file-types.ts` | 常量 + `isVisibleFileType` 只认 md/dir | 增 `HTML = 'html'`；`isVisibleFileType` **改为读政策** `treeVisible`（或委托 policy） |
| **新建** `file-type-policy.ts` | 无 | 上表 + `policy()` / `typesWhere` / 派生函数 |
| `docPath.ts` | 仅 `.md` / `.json` | 允许 `.html`（与 pathExt 一致） |
| `storagePath.ts` | `parseDisplayNameMarkdownFile` / `normaliseRelativePathForStorage` 写死 `.md` | 按创建时的 `fileType` 选后缀；或新增 `parseDisplayNameHtmlFile` + 通用 `normalise…(ext)` |
| 类型 `DocumentSummary` 等 | 已有 `fileType` 则复用 | 确保 API/前端 meta 带 `fileType` |

### B. 后端 document 主路径

| 符号 / 位置 | 现状 | 改成 |
|-------------|------|------|
| `normalizeFileName`（`document.service.ts`） | 非 `.md` 则 **追加 `.md`** → `a.html` 变 `a.html.md` | 按 `fileType` 用 `pathExt`；`html` 保证 `.html`，`md` 保证 `.md` |
| `createDocument` | 已有 `fileType?` 默认 md；内容默认当 Lexical/markdown 转 | `fileType=html` 时：`writeNormalize=raw`，**禁止** `contentFormat=markdown` 转 Lexical；默认空内容可为 `<!-- -->` 或空串 |
| `updateDocument` | `normalizeDocumentContent` 按 contentFormat | html：**不**走 markdown→Lexical；冲突 merge 入参同理 |
| `getDocument(..., format)` | `format=text` **无条件** Lexical 提取 | `extractTextForRead(file_type, content)` 读 `textExtract` |
| `moveDocument` | `file_type !== "md"` 拒绝 | `!policy(t).movable` 拒绝 → **html 可 move** |
| 删除 | md 有特殊分支（图谱 dirty 等） | html：当普通文档删；**不**建文章级 graph 缓存；若有祖先 dirty 逻辑，html 发布是否标脏见下「图谱」 |

### C. 树 / 路由

| 位置 | 现状 | 改成 |
|------|------|------|
| `tree.routes.ts` | `includeTypes: ["dir","md","folder_desc"]` | `treeIncludeTypes()` |
| `documents.routes` subtree | 同上 | 同上 |
| `POST /api/documents` | 校验 fileName 等 | 校验 `fileType ∈ {md,html}`（用户可建）；内部类型不可经此创建 |

### D. 搜索

| 位置 | 现状 | 改成 |
|------|------|------|
| `document-index-manager` dirty 扫描 | `file_type = 'md'` | 保持等价：`ftsIndexTypes()` 或继续只扫 md（html 永不 dirty 进 FTS）。**不必**为 html 写跳过分支若从未标记索引 |

### E. 知识图谱

| 位置 | 现状 | 改成 |
|------|------|------|
| `graph.service` `buildFolderSubtree` includeTypes | `dir,md,folder_desc` | `graphWalkIncludeTypes()`（不含 html） |
| 域顶层 filter | 只排除 graph_file/graph_dir | 顶层若出现 html：`buildTreeNodeForDoc` 今日会当「普通文章」；应 **跳过** `!graphExtract` 的叶子，或建节点但不 `readMarkdown`。**契约要求：不抽取、不进子树 walk** |
| `readMarkdown` deps | 永远 Lexical 提取 | 仅 graphExtract 类型会调用；实现可仍 Lexical，或统一走 `textExtract` |
| 发布 lifecycle | md 变化率 / dirty | html **不**写文章级 `__graph__/{id}.graph.json`；可选：不 `markAncestorsDirty`（推荐本期：**发布 html 不触发图谱 dirty**，避免无意义重建） |

### F. 前端

| 位置 | 现状 | 改成 |
|------|------|------|
| 创建 UI（`useCreateModal` / App 工具栏） | 仅 md 文件名 | 下拉选类型 → 默认名 `untitled.md` / `untitled.html`；校验走对应 path 助手 |
| `App.tsx` | 一律 DocumentEditor | `policy(fileType).editor` 分支 |
| **新建** `HtmlEditor.tsx` | 无 | 预览 iframe `srcdoc` + `sandbox=""`；编辑左右栏 textarea + 预览；接 autoSave/publish |
| `drafts.ts` `DraftRecord` | `content` 假定 Lexical | 增 `contentKind: 'lexical' \| 'html'`（或从打开时的 fileType 推断并写入）；autoSave 原样存字符串 |
| `useAutoSave` | 听 Lobe 更新 | HtmlEditor 用 textarea `onChange` 喂同一 hook（或薄包装）；**不要**走 Lexical updateListener |
| `MergeView` | 三路皆 Lexical → Bridge → MD | 若 `mergePipeline=raw-text`：local/base/remote **当字符串**；完成发布 **不** `convertContentApi`；`updateDocument` 直接 HTML |
| `DocumentTree` | md 图标 | html 区分图标或 `.html` 后缀 |
| 设置 `autoEdit` | 打开即编辑 | **仅 lobe/md**；html 强制先预览 |

### G. CLI / Agent（行为，未必改 CLI 仓）

| 行为 | 现状 | 改成 |
|------|------|------|
| `get ?format=text` | 当 Lexical 抽 | html → raw（或剥标签）；md 不变 |
| `list` / 树 | 跟 tree API | 自动出现 html；仍无 graph 隐藏文件 |
| `create --name` | 偏 `.md` | 支持 `.html` + 服务端 fileType；若 CLI 本期不改，至少 API 就绪（契约：**API 必须支持**；CLI 旗标可同期或紧随） |

- 隐藏 `___graph___` / `__graph__` 对 CLI 暴露

## 数据流（对照）

### 创建 html

```text
UI 选 HTML → fileName untitled.html, fileType=html, content=""
  → normalizeFileName(html) 保 .html
  → writeDocument 原文 → commit blob 原文
  → documents.file_type='html'
```

### 编辑 / 草稿 / 发布

```text
打开 html → 预览 iframe(srcdoc)
  → 编辑：textarea 改文 → useAutoSave → IDB draft { contentKind:'html', content, localBaseCommitId }
  → 发布：updateDocument(content=HTML原文) 与 md 同乐观锁 / merge 入口
```

### 冲突 merge（html）

```text
local/base/remote = HTML 字符串（blob / 草稿快照）
  → buildThreeWayMergePlan（同行级 diff3）
  → 用户接收/拒绝
  → updateDocument(mergedHtml)   // 无 markdown↔Lexical
```

### 冲突 merge（md，不变）

```text
Lexical → LexicalMarkdownBridge → MD
  → merge-plan → convert MD→Lexical → updateDocument
```

## API 契约（增量）

### `POST /api/documents`

| 字段 | 说明 |
|------|------|
| `fileType` | 可选，默认 `md`；允许 `md` \| `html` |
| `fileName` | 与类型后缀一致（或服务端按 fileType 补全） |
| `content` | html 时为 HTML 字符串；md 时仍 lexical 或 `contentFormat=markdown` |
| `contentFormat` | **仅 md**；html 传 markdown 应 400 |

### `GET /api/documents/:id?format=json|text`

- 响应 `fileType`（若尚未暴露则补上）
- `format=text`：按政策 `textExtract`

### `PUT` / merge 相关

- 请求体内容形态与 `fileType` 一致；服务端按 `writeNormalize` 处理
- merge 上下文读 blob：**原样返回**（html 即 HTML，md 即 Lexical）——前端按 `mergePipeline` 解释

## 风险与回滚

| 风险 | 缓解 |
|------|------|
| HTML 行级 merge 对压缩成单行的文档几乎无用 | 文档提示；后续可再做格式化，不阻塞本期 |
| 政策表与残留 `=== "md"` 不一致 | 本期强制改变更触达中的热点；加 policy 单测锁派生列表 |
| iframe 沙箱绕过 | 仅最严 sandbox；禁止主文档区直插 HTML |
| 草稿 contentKind 旧数据 | 缺省当 lexical（兼容旧 md 草稿） |

**回滚**：隐藏创建 HTML 入口；已有 html 仍可读（或降级源码）。

## 测试要点

1. 创建 `.html`，磁盘与 DB `file_type=html`，内容原文往返。
2. `a.html` 不会被 normalize 成 `a.html.md`。
3. 树可见；move / 删与 md 同权模型。
4. FTS 搜正文搜不到 html；标题是否可搜：本期 **不要求**（与「不进 FTS」一致）。
5. 目录生成图谱：子树无 html 节点被抽取；强制 regenerate 也不读 html 当 Lexical。
6. `GET ?format=text`：md=纯文本近似，html=原文（或约定剥标签后的稳定行为，测锁定一种）。
7. 草稿：编辑 html → IDB `contentKind=html` → 发布成功清草稿。
8. 冲突：两访客改同一 html → MergeView 无 Bridge → 发布仍为 HTML。
9. iframe：含 `alert(1)` / 读 `parent.localStorage` 的脚本不生效。
10. `autoEdit=true` 时打开 html 仍为预览。
