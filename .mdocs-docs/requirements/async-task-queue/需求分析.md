# 异步任务队列 — 需求分析

> 一句话：构建一个通用的协作式后台任务队列框架，将图谱生成等消耗 agent 资源的操作改为异步排队执行，任务可主动让出时间片，前端通过轮询查询进度。

## 背景

当前图谱生成是同步接口，点击后前端阻塞等待，体验差。且如果同时触发多个图谱生成任务，agent 资源会被并发占用，可能触发 API 限流。

需要一个后台任务框架，统一管理所有消耗 agent 资源的操作：
- 任务排队，控制并发数（资源池）
- 任务可主动让出时间片，避免大任务独占
- 结构化进度事件，前端轮询展示
- 可扩展，未来其他 agent 任务都接入

## 目标

1. 图谱生成改为异步：点击立即返回 taskId，后台排队执行
2. 通用任务队列框架：`TaskContext` 抽象，任务与调度解耦
3. 协作式时间分片：任务可主动 `yield()` 让出资源
4. 结构化进度日志：JSON Lines，按事件类型驱动前端展示
5. 同目标去重：相同 target 重复触发不重复入队

## 非目标（本期不做）

- 抢占式调度（时钟中断式强制切换）
- 优先级队列
- 任务取消
- 断点续跑（任务失败后从断点恢复）
- SSE / WebSocket 推送（前端轮询即可）
- 队列持久化（服务重启队列清空，用户手动重触发）
- 超时自动检测与清理（心跳机制未来再做）
- 队列长度上限与拒绝策略
- 多实例部署一致性

## 验收标准

1. 点击"生成图谱"后，接口立即返回 `{ taskId, status, position }`，前端显示排队/进行中状态
2. 前端每 2-3 秒轮询一次进度，展示当前处理的文档、目录、整体进度
3. 同时触发多个图谱任务，最多同时跑 N 个（默认 2），其余排队
4. 大 domain 任务处理过程中，新触发的小任务能在大任务 yield 后插队执行
5. 同一目标（type + targetId）重复点击，不会重复入队
6. 任务完成后，隐藏文件生成，前端状态变为完成，停止轮询
7. 任务失败时，前端显示错误信息，停止轮询
8. 服务重启后，队列清空；之前在跑的任务查询显示为 stale（靠日志 mtime 判定）
