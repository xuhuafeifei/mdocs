# 冲突强制覆盖（owner）— 设计契约

> **状态**：已同意（2026-09-15，实现中）  
> 配套：[需求分析](./需求分析.md)

## 方案摘要

1. **谁**：仅 `documents.owner_visitor_id === actor` 可强制覆盖。  
2. **何时**：已判定版本冲突（线性发布 `localBaseCommitId !== head` → 409）之后，在冲突入口提供选项；不是日常发布的默认路径。  
3. **语义**：用户明确丢弃远端正文变更，以 **本地正文** 作为新 head 工作区内容。  
4. **实现策略（与你对齐）**：伪装成 **merge 发布成功**——走现有 `version.merge` 通道，但合成稿 / 最终工作区 = **本地文本**；并落 `r_local` + 双亲 merge 节点，使远端 tip 仍在 DAG 上可追溯，而不是「跳过校验的线性强盖」。

## 冲突判定（确认）

| 场景 | 条件 | 结果 |
|------|------|------|
| 线性发布 | 传了 `localBaseCommitId` 且 `≠ head_commit_id` | `409 VERSION_CONFLICT` |
| 线性发布 | `localBaseCommitId === head` | 可线性写新 commit |
| merge 发布 | `remoteCommitId !==` 当前 head | 再次 409（合并过程中 tip 又变了） |
| merge 发布 | `localBase` 不是 `remote` 的祖先（如 reset） | 现网拒绝（`assertMergeFork`） |

「强制覆盖」**不**取消上述 tip 校验：打开冲突时记下的 `remoteCommitId` 若已不是当前 head，仍应 409，避免盖掉更新的远端。

## 强制覆盖 = 何种「假 merge」

### 提议（推荐）

复用 `publishMergeDocument`：

```text
localBaseCommitId     = 草稿开编 base
remoteCommitId        = 进冲突时的远端 tip（须仍等于当前 head）
localSnapshotContent  = 本地正文（Lexical JSON 或 HTML 原文）
content（工作区）      = 同上本地正文   ← 关键：不跑三路合成，直接用本地
```

效果：

```text
localBase
 ├── … → remoteCommitId（被丢弃的远端 tip，仍作 merge 父）
 └── r_local（本地快照）
        \    /
      mergeCommit（新 head，blob = 本地正文）
```

这与 Merge UI 里「全部用我的 → 完成」在 **结果正文** 上等价，差别是：

| | Merge「全部用我的」 | 强制覆盖 |
|--|-------------------|----------|
| 入口 | 进 MergeView 决议 | 冲突弹窗直接确认 |
| 权限 | 能 edit 即可 | **仅 owner** |
| 服务端 | 现网 merge | merge + **owner 校验**（建议显式 flag，见下） |

### 为何不「线性强盖」

- 不传 / 乱改 `localBaseCommitId` 跳过乐观锁：历史与审计差，且与现网「禁止无 base 强盖」精神相反。  
- 直接把 head 指到新线性 commit、父 = 旧 tip、正文 = 本地：也行，但 DAG 上看不出「曾与某 tip 分叉后弃用远端」；你提的假 merge 更贴「冲突结局」。

## API 草案

在现有 `PUT /api/documents/:id` 的 `version.merge` 上增加可选：

```ts
version: {
  localBaseCommitId: string;
  merge: {
    remoteCommitId: string;
    localSnapshotContent?: string;
    /** owner 强制以本地正文为工作区；服务端校验 owner */
    forceLocal?: boolean;
  };
}
```

| 规则 | 行为 |
|------|------|
| `forceLocal !== true` | 行为不变（合成稿由前端决议后传入 `content`） |
| `forceLocal === true` | ① actor 必须是 owner，否则 403；② 工作区 `content` **以 `localSnapshotContent`（或与之相同的 body）为准**，忽略试图混入远端的合成；③ 其余 merge 校验同现网 |
| 非 owner 带 `forceLocal` | `403 FORBIDDEN` |

前端冲突弹窗：仅 `visitorId === ownerVisitorId` 时渲染「强制覆盖」；二次确认文案写明将丢弃他人已发布变更。

## UI 触达

| 位置 | 改动 |
|------|------|
| `ConflictModal`（或其后继） | owner：`去合并` / `强制覆盖` / `关闭`；非 owner：保持现网两按钮 |
| `MergeView` | **本期可不改**（已有全部用我的）；可选后续在完成条旁提示 owner 也可用弹窗强制覆盖 |

上传文件语法不在 merge 侧展示 → **明确非本期**。

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| 误点覆盖丢别人稿 | 二次确认；文案强调不可自动撤销（依赖 commit 历史人工找回） |
| 与「全部用我的」重复 | 产品上强调强制覆盖 = 跳过审阅的 owner 快捷通道 |
| reset / 非祖先 fork | 仍走 `assertMergeFork`；不适用时只能提示无法覆盖、需其它恢复手段 |
| 权限绕过 | 服务端强制 owner，不信前端隐藏 |
