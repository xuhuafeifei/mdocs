# 智能助手表情包（agent-memes）— 设计契约

> **状态**：已同意（2026-11-03，用户口述定稿）
> 与初版草案的差别：**放弃「按分类随机挑」**，改成「id 直取」。id 就写在正文里，天然稳定，
> 不需要 seed、不需要 pick 接口、不需要概率。

## 方案摘要

1. **占位符协议**：正文写 `[meme:<id>]`，id 是资源的唯一标识。
   - id 规则：`[A-Za-z0-9_-]{1,32}`；系统库 id 人工定死（如 `s001`），用户库 id 由服务端 roll（`u` + 8 hex），**对用户隐藏**。
   - 全角半角都认（`［meme：s001］`）；代码块 / 行内代码里不替换。
   - 前端把占位符换成 `![表情](/api/memes/image/<id>)`，由 `img` 组件接管；404 时渲染「未找到表情包资源」胶囊，不出破图。
2. **两套图库，同构两目录**
   | | 路径 | 权限 |
   |---|---|---|
   | 系统 | `<dataDir>/dsh-meme/` | 只读；只能整包 npm 同步覆盖；不可编辑/删除 |
   | 用户 | `<dataDir>/tenant/<visitorId>/dsh-meme/` | 可查看 / 上传 / 改描述 / 删除 |
   检索顺序：**系统库优先，再租户库**（同 id 时系统胜出）。
3. **索引文件 `meme.json`**（每套目录一份）
   ```json
   { "version": 1,
     "memes": [{ "id": "s001", "desc": "憨笑，开心/打招呼", "meme_name": "s001.gif" }] }
   ```
   - `desc` **必填**：Agent 靠它判断什么场景用哪张（用户上传时不填直接 400）。
   - `meme_name` 只允许 basename（挡 `../`、绝对路径）。
   - 索引损坏 / 条目非法 → 跳过该条并告警，不让表情包拖垮启动。
4. **提示词**：新段落 `memes`（label「表情包目录」），由 `assembleSystemPrompt` 的 `opts.memeCatalogSection` 注入。
   内容 = `- [meme:<id>] <desc>`（最多 60 条）+ 3 条使用规则；空库返回空串、不注入。
5. **前端解析在渲染层**（不落库）：历史消息、刷新页面、重启进程都不需要迁移；
   正文是事实，图片是呈现。

## 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/memes` | 合并列表（系统 + 租户），带 `source` |
| GET | `/api/memes/image/:id` | 原始字节；系统优先再租户；不存在 404 |
| POST | `/api/memes` | multipart 上传（`file` + `desc` 必填 + 可选 `meme_name`），返回 roll 出来的 id |
| PATCH | `/api/memes/:id` | 改 `desc`（系统库拒绝） |
| DELETE | `/api/memes/:id` | 删租户图（系统库返回「不可删除」） |
| POST | `/api/memes/system/sync` | `{ spec? }`：整包 `npm install`（默认 `mdocs-memes@latest`）→ 只取 `meme.json` + 清单图片 → 原子覆盖系统库；registry 由 `MDOCS_MEME_REGISTRY` 配（默认淘宝镜像） |

**启动旁挂**：`buildApp` 调用 `ensureSystemMemesBackground()`——系统库为空（无可读图片）时后台跑一次默认同步，**不阻塞 listen**；失败只打日志，可稍后在设置页手动同步。

## 管理界面（设置 → 表情包）

两层与后端两套图库一一对应，用分段 Tab 切换，避免把只读的全局库和可编辑的个人库混在一屏：

| 层 | 能力 | 对应接口 |
|---|---|---|
| 系统图库 | 列表 / 搜索 / 查看；整包同步（填 npm 包 spec）并回显版本、张数、大小、上次同步时间 | `GET /api/memes?scope=system`、`GET /api/memes/system/meta`、`POST /api/memes/system/sync` |
| 我的表情包 | 列表 / 搜索；上传（图片 + 必填描述）；改描述；删除（确认弹窗，提示会使历史消息缺图） | `GET /api/memes?scope=tenant`、`POST /api/memes`、`PATCH /api/memes/:id`、`DELETE /api/memes/:id` |

- 系统库在 UI 上不提供单张改/删：它是整包覆盖的产物，单张改动下次同步即失效。
- 图片一律用 `/api/memes/image/:id`（同源 img 自带 cookie），前端不拼磁盘路径。
- 同步元信息落 `<dataDir>/dsh-meme-meta.json`（不放进系统库目录，否则会被覆盖）。

## 风险与回滚

| 风险 | 说明 |
|------|------|
| 模型编造 id | 前端 404 → 「未找到表情包资源」胶囊，不破版 |
| 占位符出现在代码块 | 解析器先切代码块/行内代码，块内原样 |
| 删图后历史消息 | 历史里的 id 仍在，图片变成「未找到」——可接受（正文是事实） |
| 系统库同步是覆盖 | 旧资源直接消失；先写临时目录再整体替换，半途失败不毁旧库 |
| 提示词膨胀 | 只列 id + desc，最多 60 条（约 0.6k tokens）；空库不注入 |
| 回滚 | 去掉 `memes` 段 + `img` 拦截 + 路由即可，助手退化为纯文本 |

## 测试要点

- `store`：合并去重、系统优先、id 非法拒绝、desc 缺失拒绝、`../` 文件名拒绝、删系统图报错
- `prompt`：空库返回空串、超 60 条截断
- `meme-placeholder`：占位符替换、全角、代码块不替换、非法 id 原样（8 条单测已过）
- 手测：助手闲聊时自己发一张 → 气泡出图 → 刷新/重开仍是同一张 → 点开看大图；坏 id 显示胶囊
