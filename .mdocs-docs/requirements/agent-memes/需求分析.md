# 智能助手表情包（agent-memes）— 需求分析

> 一句话：mdocs 智能助手在闲聊时能自己发一张表情包——**模型只写 `[meme:<id>]`**，
> 前端拿 id 去后端取图渲染。图库两套：系统内置（只读、可覆盖下载）+ 用户自建（可增删改）。

## 背景

- 当前助手只会说话。斗图能明显提升对话体验（同类插件验证过这个交互有效），但那类方案依赖输入框选择器、
  图库面板与 IM 渠道，形态和 mdocs 的 Web 助手不同。
- mdocs 是多租户 Web 应用，有自己的静态资源与设置页。表情包属于「对话体验」，不是「工具能力」，
  所以不走 MCP 插件，直接内置（见 [019 决策](../../decisions/019-agent-memes-builtin-placeholder.md)）。

## 目标

1. **协议极简**：占位符里就是 id，`[meme:s001]`。不按分类随机、不需要 seed——id 写在正文里，
   刷新、重开、重启进程都还是同一张图。
2. **两套图库**：系统库（`<dataDir>/dsh-meme/`，只读，整包 npm 安装后覆盖）+
   用户库（`tenant/<vid>/dsh-meme/`，上传 / 改描述 / 删除），检索系统优先。
3. **desc 必填**：Agent 不认识图片，只认识「id + 一句话描述」；用户上传不填描述直接拒绝。
4. **模型零工具**：目录在每轮 run 开始时进系统提示词（新段落 `memes`），不占工具槽、不产生往返。
5. **前端兜底**：id 查不到就渲染「未找到表情包资源」，不出破图；代码块里的占位符原样保留。

## 非目标（本期不做）

- 设置页「表情包」管理面板（接口已就绪，UI 下期）
- 主动发图档位（关闭/看气氛/活跃/每轮）
- AI 自动学图（读用户上传图 → 视觉识别 → 自动入库）
- 图库市场 / ZIP 导入导出 / 输入框表情选择器
- 接 MCP 或第三方表情包插件

## 验收标准

| # | 场景 | 验收 |
|---|------|------|
| 1 | 闲聊收尾 | 助手输出 `别熬了 [meme:u3f2a1c9]` → 气泡内出现图片，而不是文字标记 |
| 2 | 稳定 | 刷新页面 / 关掉浏览器重开 / 重启 mdocs 进程 → **同一张** |
| 3 | 兜底 | `[meme:zzz]` → 灰色胶囊「未找到表情包资源」，不显示破图 |
| 4 | 代码块 | 三反引号代码块里写 `[meme:s001]` 原样保留，不替换 |
| 5 | 空库 | 一张图都没有时，系统提示词不出现「表情包目录」段落 |
| 6 | 上传校验 | 不带 desc 上传 → 400「desc 必填」 |
| 7 | 只读 | 删系统图 → 明确报「系统内置表情包不可删除」 |
