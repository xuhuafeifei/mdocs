# 文档移动 — 需求分析

> 一句话：在侧边栏把文档拖到另一个文件夹（或域根），服务端改 `parent_id` + `relativePath` + 磁盘路径；草稿按 `documentId` 不变。

## 背景

文档树已按 `parent_id` 构建（ADR-002），创建时路径由后端用 `fileName` + `parentId` 计算（ADR-003）。目前没有「改父目录」的 API / UI，只能删建或手工改库。

本地草稿以 `documentId` 为主键；`DraftRecord.relativePath` 已删除，路径以 `GET /api/documents/:id` 为准——移动与草稿模型兼容。

## 目标

1. 用户可在**同一域内**把一篇 Markdown 文档移到另一文件夹，或移到域根。
2. 主交互：侧边栏文档树 **拖拽**（文档 → 文件夹 / 根）。
3. 服务端原子更新：`parent_id`、`relative_path`、磁盘文件路径；树与打开中的 meta 刷新正确。
4. 有本地未发布草稿时，移动后仍可继续编辑/发布，无需改草稿内容。

## 非目标（本期不做）

- 移动**文件夹**（含子树批量改路径）
- **跨域**移动
- 改文件名 / 重命名（basename 保持不变）
- Agent tool、右键「移动到…」菜单（可作为后续增强）
- 引入 `@dnd-kit` 等重型库（本期 HTML5 DnD）

## 验收标准

- [ ] 拖文档到目标文件夹后，树中出现在正确父节点下；磁盘与 DB 路径一致。
- [ ] 拖到侧边栏空白/根区域可落到域根。
- [ ] 目标目录已有同名文件 → 409，树不变，有错误提示。
- [ ] 无权限 / 非法目标（非 dir、跨域）→ 明确错误，树不变。
- [ ] 正在打开的文档被移动后：`activeDocMeta.relativePath` / parent 更新，编辑器正文与草稿不丢。
- [ ] 有 IndexedDB 草稿的文档移动后，自动保存 / 发布仍按同一 `documentId` 工作。
