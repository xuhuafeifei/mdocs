# 文档移动 — 设计契约

> **状态**：已同意（2026-07-29）  
> 实现已落地；见 [代码索引](./代码索引.md)。

## 不变量（已确认）

**逻辑位置（`parent_id`）与物理路径（`relative_path` + 磁盘）必须始终一致。**

- 树挂载看 `parent_id`；读写/删文件、按前缀删目录、唯一约束都看 `relative_path`。
- 移动**禁止**只改 `parent_id`：必须同时重算 `relative_path` 并磁盘 rename。
- 不引入「path 当不透明存储键、搬家不改盘」的解耦模型（若将来要做，另开 ADR）。

## 权限与 UX（已确认）

- **后端**：仅文档 **owner** 可移动成功（与删除同级；中间件 `requireDocumentOwner` 或 service 内等价校验）。非 owner → `403 FORBIDDEN`。
- **前端**：可见即可拖（不按 owner 禁用拖拽）。**不乐观改树**；只有 API 成功才 `refreshTree` / 更新 meta。失败 toast，树保持原样。
- 例：A 是 owner，B 只读可见 → B 可拖，drop 后后端报错，对 B 而言拖动失败。

## 方案摘要

### 后端

```
POST /api/documents/:documentId/move
Body: { "parentId": "<folderDocumentId>" | null }
Auth: requireDocumentOwner（或等价）
```

- `parentId: null` → 移到**当前文档所在域**的根。
- 仅允许 `file_type === 'md'`（本期不搬文件夹）。
- **同域**：目标文件夹必须与源文档同 `domain_id`；禁止跨域。
- 新路径：`basename(源 relative_path)` + 目标父路径（或仅 basename 若根）；**不**再跑会改字符的 `normalizeFileName`。
- **一次移动必须完成**：`parent_id` + `relative_path` + 磁盘 rename + `updated_at`。
- 目标路径已存在 → `DOC_EXISTS` 409。
- 非法父节点（不存在 / 非 dir）→ 400。
- 幂等：`parentId` 已等于当前 `parent_id` → 200，不碰磁盘。
- FTS：路径变更后更新该文档索引（若需要）。

顺序：校验（含 owner）→ 磁盘 rename → DB update；磁盘成功 DB 失败时尝试 rename 回滚。

### 前端

`DocumentTree` HTML5 DnD：

| 行为 | 说明 |
|------|------|
- 拖到**文件夹行** → 进入该文件夹
- 拖到**某篇文章** → 进入该文所在目录（成为兄弟）
- 拖到侧栏**空白** → 域根

### 草稿

- 不改 IndexedDB；移动后同一 `documentId`，只刷新 meta。

## 风险与回滚

| 风险 | 缓解 |
|------|------|
| 磁盘已改、DB 失败 | rename 回滚；日志 |
| 非 owner 误拖 | 预期行为；清晰 403 文案 |
| 拖拽误触打开 | 短距离仍走 click |

回滚：下线 route + 还原 Tree DnD；无 DB 迁移。

## 测试要点

- 根 ↔ 文件夹；同名 409；跨域 / 非 dir
- **非 owner 403，树不变**
- owner 成功后树与 `relativePath` 一致
- 打开中 + 有草稿：meta 更新，草稿仍可发布
- 幂等同 parent
