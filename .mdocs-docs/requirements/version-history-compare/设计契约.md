## 方案摘要

同一个 `.mdocs-version-history-dialog` 弹框上加两个正交开关：**全屏** 与 **对比模式**。对比模式下右侧由「单栏预览」变成「左右两栏只读 Lobe」，两栏滚动按**百分比**联动（可关）。**没有任何 diff 计算**：两栏各自渲染原始 blob，互不分析。

```text
single 模式                        compare 模式
┌──────────────────────────┐      ┌───────────────────────────────────────┐
│ head: 标题/说明/[icons]  │      │ head: 标题/说明/[icons]               │
├────────┬─────────────────┤      ├──────┬───────────────┬───────────────┤
│ 列表   │ 预览（选中版本）│      │ 列表 │ [选版本▾]     │ [选版本▾]     │
│ 280px  │                 │      │ 260px│ Lobe A        │ Lobe B        │
├────────┴─────────────────┤      ├──────┴───────┬───────┴───────────────┤
│ foot: [恢复此版本]       │      │ [联动滚动]   │ [恢复此版本]          │
└──────────────────────────┘      └──────────────┴───────────────────────┘
```

| 项 | 约定 |
|----|------|
| 入口 | 文档信息 → 版本历史（不变）；弹框内新增图标按钮：并排对比、全屏 |
| 左栏内容 | 左侧下拉选择的 commit（默认=列表选中） |
| 右栏内容 | 右侧下拉选择的 commit（默认=head）；**不含未发布草稿** |
| 文档类型 | 仅 `md` 开放对比；`html` / `sheet` 保留单栏 |
| 后端 | 零改动，只用现有 commits 两条 GET |
| 持久化 | `localStorage["mdocs.versionCompare.syncScroll"]`（默认 `"1"`）；全屏/对比态不持久化 |
| 滚动 | 比例映射；默认联动；开关即时生效 |

## 状态机

```ts
type PanelMode = "single" | "compare";
type CompareSide = "left" | "right";

// 组件内新增 state
mode: PanelMode                     // 默认 single
fullscreen: boolean                 // 默认 false
syncScroll: boolean                 // 初值读 localStorage，默认 true
listCollapsed: boolean              // 对比态左侧列表折叠（默认 false）
leftId: string | null               // 左栏版本（允许空）
rightId: string | null              // 右栏版本（允许空）
pickSide: CompareSide               // 下一次点列表放进哪一侧（左→右交替）
rightDetail: DocumentCommitDetail | null  // 右栏数据
detailCache: Map<string, DocumentCommitDetail>  // commitId → detail，左右两栏共用
```

迁移规则：

| 事件 | 结果 |
|------|------|
| 点「并排对比」（`md` 且可见版本 ≥ 2） | `mode = "compare"`；`leftId = rightId = null`；`pickSide = "left"` |
| 点未选的列表行 | 放进 `pickSide` 一侧，`pickSide` 取反（第 1 次左、第 2 次右…） |
| 点已选的列表行 | 摘掉该侧（可变成空），`pickSide` = 该侧 |
| 两侧都满时点第三行 | 放进 `pickSide`（此时为左）→ 替换左栏 |
| 改任一栏下拉 | 只改该侧；选「未选择」= 置空；徽标同步 |
| 单栏模式点列表行 | 老行为：只切换预览（`selectedId`） |
| 退出对比 | `mode = "single"`；若左栏有版本则把它设为列表选中，保持预览连续 |
| `items` 刷新（恢复/同步） | `detailCache` 保留（blob 不可变）；被隐藏/删除的 id 从两侧摘掉 |
| 恢复成功 | `mode = "single"`，`fullscreen = false`，`load()` 重拉列表（沿用现有 `onRestored`） |
| Esc | 若 `fullscreen` → 只退全屏；否则关闭弹框（`onClose`）。对比态由图标按钮退出 |
| 点 backdrop | 沿用现有：关闭整个弹框 |

## 数据获取

```ts
// 复用现有
listDocumentCommitsApi(documentId) -> DocumentCommitSummary[]  // 含 isHead / source / message
getDocumentCommitApi(documentId, commitId) -> DocumentCommitDetail

// 左栏：leftSourceId = compare ? leftId : selectedId 的 effect
// 右栏：rightId 的 effect（仅 compare 态）

```

- 两栏请求互不影响：任一失败只在该栏显示错误文案，另一栏照常。
- `detailCache` 存放 `{content, contentHash, createdAt, ...}`；切换历史版本命中缓存直接渲染，不闪 loading。
- 对比态**不**预取其它版本。

## 滚动联动（核心，纯函数可测）

两栏滚动容器都用 `.mdocs-version-preview-editor`（现有 `overflow: auto`）。比例按「可滚动距离」算，而不是 `scrollHeight` 直接比：

```ts
// src/web/app/version-compare-scroll.ts
export function scrollRatio(el: HTMLElement): number {
  const max = el.scrollHeight - el.clientHeight;
  if (max <= 0) return 0;
  return Math.min(1, Math.max(0, el.scrollTop / max));
}

export function computeSyncedScrollTop(source: HTMLElement, target: HTMLElement): number {
  const max = target.scrollHeight - target.clientHeight;
  if (max <= 0) return 0;               // 目标不可滚 → 停在 0
  return Math.round(scrollRatio(source) * max);
}
```

绑定：

```ts
/**
 * @returns 解绑函数
 */
export function bindProportionalScroll(a: HTMLElement, b: HTMLElement): () => void;
```

- 用 `scroll` 事件（`passive: true`）→ 一帧合并（`requestAnimationFrame`）→ 写对侧 `scrollTop`。
- 回环抑制：写对侧前置 `syncing[target] = true`，在其 `scroll` 事件里见到标记则丢弃并清除（用 `queueMicrotask`/下一帧清）。
- 用户操作判定：`wheel` / `pointerdown` / `keydown` 命中哪一栏，就把该栏记为 `source`；`scroll` 只从 `source` 推对侧，避免两栏互相拽。
- 内容高度异步（Lobe 渲染完才稳定）：绑定后再 `requestAnimationFrame` 触发一次对齐；可选 `ResizeObserver` 监听 `scrollHeight` 变化后重新对齐（不做也能用）。
- 关闭联动 → 直接 `unbind()`，两栏各滚各的；重新开启 → 立即按当前两栏中「有用户操作痕迹」的一栏对齐一次。

语义说明（写进 UI tooltip）：「按百分比联动」：内容长度不同的两篇，短的一栏到底后长的一栏还会继续走——这是预期，不是 bug。

## 风险与回滚

| 风险 | 处理 |
|------|------|
| 两个 Lobe 只读实例内存/渲染翻倍 | 只在 compare 态挂载第二实例；单栏不受影响；大文档仍走同一插件集 |
| 两栏高度差大导致「短的一栏到底后长栏继续」被误判为 bug | UI tooltip + 文案说明；这是百分比联动的定义 |
| `scrollHeight` 渲染后变化导致初次不对齐 | 首帧 rAF 再对齐一次；切换版本后重绑 |
| 事件回环抖动 | `source` 判定 + 一帧合并 + 写回标记 |
| 右栏陈旧（他端发布 / 恢复后） | 打开面板与恢复成功都重拉列表；id 失效则回落 head |
| 全屏 + 手机浏览器 `100dvh` 兼容 | 用 `100dvh`，回退 `100vh` |
| 回滚 | 删 `is-compare` / `is-fullscreen` 分支与新增文件即可，单栏路径保持原样 |

## 测试要点

单测（`version-compare-scroll.test.ts`）：

- 源在 0 / 50% / 100% → 目标 `computeSyncedScrollTop` 分别为 0 / 一半 / 满。
- 源不可滚（`scrollHeight <= clientHeight`）→ 目标 0。
- 目标不可滚 → 返回 0，不抛错。
- 比例越界（人为 `scrollTop > max`）→ clamp 到 1。

手工验收：见 [`需求分析.md`](./需求分析.md#验收标准)（两栏渲染、两栏各自选版本、联动开关、全屏、版本数 ≥2 才可对比、html/sheet 无入口、窄屏无入口、恢复后退出对比、无 diff 请求）。
