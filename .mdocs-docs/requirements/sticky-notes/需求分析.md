# 便签 — 需求分析

> **状态**：讨论中（2026-11-19）。只记功能判断，不写设计契约，不改业务代码。产品文档与技术方案由人后写。
>
> 一句话：做一个没有工作空间、没有目录的私人速记。对人是黄色便签；底下仍是带草稿、发布和 git 的 Markdown。

## 背景

现在记一笔要先选工作空间、再选目录、再新建文章。灵光一闪用这套流程太重。便签只服务「先记下来」，把和记录无关的选择从入口拿掉。

## 已对齐的产品判断

1. **入口只有记。** 打开就能写，不选工作空间，不选目录，不起文件名。
2. **没有层级。** 便签之间不平级套文件夹，也不做标签。按记录时间排成一列。
3. **没有工作空间这个词。** 使用时不出现域、目录、权限、成员。
4. **只有自己能看。** 不提供公开、邀请、成员。要给别人，先导出成普通 Markdown 文章；导出是复制一份进某个工作空间，原便签仍私人。Excel / HTML / job 的 AI 导出以后再做。
5. **编辑器用 Lobe。** 内容是 Markdown。本期不做表格、HTML、job 这几种文件。
6. **外观是便签纸。** 黄色纸感，一条一条，而不是现在的文档树加正文。
7. **草稿、远端发布、git 都留着。** 能力还在，记录路径上不摆提交说明、分支、对比这些操作。
8. **底层可以有一个跟人绑定的便签域。** 存储仍然按域落盘。这个域只给机器用，界面不把它叫做工作空间。个人工作空间（`domain_id === visitor_id`，仍有目录）是另一件事，便签不塞进那棵树。

## 讨论里先记下的约束

- 域的键用访客 id，不用「便签 + 昵称」。昵称会改，也会重名。展示名不进产品文案。
- 隐藏域会漏进工作空间切换、我的文章、搜索、助手列域、目录树，除非有明确标记把它们排除。标记要落在数据上，不能靠名字前缀判断。
- 「普通文本」在这里指：只有 Markdown 便签，没有别的文件类型，也没有建目录、分享、选域。Lobe 仍按 Markdown 编辑。
- 排序按**记下的时间**。之后修改不把旧便签顶到最前。
- 重构（目录搬迁、Nest 换路由）期间不实现本需求。

## 非目标（本期不做）

- 目录、标签、置顶
- 分享、邀请、公开读
- 导出成 Excel / HTML / job（含 AI 导出）
- 把便签放进个人工作空间的目录树
- 在捕获路径上露出提交说明、分支、版本对比

## 留给产品文档拍板

- 新建是空白一条，标题用首行还是用时间
- 远端是后台自动发布，还是保留一次「保存」
- 便签列表是独立页面，还是主界面里的一种模式
- 删除走不走现有回收站
- 便签内搜索要不要做
- 手机上是不是主入口
