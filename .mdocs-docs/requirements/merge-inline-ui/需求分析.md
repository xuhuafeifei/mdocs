# merge-inline-ui — 需求分析

> 一句话：冲突 Merge 改成与帮写同构的单栏 inline 审阅；段级接收/拒绝，整体「全部用我的 / 全部用别人的」；有未决议段不可手改。

## 背景

现网 Merge 为左 local / 中结果 / 右 remote，心智抽象；帮写已是单栏红绿 + 接受/拒绝。产品上两者都是「按段决议」，UI 应统一。

## 目标

1. 默认单栏 inline：红 = 我的（local），绿 = 别人的（remote）。
2. 每段：**接收**（= remote）/ **拒绝**（= local）。
3. 工具条：**全部用我的** / **全部用别人的**。
4. 有未决议段 → 只读审阅；全部决议完 → 整篇可编辑 → 再完成 merge 发布。
5. 三路 diff 算法与 merge 发布 API **不变**。

## 非目标

- 左右对照主布局
- 段级「两边都要」「手改」按钮
- 与帮写共用同一数据模型 / 同一页面组件（可视觉同构，逻辑分流）
- 上手引导

## 验收标准

- [ ] 打开冲突 Merge：无左右栏，单栏 inline。
- [ ] 接收 → 该段用 remote；拒绝 → 该段用 local。
- [ ] 全部用我的 / 全部用别人的一次清完。
- [ ] 未全部决议时不可改正文、不可点完成。
- [ ] 全部决议后可手改，完成仍走 merge 发布。
