# mdocs-cli 知识图谱 — 需求分析

> **状态**：已同意（2026-09-11）— 两阶段均做；域图显式 `--domain`，无启发式。  
> 一句话：给外部 Agent / 本地 CLI 补上「读 + 触发」知识图谱能力，与 Web 同源 API；门禁服从 graph-access。

## 背景

- mdocs 服务端已有 `/api/graph/*`（读缓存、异步 analyze、任务查询）。
- `mdocs-cli`（`~/.mdocs-cli`）仍停在文档 CRUD + 搜索，Agent 无法用统一 JSON 协议拿图谱。
- 用户常从 Web URL / 隐藏文件 id 进入；CLI 需本地纠偏，而不是要求人手改 id。

## 目标

1. CLI 能按 **文章 id / 目录 id / domainId**（及常见 URL、特殊后缀 id）读取图谱缓存。  
2. ID/URL **在 CLI 侧归一化**后再打 API；域图仅 `--domain`，无启发式。  
3. Phase 2：触发 analyze、查询 task，供「经 mdocs 建图」工作流。  
4. 权限与错误与 [`knowledge-graph/设计契约-graph-access.md`](../knowledge-graph/设计契约-graph-access.md) 一致：CLI Token 继承访客身份，403 原样透出。

## 非目标（本期）

- 外部 Agent 直写目录/域 `___graph___`（共享缓存中毒/泄密风险，已否决）。  
- 开放 `viaDocumentInvites` 用户的图谱能力。  
- 文章级 `put-article` 隐藏文件写入（可另开契约；与「仅 full 可碰图」叠加后再做）。  
- 把 `/api/agent/*` SSE 塞进 CLI。

## 验收（人审）

1. `graph get <文章或目录 id>` / URL / `.folder-desc` / `.graph-file` 能落到正确 GET。  
2. `graph get --domain <domainId>` 走域级 GET。  
3. private/restricted 下非 `full` Token 得到可识别失败（`ok:false` + 服务端错误信息）。  
4. `graph analyze` 入队返回 `taskId`，`graph task` 能查到状态。
