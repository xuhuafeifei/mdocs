# mdocs-cli 知识图谱 — 设计契约

> **状态**：已同意（2026-09-11）  
> 依据：[`需求分析.md`](./需求分析.md)  
> 门禁母约：[`../knowledge-graph/设计契约-graph-access.md`](../knowledge-graph/设计契约-graph-access.md)（已同意）  
> 实现仓：`https://github.com/xuhuafeifei/mdocs-cli.git`（`~/.mdocs-cli/mdocs.mjs`）；服务端 API 已存在，**本期默认不改 mdocs 路由**（若 graph-access 门禁尚未落地，读/生成仍可能过宽——门禁以服务端契约为准另轨落地）。

## 已定决策

1. **两阶段都做**：Phase 1（`graph get` + 纠偏）+ Phase 2（`graph analyze` / `graph task`）。  
2. **域图必须显式 `--domain`**：不做「剥完后缀像 domainId 就改走 domain 路由」等启发式。  
3. **本期不做** put-article / 外部直写共享图谱缓存。

## 方案摘要

CLI 薄封装现有 HTTP：

| CLI | HTTP |
|-----|------|
| `graph get <idOrUrl>` | `GET /api/graph/:id`（文章或目录资源 id） |
| `graph get --domain <domainId>` | `GET /api/graph/domain/:domainId` |
| `graph analyze <idOrUrl>` | `POST /api/graph/:id/analyze` |
| `graph analyze --domain <domainId>` | `POST /api/graph/domain/:domainId/analyze` |
| `graph task <taskId>` | `GET /api/graph/tasks/:taskId` |

认证：既有 `x-cli-token`；输出仍 `{"ok":true,"data":...}` / `{"ok":false,...}`。

## Phase 1 — get + 纠偏

### A. 命令

```bash
node ~/.mdocs-cli/mdocs.mjs graph get <idOrUrl>
node ~/.mdocs-cli/mdocs.mjs graph get --domain <domainId>
```

- `<idOrUrl>`：裸 UUID、带后缀特殊 id、或 `http(s)://host/...` / `/#/doc/...` / `/doc/...`  
- `--domain` 与位置参数互斥；同时出现则报错  
- 成功 `data` 即为服务端返回的 `{ nodes, edges }` 或 `null`（无缓存）

### B. CLI 本地 ID / URL 归一化（纠偏）

在发请求前解析出 **资源 id**（域图只用 `--domain`，不在此启发式推断）：

| 输入 | 行为 |
|------|------|
| 普通文档 / 目录 UUID | 原样 → `GET /graph/{id}` |
| `{id}.folder-desc` | 剥后缀 → `{id}`（目录）→ `GET /graph/{id}` |
| `{id}.graph-file` | 剥后缀 → `{id}` → `GET /graph/{id}` |
| `{id}.graph-dir` | 剥后缀 → `{id}`（父目录）→ `GET /graph/{id}` |
| URL 含 `/doc/<x>` 或 `#/doc/<x>` | 取出 `<x>` 再走后缀规则 |
| 仅 `--domain <domainId>` | `GET /graph/domain/{domainId}` |

说明：

- **目录描述 URL** → 纠成目录图谱。  
- **图谱隐藏文件 URL** → 剥成资源 id 再读正式 graph API（优先），不默认 `get` 原始 JSON 文件（除非后续加 `graph get --raw-file`）。  
- 域级隐藏文件 id 形态为 `{domainId}.graph-file`：剥后缀后仍走 `/graph/:id`，**绝不**自动改走 `/graph/domain/:id`。域图一律：`graph get --domain <domainId>`。

### C. Phase 1 不做

- analyze / task（属 Phase 2）  
- put-article / 写隐藏文件  
- 服务端改契约以外的新 API

## Phase 2 — analyze / task

```bash
graph analyze <idOrUrl>           # 入队；输出 taskId / position
graph analyze --domain <domainId>
graph task <taskId>               # 轮询状态；不强制内置 spin-wait（可由 Agent 循环调）
```

- URL / 特殊 id 纠偏与 Phase 1 相同；域图同样 **必须** `--domain`，无启发式。  
- **不**在 CLI 默认加 `force:true`（避免重抽已干净文章）；若加 `--force` 须文档标明会忽略文章缓存。  
- 403 / AI 未配置等错误透出 `code`（若有）与 `error` 文案。

## 与外部 Agent「只刷文章、mdocs 聚合」

- **本期 CLI 不实现 put-article**。  
- 建图推荐路径：有 `full` 身份的 Token → `graph analyze`（目录或域）→ `graph task` → `graph get`。  
- 文章级外部回写若要做：另约；且须遵守 graph-access（private/restricted 仅 full）。

## 变更触达

| 仓 / 文件 | 改动 |
|-----------|------|
| `mdocs-cli` / `mdocs.mjs` | 子命令 `graph`、归一化函数、help |
| `mdocs-cli` / README + 分发的 `SKILL.md` | 命令表 |

| mdocs 服务端 | 本期 **无必须改动**；graph-access 门禁按母约另轨 |

## 风险

- 门禁未落地前，CLI 能读到服务端仍过宽的图 → 以尽快落地 graph-access 为准。  
- `{domainId}.graph-file` 剥后缀误走 `/graph/:id` 可能 404/空 → 文档/help 强调域图用 `--domain`。

## 验收对照

同需求分析四条；另：纠偏单测或脚本覆盖 `.folder-desc` / `.graph-file` / hash doc URL；域图路径仅经 `--domain`。
