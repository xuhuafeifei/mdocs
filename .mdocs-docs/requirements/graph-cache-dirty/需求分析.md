# 图谱缓存 dirty — 需求分析

> 一句话：正文 CRUD 与图谱构建用 `meta.dirty` + 异步生命周期解耦；不引入 event bus；mark 只吃 `parentId`。

## 背景

知识图谱已能构建与展示，但：

- 文章级有 commit 缓存，目录级每次仍重跑归纳
- 删/挪正文不清理 / 不失效图谱隐藏文件
- 目录结构 ≠ 知识结构，不能沿知识边打补丁

需要一套**缓存一致性**协议，且尽量不污染 `document.service` 主链路。

## 目标

1. 文章/目录落盘图带 `meta.dirty`；构建只看 dirty 决定是否重算
2. 发布后异步用正文变化率决定是否置文章 dirty，并蔓延祖先目录图
3. 删/挪后异步：用事先抠出的 `parentId` mark，再清文章级缓存
4. 主链路不写隐藏文件细节；无 event bus，用 `setImmediate` / fire-and-forget 调 graph lifecycle

## 非目标

- `sourceHash` / 图内容 hash 第二道闸
- 完整领域 event bus
- 移动时搬迁 `__graph__` 文件
- 沿知识边精确增删 concept

## 依据

- 母需求：[knowledge-graph](../knowledge-graph/设计契约.md)
- 本夹设计契约：`设计契约.md`

## 验收

- 小改发布不 dirty；大改文章 dirty + 祖先目录 dirty
- 删文后祖先图 dirty，文章级缓存消失；主链路删除仍同步返回
- 目录 `!dirty` 构建跳过 AI；`dirty` 必重算并清 dirty
- lifecycle 失败不影响正文 CRUD 成功
