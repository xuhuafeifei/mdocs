# document-version-restore — 需求分析

> 一句话：文章可浏览历史发布版本，并选中某一版「恢复」——把该版正文作为**新的一次发布**写回（新 commit，parent = 当前 head）。

## 背景

每次 publish 已写入 `document_commits` + blob。用户无法在产品里挑历史版。回收站只救删前 head，不是版本选择。

已定语义（2026-10-21）：**不拨 head 指针**；旧内容再 commit 一次，图继续向前。

## 目标

1. 列出某文档的历史 commit（时间、作者、是否当前 head）
2. 可预览某 commit 正文
3. 有编辑权者可「恢复到此版本」→ 工作区 = 该版内容 + 新 commit（parent=原 head）+ 更新 `head_commit_id` / `content_hash`
4. 入口在文章侧（文档信息菜单「版本历史」）

## 非目标

- 不拨指针 / 不删中间 commit（不做 reset）
- 不做可视化 commit DAG / 三路 diff 选版（预览全文即可）
- 不改回收站语义
- 不恢复邀请/评论
- CLI / Agent tool 本期不做

## 验收

- 发两版 → 历史列表 ≥2；当前 head 有标记
- 预览旧版内容与当时发布一致
- 恢复后：正文变旧版；多一条新 commit；再列历史可见该恢复点
- 无编辑权 → 可看历史（若可读）或不可恢复；恢复接口 403
- 选当前 head 恢复 → 幂等或明确提示无需操作

## 依据

- schema：`document_commits` / `commit_parents` / `head_commit_id`
- `writeCommitBlob` / `readCommitBlob`；`updateDocument` 发布路径
