# 顶栏草稿状态 — 需求分析

> 一句话：顶栏只看本地有没有未发布草稿。没有就是「已发布」，有就是「编辑中」。现在这个字会晚一拍。

## 背景

顶栏圆点文案在 `DocChrome`：`draftExists` 为真显示「编辑中...」，否则「已发布」。这个布尔来自 `useAutoSave` 自己的 React state，初始是 `false`，只在 `documentId` 变化时异步 `getDraft`，以及防抖保存成功后才改。

帮写回写、发布删草稿、合并成功，都是在 Hook 外面改 IndexedDB。顶栏不会跟着变，要等下次打开这篇，或者 Hook 自己再存一次。打开已有草稿的文档时，还会先闪一下「已发布」。

## 目标

- 当前文档在 IndexedDB 里没有未发布草稿 → 顶栏「已发布」。
- 有未发布草稿 → 顶栏「编辑中...」。
- 草稿写入或删除的同一轮就改字，不依赖重新打开文档。

## 非目标（本期不做）

- 不改自动保存的 1 秒防抖。没落盘之前仍算没有草稿，显示「已发布」。
- 不改发布按钮、不自动发布。
- 不改 `draft.published === true` 的旧记录：打开文档时本来就不当成未发布草稿。

## 验收标准

- 打开有草稿的文档，顶栏一开始就是「编辑中」，不先闪「已发布」。
- 帮写确认回写后，不离开这篇，顶栏变为「编辑中」。
- 发布成功草稿被删后，顶栏立刻变为「已发布」。
- 没有草稿时编辑，防抖落盘成功后才变为「编辑中」。

## 依据

- 代码：`src/web/app/DocChrome.tsx` 保存指示（`draftExists ? unsaved : published`）；`src/web/app/hooks/useAutoSave.ts` 的 `draftExists` 与 `getDraft` effect；`src/web/app/App.tsx` `loadEditorFromDraft` / `finalizeAfterPublish` / `completeAiWrite`
- 文案：`src/web/i18n/locales/zh.ts` `unsaved` = 「编辑中...」，`published` = 「已发布」
- 待确认：无
