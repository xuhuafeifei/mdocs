# Agent 重命名文档文件名 — 设计契约

> **状态**：已同意（2026-10-10）。

## 方案摘要

| 项 | 约定 |
|----|------|
| 工具名 | `rename_document` |
| 入参 | `documentId`（必填）、`fileName`（必填，可无路径；规范化后为 basename） |
| 行为 | 同域、同 `parent_id`，只改 `relative_path` 最后一段 + 磁盘文件；`displayName` **本期不改** |
| 权限 | 仅 `owner_visitor_id === actor`（与 `move_document` 相同） |
| 类型 | `getPolicy(...).movable === true`；文件夹拒绝 |
| 冲突 | 同域新路径已有其他文档 → `DOC_EXISTS` |
| 幂等 | 规范化后 basename 与当前相同 → 直接返回当前详情，不写盘 |

服务层新增 `renameDocument`（与 `moveDocument` 并列），工具薄封装。磁盘失败回滚策略对齐 move：先磁盘 rename，再 DB；DB 失败则尝试 rename 回去。

## 工具契约（给模型）

- **label**：重命名文件
- **description**：在同一文件夹下改文档文件名（磁盘路径最后一段）。不移动父目录；换文件夹用 `move_document`。仅文档创建者。Markdown / HTML / 表格可改，文件夹不可。
- **返回**：`documentId`、`domainId`、`parentId`、`relativePath`、`displayName`、`fileType`

## 风险与回滚

| 风险 | 处理 |
|------|------|
| 磁盘已改 DB 失败 | 同 move：尝试 rename 回旧路径 |
| 模型误用改展示名 | 描述写清；本期不改 `displayName` |
| 去掉扩展名导致类型错 | `normalizeFileName` 按当前 `file_type` 补后缀；禁止靠改扩展名换类型 |

## 测试要点

- 根下 `a.md` → `b.md`，树与 `get_document.relativePath` 一致。
- 文件夹内 `dir/a.md` → `dir/c.md`，`parentId` 不变。
- 目标已存在 → 失败、原路径不变。
- 非创建者 → 403 类错误。
- `fileName` 带路径段时只取最后一段（与创建一致）。
