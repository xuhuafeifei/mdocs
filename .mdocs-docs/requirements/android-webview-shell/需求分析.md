# android-webview-shell — 需求分析

> 一句话：提供可侧载的 Android APK，用户填自己的 mdocs 服务器地址后，用 WebView 打开该站，不必在浏览器里敲网址。  
> 状态：**已同意**（2026-09-12）

## 背景

mdocs 是自托管 Web。手机每次用都要打开浏览器、输入地址。团队规模小，不需要应用商店；只要一个 APK，点图标进自己的实例。

现有前端已有窄屏 reader；访客身份在页面的 localStorage。壳不该重做编辑器或登录。

## 目标

1. 产出可安装的 **Android APK**（侧载，不上架）
2. 首次打开：一个输入框填服务器 URL，确认后进入该站
3. 之后打开：直接加载已保存地址
4. 可更换服务器地址
5. 页面能力与手机 Chrome 打开同一 URL 相当（JS、localStorage、草稿、上传）

## 非目标（本期不做）

- iOS / 应用商店 / 推送 / 桌面图标商店分发
- 把前端打进 APK，或改 `/api` 走壳内绝对地址（避免 CORS / 双份前端）
- 原生重写编辑器、树、身份
- 多账号切换、扫码配网、自动发现局域网实例
- 后台保活、离线包完整站点

## 验收标准

1. 未保存地址时只看到填写页；非法 URL 有提示、不跳转
2. 保存后重启 App 仍打开同一地址，不必再填
3. 填写页可改地址后加载新站
4. 能完成访客注册/恢复、打开文档、编辑并发布（取决于该服务器本身）
5. 系统返回键：有历史则 WebView 后退，否则退出

## 依据

- 讨论结论：不上架、用户自填地址、先 Android
- 前端 API 相对路径 `/api`，必须 **整页加载用户填写的源站**（与浏览器同源）
- map：`src/web/services/client.ts`（token 在 localStorage）
