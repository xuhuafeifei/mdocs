# Agent 上下文 LLM 压缩 — 设计契约

> **状态**：已实现（2026-10-21）  
> 含：自动（≥85%）+ **主动压缩** API / UI。

## 方案摘要

| 项 | 约定 |
|----|------|
| 阈值 | 估算 `percent >= 85` 触发（用现有 `estimateTokens` / `getAgentContextUsageForApi` 同算法） |
| 时机 | **本轮 chat 进入模型前**：先 compact，再 hydrate + run |
| 主动 | `POST /api/agent/session/compact`（当前 lastOpened session）；不要求已到 85%；无可折内容 → 200 `{ compacted: false, reason: "nothing_to_compact" }` |
| 模型 | 访客当前默认 Agent 配置（与正常对话同一套 `createAgentModel`） |
| 保留 | 最近 **K=6** 条「可见轮」（user/assistant 对；中间夹着的 tool 行跟着所属轮一起保留）。更早全部进摘要 |
| 落盘形态 | jsonl 变为：`[role=system_summary 或 user 伪装的压缩块]` + 保留的尾部原文；旧文件先 rename 备份 |
| UI | SSE `context_compacting` → 面板显示「正在压缩上下文…」；`context_compacted` 后清除并继续正常流；面板提供「压缩上下文」按钮走主动 API |
| 锁 | 该 `sessionId` 进入 `compacting`；持有直至写回结束；期间其它写/run **409** |

## 1. 触发与流程

### 自动（chat 前）

```text
POST /chat (或等价 run)
  → 解析 sessionId
  → 若 session 已 compacting → 409 SESSION_COMPACTING
  → 估算 usage（system+tools+该 session 消息）
  → if percent < 85: 正常 run
  → else:
       设 compacting + 发 context_compacting
       持锁做 LLM 摘要 + 改写 jsonl
       发 context_compacted { percentAfter }
       清 compacting
       再正常 run（用压缩后历史）
```

### 主动

```text
POST /api/agent/session/compact
  body?: { sessionId?: string }  // 默认 lastOpened
  → 同锁 + 同 LLM 写回
  → 无 SSE 流时：响应 JSON { compacted, percent, used, limit, reason? }
  → 若前端在开着该 session 的 chat SSE：可选再推 context_*（能推则推；主动 API 以 JSON 为准）
```

UI：助手面板用量环旁或菜单「压缩上下文」→ 调主动 API；进行中按钮 loading + 与自动相同的「正在压缩…」遮罩。

coding session 同逻辑（独立目录；compact API 带 `kind=coding` 或沿用现有 session 路由约定）。

## 2. 摘要内容（给模型）

输入：将被折叠的 messages（user / assistant / tool），按现有 hydrate 可读文本拼接，设硬顶（如 200k 字符）超出则从最旧再截断并注明 truncated。

System/user 指令大意：

> 将以下对话历史压缩成简洁中文摘要，保留：用户目标、已确认结论、重要 documentId/路径、未完成待办、关键工具结论。不要复述大段正文；不要编造。输出纯文本摘要。

输出：单段文本，建议 ≤ 4k 字符（超则再截断尾）。

写入 jsonl 一条，例如：

```json
{
  "role": "user",
  "content": "【系统·上下文压缩】以下为更早对话的摘要，详情若需要请重新调用工具读取。\n\n<summary>",
  "ts": "...",
  "kind": "context_compact_summary"
}
```

（`kind` 供 hydrate/UI 识别；对人可见时间线可渲染为 muted「上下文已压缩」+ 可展开摘要。）

其后 append 原保留的尾部行（顺序不变）。

## 3. 锁定（你要的 session 锁）

已有 `withSessionMetaLock(session.json)` 管 meta 丢更新，**不够**：LLM 耗时长，不能整段占死所有 session 的 meta 队列。

本期加 **按 sessionId 的压缩锁**：

| 机制 | 行为 |
|------|------|
| `session.json` 内该 entry：`compacting: true` + `compactingAt` | 或旁路 `{sessionId}.compacting` 锁文件；**定稿：锁文件** `{sessionId}.jsonl.compact.lock` + meta 可选标记便于 API 查询 |
| 获取 | compact 开始时 `wx` 创建锁文件；结束 unlink |
| 互斥 | `appendUser` / `appendAssistant` / `appendToolExchange` / 新 run 针对该 session：若锁存在 → **抛 / 409 `SESSION_COMPACTING`** |
| meta | touch/list/open **其它** session 不挡；open **本** session 可读消息但标注 compacting |

并发第二路 chat：立刻 409，前端提示「正在压缩，请稍后再试」（不静默排队，避免超时叠请求）。

改写 jsonl：

1. 读全量行  
2. 算保留尾 + 待摘要前缀  
3. 调 LLM（**此时仍持有 compact lock**，不持全 visitor meta 长锁）  
4. 写 `{id}.jsonl.tmp` → `rename` 成 `{id}.jsonl`；同时把旧文件 `rename` 为 `{id}.jsonl.bak-compact-<ts}`（只留最近 1～2 个备份）  
5. `touchLastOpened`（短持 meta 锁）

## 4. SSE / 前端

新增事件（`stream-events.ts` + `endpoints`）：

```ts
| { type: "context_compacting" }
| { type: "context_compacted"; percent: number; used: number; limit: number }
```

`AgentChatPanel`：收到 `context_compacting` 显示顶栏/遮罩「正在压缩上下文…」（禁用发送）；`context_compacted` 或 `error` 后恢复。若 409，toast 同文案。

用量环：压缩后用 `context_compacted` 的数字更新。

## 5. 边界

| 情况 | 处理 |
|------|------|
| 消息很少但 percent≥85（工具 schema 巨大） | 若可折叠消息 < 2 轮 → **跳过压缩**，照常跑（避免空转烧钱） |
| LLM 失败 / 超时 | 发 error 或 compact 失败事件；不解绑锁前恢复；**不改** jsonl；本轮 chat 可 503 或带警告继续（**定稿：压缩失败则本轮仍尝试原历史跑**，并打日志） |
| 摘要后仍 ≥85% | 本轮照跑；不在同轮递归压缩（防死循环）；下轮再触发时可把 K 降到 4（可选，一期固定 K=6） |

## 风险

| 风险 | 处理 |
|------|------|
| 摘要丢失细节 | 文案要求重读；documentId 尽量保留 |
| 压缩占模型额度 | 仅 ≥85% 触发；可折叠不足则跳过 |
| 长锁拖死 | 只用 session 级 compact 锁，不长时间占 meta 全局锁 |
| bak 占盘 | 每 session 最多保留 2 个 bak |

## 测试要点

- percent 84 → 不调 LLM；85 → 调（mock）  
- compact 中 append → 失败  
- 成功后 jsonl 含 summary kind + 尾部保留  
- 失败保留原 jsonl
