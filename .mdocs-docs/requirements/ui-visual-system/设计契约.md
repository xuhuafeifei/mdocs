# UI 视觉体系 — 设计契约

> **状态**：已同意（2026-09-13，**已落地**）
> 未经「已同意」不得开始写代码。

## 方案摘要

四条规则，全部落在 `App.css` / `DocChrome.tsx`，不引入主题框架。

### 规则 1：选中态用「浅灰底 + 指示条」，不用色块边框

选中项表达"当前在哪"，不需要高声量。绿色只留 3px 指示条做定位锚点。

```css
.mdocs-tree-row.active {
  background: #f2f3f5;                      /* 原：var(--mdocs-accent-soft) #E8F5E9 绿底 */
  border-left: 3px solid var(--mdocs-accent); /* 保留：唯一品牌色落点 */
  border-top: none; border-right: none; border-bottom: none; /* 原：border-color 绿框 */
}
```

### 规则 2：侧边栏与内容区用背景分层

```css
.mdocs-sidebar { background: #fafafa; }  /* 原 var(--mdocs-surface) 白 */
.mdocs-main    { background: #ffffff; }  /* 新增显式白 */
```

层次 = 背景深浅差，而不是靠边框。边框仍保留 1px 作为硬边界。

### 规则 3：控件声量分级

| 层级 | 样式 | 用途 |
|------|------|------|
| 主操作 | `primary`（绿实心） | 发布、保存、生成 |
| 次要操作 | `ghost`（无边框、灰图标、hover 浅灰底） | 收藏、评论、同步 |
| 危险操作 | `danger`（红实心） | 删除、退出 |

**改动**：`DocChrome` 里收藏与评论由 `secondary`（绿描边）→ `ghost`。

### 规则 4：浮层层级必须高于常驻层

**这是本次唯一的"功能性"视觉修复**（不只是好看）。

根因：`.mdocs-dialog-backdrop` 原 `z-index: 40`，而手机端侧边栏抽屉是 `50`、抽屉遮罩 `45` —— 于是手机端从侧边栏底部点「退出」弹出的确认框，**被侧边栏盖住**。

```css
.mdocs-dialog-backdrop { z-index: 200; } /* 原 40 */
```

**层级序（改动后，自低向高）**：

| 层 | z-index |
|----|---------|
| 阅读器顶部浮标 / agent 关闭确认 | 20 |
| 编辑器工具栏（float / docked） | 30 |
| drawer overlay | 30 |
| agent skill popover | 40 |
| 手机端 nav scrim | 45 |
| **手机端侧边栏抽屉 / 右键菜单** | **50** |
| 文档信息下拉 | 100 |
| agent FAB / **弹框 backdrop** | 200 |
| agent 面板 | 201 |
| AI 帮写全屏层 | 1200 |
| Mermaid 全屏查看器 | 12000 |

**约定**：新增浮层时，纯浮层用 `≤ 200`；模态全屏层才允许越过 `200`。若某弹框开在 agent 面板（201）之内，需单独确认是否要更高。

### 规则 5：空白状态给引导，不给空洞

原空白页只有一个 `< >` 图标。改为：

- `Code2` 图标 `64px`、`opacity 0.15`（`.mdocs-welcome-icon`）
- 文案沿用既有 i18n key `createDocToStart`（"创建或选择一个文档开始写作"），**不新增 key**
- 主操作按钮在前（新建文档），次要在后（新建文件夹 / AI 帮写）

### 规则 6：间距

树行 `padding: 4px 10px` → `6px 12px`。缩进 `8 + depth * 16` 保持不变。

## 风险与回滚

| 风险 | 缓解 |
|------|------|
| 改 `App.css` 的 `.mdocs-tree-row.active` 影响图谱焦点高亮 | 图谱焦点走独立类 `.mdocs-tree-row--graph-focus`（紫色系），不受影响 |
| 侧边栏改灰后与 hover 态撞色 | hover 用 `var(--mdocs-bg)` `#F5F5F5`，与选中 `#f2f3f5` 仍可辨 |
| `z-index: 200` 被后续新浮层超过 | 契约内固化层级表；新增浮层须对照本表 |
| 空白状态改文案影响 i18n | 复用既有 key，不新增 |

**回滚**：全部为 CSS / className 级改动，`git revert` 单个提交即可，无数据影响。

## 测试要点

1. 侧边栏选中项：浅灰底 + 左侧绿条，**无绿框**
2. 侧边栏 `#fafafa` vs 内容区 `#ffffff` 可辨
3. 树行间距比改动前宽松
4. 收藏 / 评论按钮：无边框；hover 出浅灰底
5. **手机端**：开侧边栏抽屉 → 点底部「退出」 → 确认框**完整可点，不被抽屉遮挡**
6. 手机端：新建文档弹框、恢复码弹框同样不被遮挡
7. 空白状态：图标 + 文案 + 主按钮齐全，点主按钮能开新建弹框
8. 图谱焦点高亮（紫色）未受影响
