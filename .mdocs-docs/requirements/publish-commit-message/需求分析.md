# publish-commit-message — 需求分析

> 一句话：每次发布可为 commit 附带说明（类似 git commit message），按发布来源区分自动/手动/助手/CLI；版本历史可展示并筛选自动发布。

## 背景

当前 `document_commits` 只有时间、作者、hash，回滚时难以判断「这次发布改了啥」。自动发布（`useAutoPublish`）会产生大量噪声节点，与手动/助手发布混在一起。

## 目标

1. **发布可带 message**：可选短文本，落库到对应 commit，版本历史可见。
2. **按来源填 message**：
   - **自动发布**：接口固定携带 message = `自动发布`，并标记来源 `auto`。
   - **前端手动发布（按钮/快捷键）**：弹框，用户可填 message（默认可空）；提供 **AI 生成** 入口；生成时基于「当前待发正文」相对「上一次非自动发布」的增量 diff。
   - **mdocs 智能助手发布**：助手自行生成 message（工具入参），来源 `agent`。
   - **CLI `update`**：支持 `--message`，来源 `cli`；不传则空字符串。
3. **版本历史**：列表展示 message；增加「隐藏自动发布」筛选开关，**默认关闭**（不过滤）。

## 非目标（本期不做）

- 不改 commit DAG / merge-base / 冲突解决语义。
- 不做 message 全文检索 / 按 message 搜历史。
- 不强制所有历史 commit 回填 message（旧数据为空即可）。
- 不在本期做「编辑已发布 commit 的 message」（commit 仍不可变）。
- 不把 AI 生成做成必须依赖打开聊天面板的长会话（见设计契约推荐方案）。

## 验收标准

- [ ] 自动发布产生的 commit：`source=auto`，`message=自动发布`。
- [ ] 手动点发布：出现 message 弹框；不填可发布；填了可在版本历史看到。
- [ ] 弹框内 AI 可生成候选 message（可再编辑后发布）；diff 基线为最近一次非 `auto` 的 commit。
- [ ] 助手写文档类工具发布时可带 message；prompt/工具约定助手应生成说明。
- [ ] CLI `update` 支持 `--message`；版本列表能看到。
- [ ] 版本历史可开关「隐藏自动发布」；默认显示全部。
- [ ] 旧 commit（无列/空值）在筛选时视为非自动（始终显示）。

## 本次变更（2026-10-23）— merge 发布说明（merge-message）

> 一句话：冲突合并收尾**不再复用普通发布说明文案与 suggest-commit-message**；专用弹窗 + 新接口，输入 left/right/merged，只写 message，不改决议。

| 做 | 不做 |
|----|------|
| Merge「完成合并并发布」走 **合并说明** 弹窗（文案区别于普通发布） | 与 ai-merge 共用一个接口 |
| `POST .../suggest-merge-message`：local + remote + merged（可选 base） | AI 直接改正文 / 填 resolution |
| 「AI 生成」调新接口；`source` 仍 `manual` | 新增 `source=merge`（本期不必） |
| 弹窗 z-index 高于 merge overlay（已修 2500） | 改 diff3 / merge-plan |

与 **ai-merge** 关系：ai-merge 填 resolution；本变更在用户确认 merged 之后生成说明。可串行，契约上两接口。
