# publish-commit-message — 设计契约

> **状态**：已同意（2026-10-22）  
> 拍板：AI=弹框 suggest 接口；diff 基线=最近非 auto；冲突合并后再弹 message 框。

## 方案摘要

在每次 publish 写入的 `document_commits` 行上增加 **message** 与 **source**，由调用方按入口约定填写；版本历史展示 message，并支持前端过滤 `source=auto`。手动发布前增加确认弹框（可空 message + AI 建议）；AI 建议基于「待发内容 vs 最近一次非 auto commit」的文本 diff，走一次性 LLM 接口（不强制开聊天）。

### 数据模型

`document_commits` 新增列（启动时 `ALTER TABLE` 迁移，与现有 `migrateDocuments*` 同模式）：

| 列 | 类型 | 含义 |
|----|------|------|
| `message` | `TEXT NOT NULL DEFAULT ''` | 发布说明；空串合法 |
| `source` | `TEXT NOT NULL DEFAULT 'manual'` | 枚举见下；**旧行迁移后一律 `manual` + 空 message**（无法回溯） |

`source` 取值：

| 值 | 谁写入 | 默认 message |
|----|--------|--------------|
| `auto` | 前端自动发布 | 固定 `自动发布`（服务端也可在 `source=auto` 时强制覆盖，防客户端漏传） |
| `manual` | 前端按钮/快捷键/冲突合并确认后的手动发布、版本恢复 | 用户输入或空 |
| `agent` | 智能助手工具写后发布 | 助手生成（工具参数）；缺省空 |
| `cli` | mdocs-cli / 带 CLI token 的脚本 | `--message` 或空 |

服务端校验：`source` 仅允许上表四值；`message` 建议上限 **500 字符**（超出 400）。

### HTTP API

**`PUT /api/documents/:id`** 请求体增量：

```ts
{
  // …既有 content / displayName / permission / contentFormat / version
  message?: string;          // 默认 ''
  source?: 'auto' | 'manual' | 'agent' | 'cli';  // 默认 'manual'
}
```

- `source=auto` → 服务端将 `message` 规范为 `自动发布`（忽略客户端其它文案）。
- merge 发布、restore 成新 commit 同样写入这两列（restore 建议 `source=manual`，message 默认空或前端可填；本期 restore 弹框不做，message 空即可）。

**`GET .../commits` / `GET .../commits/:commitId`** 的 summary/detail 增加：

```ts
{ message: string; source: 'auto' | 'manual' | 'agent' | 'cli' }
```

本期列表过滤在**前端**完成（全量已按时间倒序返回）；不新增 query。若日后 commit 极多再考虑服务端 `excludeAuto`。

**AI 建议 message（新接口）**：

`POST /api/documents/:id/suggest-commit-message`

```ts
// body
{ content: string; contentFormat?: 'markdown' | 'lexical' }
// response
{ data: { message: string; baseCommitId: string | null } }
```

逻辑：

1. 鉴权：与编辑相同（`edit`）。
2. 找该文档最近一条 `source != 'auto'` 的 commit 作 base（无则 `baseCommitId=null`，diff 对空文档）。
3. 将 base blob 与请求 `content` 规范为可 diff 文本（md：Lexical→markdown；html：原文；sheet：列/行摘要 JSON 稳定序列化）。
4. 截断后的 unified diff（例如合计 ≤12k 字符）+ 短 system prompt，调用访客默认 Agent 模型，生成 ≤80 字中文说明。
5. 无模型配置 / LLM 失败 → 4xx/5xx 明确错误，前端 toast，不挡手动填写。

### 前端

| 入口 | 行为 |
|------|------|
| `useAutoPublish` → `publishDraftFromList` | `source: 'auto'`（message 可省略，服务端强制） |
| DocChrome / 编辑器发布按钮、发布快捷键 | **先弹** `PublishMessageDialog`：textarea（可选）+「AI 生成」+「发布」/「取消」；确认后 `source: 'manual'` + message |
| 冲突合并后的最终 PUT | 同手动：再走一次弹框，或复用已确认的 message（推荐：合并确认后再弹一次，避免漏） |
| `VersionHistoryPanel` | 列表项展示 message（空则不占行）；工具栏 toggle「隐藏自动发布」，默认 off，状态可 `sessionStorage` 记忆 |

弹框「AI 生成」：调 suggest 接口，结果写入 textarea，用户可改后再发布。

### 智能助手

所有会调用 `updateDocument` 的写工具（`overwrite_document` / `append_document` / `replace_document_markdown` / sheet 写工具等）增加可选参数 `message`；system prompt / 工具说明要求：**发布时必须生成简短 message**（写了什么）。调用时 `source: 'agent'`。

### CLI（`mdocs-cli` 仓库）

`update <id> ... --message "..."` → PUT 带 `message` + `source: 'cli'`。  
本仓仅保证 HTTP 契约；CLI 改动在 [mdocs-cli](https://github.com/xuhuafeifei/mdocs-cli) 同步。

### 「上一次手动发布」定义（AI diff 基线）

**采用：最近一条 `source !== 'auto'` 的 commit**（含 `manual` / `agent` / `cli` 及迁移后的旧数据）。  
理由：自动发布只是定时落盘，不应成为「增量说明」的基线；助手/CLI 与按钮同属「有意发布」。

## 风险与回滚

- LLM suggest 耗时/失败：仅影响按钮，不阻塞空 message 发布。
- diff 过大：截断；可能建议偏泛，可接受。
- 旧数据全标 `manual`：筛选「隐藏自动」不会误藏历史节点。
- 回滚：忽略新列即可读旧逻辑；新前端依赖字段时给默认 `''` / `'manual'`。

## 测试要点

- auto PUT → DB `source=auto` `message=自动发布`（即使 body 乱传 message）。
- manual 空 message / 有 message 均可发布；历史可见。
- suggest：无非 auto base、有 base、无模型配置三条路径。
- 版本列表 toggle 只藏 auto；head 为 auto 时仍可选中预览（若未过滤掉）。
- agent 工具带 message 落库 `source=agent`。
