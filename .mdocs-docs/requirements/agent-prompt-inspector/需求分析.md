# 智能助手 · 系统提示词诊断 — 需求分析

> 一句话：点输入框旁那个「上下文占比圆环」，能看到本轮**真正发给模型**的 system prompt，以及按段落的体量占比。

## 背景

- normal 模式的角色规则已经 3.8k 字；再叠加 soul 与 skill 目录，提示词体积只能靠猜。
- 调试「模型为什么不按套路走」「上下文为什么爆」时，没有任何入口能看到实际拼好的 prompt。
- 改了 `soul/mdocs.md` 或私人 Skill 后，也没有直观反馈"到底进没进上下文、占多少"。

## 目标

1. 从智能助手浮球（那个圆）一键打开弹框，展示**完整** system prompt。
2. 按段落给出 **字符数 / 估算 token / 占比%**，并用条形图直观呈现。
3. 数据与真实请求**同源**：复用 `buildSystemPrompt`，不是另写一份拼接逻辑。

## 非目标（本期不做）

- 在线编辑提示词并回写（diagnostics only）
- 提示词历史对比 / 版本 diff
- plugin-pipeline 模式（该模式提示词结构不同，本期只看 normal / coding）
- 精确 tokenizer（不引入 tiktoken 类依赖，用粗估）

## 验收标准

- [x] 点击输入框旁的上下文占比圆环 → 弹框（原浮球角标方案已废弃）
- [x] 弹框显示总字符数、估算 token、段数
- [x] 每段显示 label、字符数、token、占比与条形图，占比合计 100%
- [x] 完整 prompt 可滚动查看、一键复制
- [x] 与大模型实际收到的内容一致（除 MCP 提示与多模态附件）

## 依据

- 实现：`src/server/agent/Agent/system-prompt.ts`（`assembleSystemPrompt`）
- 统计：`src/server/agent/Agent/prompt-stats.ts`
- 接口：`GET /api/agent/system-prompt`
- 待确认：是否需要把 MCP 工具提示也纳入（需实际连一次 MCP，成本高）
