# 智能助手 · 系统提示词诊断 — 设计契约

> **状态**：已同意（2026-10-29，会话中直接指定实现）

## 方案摘要

1. **后端拆分**：`buildSystemPrompt` 保留为兼容包装，新增 `assembleSystemPrompt` 返回
   `{ sections: [{id,label,text}], prompt }`。段落 id：`base` / `ui-context` / `soul` /
   `skill-meta` / `mcp` / `pipeline` / `pipeline-yaml`。
2. **统计**：`prompt-stats.ts` 给出 `chars / tokens / sharePercent / windowPercent`。token 用粗估
   （CJK ≈ 1 token/字，其余 ≈ 4 字符/token），不引第三方 tokenizer。
   **两套基准别混**（2026-11-03 修订）：`sharePercent` 是段间构成（条形长度用它），
   `windowPercent` 是占模型上下文窗口（行尾百分比用它）。分母取该访客 AI 配置的
   `contextWindow`（缺省 `DEFAULT_AGENT_CONTEXT_WINDOW`），与圆环同源。
3. **接口**：`GET /api/agent/system-prompt?mode=normal|coding`，需要访客身份；
   返回 `{ mode, sections, total, prompt, notes }`。
4. **前端**：输入框旁的**上下文占比圆环**（`ContextUsageRing`）改为按钮，点击 → `SystemPromptDialog`；
   弹框内三段式：总量 → 分段条形 → 全文（可复制）。弹框 `createPortal` 到 `body`，避免被阅读模式/设置页 transform 带偏。
   （早期用浮球角标 `{}` 作为入口，已废弃。）

## 风险与回滚

| 风险 | 说明 |
|------|------|
| 与真实请求的偏差 | 预览不含 MCP 工具提示（要真连一次 MCP）与多模态附件；弹框里已注明 |
| token 误差 | 只是比例参考，不做计费依据 |
| 段落拆分漂移 | 拆分与拼接在同一函数内，新增段落必须同时给 label，否则统计少一段 |
| 百分比被误读 | 分母是「窗口」不是「提示词」：2,361 tokens 只占 1M 窗口 0.24%，但占提示词 85%，所以条形与百分比基准不同，弹框里有图例说明 |
| 回滚 | 删掉入口 + 路由即可，`buildSystemPrompt` 行为未变 |

## 2026-11-03 修订

- 段落 `base` 的 label 由「角色规则（normal）」改为「系统提示词（角色规则）」：这一段就是系统提示词本体，
  之前叫「角色规则」容易被当成另一类提示词。
- 占比分母从「提示词自身字符数」改为「模型上下文窗口 token」，接口新增 `window` 与
  `total.windowPercent`，字段 `percent` 拆成 `sharePercent` / `windowPercent`。
- 窗口未知（配置缺失）时窗口百分比为 0，弹框显示「窗口未知」并回退到 `sharePercent`。

## 2026-11-04 增量（会话中指定实现）

圆环统计 = **系统提示词 + 工具定义 + 会话历史**，但弹框原先只露系统提示词，看不出动态积累。

1. `GET /api/agent/system-prompt` 增返回 `buckets`（system / tools / history）与 `items`（可点开看正文：
   系统各段全文、各工具 schema、每条 user/assistant/tool 消息正文）。
2. 可选 query：`sessionId`（缺省 lastOpened）、`domainId` / `documentId`（拼 ui-context）。
3. 弹框改「上下文诊断」：顶栏三桶对齐圆环 → 点桶看条目列表 → 点条目看/复制正文。
