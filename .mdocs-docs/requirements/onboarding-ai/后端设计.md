# onboarding-ai — 后端设计（可开发）

> **范围**：仅后端。前端另开。  
> **原则**：Pi 管模型与流；我们只做 Config、Skill、两 tools，以及把 Pi 事件接到 HTTP。  
> **不做**：自研 Runner / 自研 stream 抽象 / 二次封装 model 交互。

## 1. 模块（三块 + 路由）

```
src/server/agent/
├── Config/config.ts       # env → apiKey / endpoint / model；enabled
├── Skill/skill-loader.ts  # list / read 包内 agent-skills
└── Agent/
    ├── run.ts             # 主入口：model → agent → skill → prompt → onEvent
    ├── session-manager.ts # （待）tenant jsonl load/append
    ├── system-prompt.ts
    └── tools.ts

src/server/routes/agent.routes.ts   # 薄：调 runOnboardingChat({ onEvent }) → SSE
scripts/build-agent-skills.mjs
```

挂载：`app.use("/api/agent", buildAgentRouter())`（`authMiddleware` 之后）。

**分层（对齐 agent-demo）**：

- **route**：只校验入参、开 SSE、调用 agent、把 `onEvent` 写成 SSE；不感知 skill / prompt / Pi。
- **agent `runOnboardingChat`**：主流程 + `onEvent` 回调供前端片段渲染。

## 2. Config（个人 SQLite；增量草案）

**运行时真源**：表 `agent_model_configs`（按 `visitor_id`），不再用 `MDOCS_DEEPSEEK_API_KEY` 决定 enabled。

| 仍可用的 env | 含义 |
|--------------|------|
| `MDOCS_AGENT_SKILLS_DIR` | 覆盖 skills 根 |
| `MDOCS_SITE_DOCS` | 仅 skills 构建脚本 |

| 常量 | 值 |
|------|-----|
| endpoint | `https://api.deepseek.com`（写死） |
| model 白名单 | `deepseek-v4-flash`、`deepseek-v4-pro` |

```ts
export interface VisitorAgentConfig {
  id: string;
  ownerVisitorId: string;
  name: string;
  provider: "deepseek";
  modelId: "deepseek-v4-flash" | "deepseek-v4-pro";
  apiKey: string; // 仅服务端；API 对外脱敏
}

/** 空白 name → `${visitorName}的 ds 配置` */
export function resolveConfigName(name: string | undefined, visitorName: string): string;
export function getVisitorAgentConfig(visitorId: string): VisitorAgentConfig | null;
export function upsertVisitorAgentConfig(...): VisitorAgentConfig;
export function resolveSkillsRoot(): string | null;
```

`getAgentStatus(visitorId)` / `runOnboardingChat({ visitorId, ... })` 读上表；无 apiKey → 不可用。

表：`agent_model_configs(id PK, owner_visitor_id UNIQUE, name, provider, model_id, api_key, updated_at)`。

## 3. Skill（仍要：我们的知识，不是 Pi 的事）

磁盘 / frontmatter / `SkillMeta` / `SkillLoader.list|read` / `build-agent-skills` —— 与前版相同，略。

Tools 实现里直接调 loader，不另起「知识服务」。

## 4. Agent 主流程（`run.ts`）

```ts
export async function runOnboardingChat(params: {
  visitorId: string;
  message: string;
  onEvent: (event: AgentStreamEvent) => void;
  signal?: AbortSignal;
}): Promise<void>;
```

**已落地顺序**（无 session）：

1. model — DeepSeek via Pi  
2. load skill → tools  
3. `buildSystemPrompt()`  
4. `new Agent({ systemPrompt, model, tools, streamFn })`  
5. `subscribe` → SSE；`await agent.prompt(message)`

**Session 增量（待同意）** — 见 [`设计契约.md`](./设计契约.md) §1.5：

```
ensureLastOpened(visitorId)
  → load jsonl → historyMessages
  → new Agent({ …, messages: historyMessages })
  → subscribe（append user/assistant + SSE）
  → agent.prompt(本轮 message)
```

- 持久真源：`tenant/{visitorId}/agent/session/{sessionId}.jsonl`  
- `Agent.messages` = 请求内内存副本，非全局常驻  
- 不把历史糊成单字符串 prompt

## 5. HTTP（薄）

### `GET /api/agent/config`

```json
{ "data": { "id": "uuid", "name": "张三的 ds 配置", "modelId": "deepseek-v4-flash", "hasApiKey": true, "apiKeyMasked": "…xxxx" } }
```

无记录：`{ "data": null }` 或等价空对象（实现时与前端约定一种即可）。

### `PUT /api/agent/config`

```json
{ "modelId": "deepseek-v4-pro", "name": "团队答疑", "apiKey": "sk-..." }
```

- `name` 省略或空白 → 服务端用 `{当前访客昵称}的 ds 配置`  
- 省略 `apiKey` → 保留旧值；空串 / 非法 model → 400  
- upsert：首次生成 `id`，之后同一 owner 更新不换 `id`

### `GET /api/agent/status`

```json
{ "data": { "enabled": true, "skillsReady": true, "model": "deepseek-v4-flash" } }
```

逻辑：本人 SQLite 配置 + `skills.isReady()`，**不**碰 Pi。

### `POST /api/agent/chat`

Body：

```json
{ "message": "如何发布文档？" }
```

- SSE：`text_delta` / `sources` / `done` / `error`  
- Session 增量后：每请求 load jsonl → hydrate `Agent.messages` → append；body **仍只带** `message`  

### `GET /api/agent/session`（待实现）

```json
{
  "data": {
    "sessionId": "uuid",
    "messages": [
      { "role": "user", "content": "…" },
      { "role": "assistant", "content": "…" }
    ]
  }
}
```

面板 open 时拉取；与 jsonl 真源一致。无 session 时 `messages: []`。

`!enabled` / `!skillsReady` → **503 JSON**，不开 SSE。

## 6. 边界

| 我们写 | Pi 做 |
|--------|--------|
| Config、Skill 文件、两 tools、system 文案 | model、stream、tool loop、agent 事件 |
| Express 路由 + SSE 胶水 | — |
| skills 构建脚本 | — |

## 7. 实现顺序

1. `skills:build` + SkillLoader  
2. Config + `runOnboardingChat`（model → agent → skill → prompt → onEvent）  
3. `agent.routes.ts` 薄挂载  
4. curl 验收
