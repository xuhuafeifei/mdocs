## 本次增量：个人 Model 配置（待同意）

### 产品一句话

当前访客在 **设置 → AI** 保存自己的 DeepSeek 配置（`id` + `name` + `modelId` + `apiKey`）；仅本人 chat 可用。  
未填名称时默认为 **`{访客昵称}的 ds 配置`**。  
**不是**「分发 apiKey」；未来若开放给别人，分发的是 **配置使用权**（按 `config.id` 授权，被授权人看不见 key）。

### 决策

| 项 | 选择 |
|----|------|
| Provider | 仅 DeepSeek；endpoint 写死 `https://api.deepseek.com`（UI 不暴露） |
| 模型白名单 | `deepseek-v4-flash`、`deepseek-v4-pro` |
| 标识 | 每条配置有 **`id`（UUID）** + **`name`（展示名）**；所有者为 `owner_visitor_id` |
| 本期数量 | **一人一份**（`owner_visitor_id` UNIQUE）；表结构用 `id` 便于下期多配置 / 授权 |
| 默认名称 | 用户未填或只填空白 → **`{访客昵称}的 ds 配置`**（昵称取当前 visitor.name） |
| 存储 | SQLite 表 `agent_model_configs` |
| 真源 | 以 SQLite 为准；运行时 **不读** `MDOCS_DEEPSEEK_*` env |
| 读回安全 | GET 回 `id`、`name`、`modelId`、`hasApiKey`、`apiKeyMasked`；明文只在 PUT 写入 |
| PUT 语义 | 必填合法 `modelId`；`name` 可选；`apiKey` **省略** → 保留旧值；**空串** → 400；首次保存必须非空 key |
| enabled | 本人有非空 apiKey **且** skillsReady |

### 数据

```
agent_model_configs
  id                TEXT PK     UUID
  owner_visitor_id  TEXT UNIQUE → visitors.id（本期一人一行）
  name              TEXT        展示名；空则服务端填默认「{昵称}的 ds 配置」
  provider          TEXT        固定 'deepseek'
  model_id          TEXT
  api_key           TEXT        明文（本期不 at-rest 加密）
  updated_at        TEXT
```

下期若做授权：`agent_model_config_grants(config_id, grantee_visitor_id)`，引用本表 `id`；**不**复制 apiKey。

### API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/agent/config` | 本人配置：`{ id, name, modelId, hasApiKey, apiKeyMasked }`；无记录时 `null` 或 `hasApiKey: false` |
| PUT | `/api/agent/config` | upsert 本人那一行：`{ modelId, name?, apiKey? }`；返回含 `id`/`name` |
| GET | `/api/agent/status` | `enabled` / `skillsReady` / `model` / 可选 `configId` |
| POST | `/api/agent/chat` | 不变；内部按本人配置 `id` / owner 取 key；SSE 含 `text_delta` / `sources` / `done` |

手册链接写死：`https://xuhuafeifei.github.io/mdocs-site/docs/{source去.md}.html`（例：[无账户身份识别](https://xuhuafeifei.github.io/mdocs-site/docs/core-concepts/no-account.html)）。tool 读正文时累计 sources，前端展示「已阅读 N 个页面」。

### 前端

[`SettingsPage`](../../../src/web/app/SettingsPage.tsx) Tab「AI」：

- 已有配置：**只读**展示 name / model / 脱敏 key；点「编辑」进入修改态  
- 无配置：直接进入编辑态（首次保存）  
- 编辑态：名称、`MiniSelect` 选模型、apiKey 输入 + **小眼睛**切换明文/掩码（仅当前输入框，无解密 API）  
- 保存 → PUT；取消还原草稿；`api_key` **明文落库**（本期不做 at-rest 加密）  
- 可展示 `id`（小字）

未配置：status 不可用；入口降级（与既有一致）。

### 明确不做（本期）

- 配置授权 / 「我可用的配置」列表 / 选别人的配置  
- token 用量监控 / 配额  
- 多 provider、自定义 endpoint、一人多条配置  
- apiKey 加密 at rest  

### 愿景（不实现，防歧义）

- **配置授权**：所有者授权 visitor；被授权人只见「可用配置」卡片，不见 key。  
- **用量**：共享后再做；按 config 所有者 + 调用者累计 token。

## 风险与回滚

| 风险 | 缓解 |
|------|------|
| apiKey 明文落库 | 契约明示；仅所有者可读 API；下期可加密 ADR |
| 去掉 env 后本地开发要先走设置页 | 文档说明；或一次性引导 |
| 模型 id 写错 | 服务端白名单校验 |

## 测试要点

1. 无配置 → status.enabled=false；chat 503。  
2. PUT 合法 model + key → GET 脱敏；chat 可用。  
3. PUT 只改 model、省略 apiKey → 旧 key 仍可用。  
4. PUT 空 apiKey → 400。  
5. 非法 modelId → 400。  
6. 访客隔离：A 的配置不影响 B。  
7. 未填 name → 落库为 `{visitor.name}的 ds 配置`；自填 name 原样保存（trim 后非空）。  
8. 新建后响应含稳定 `id`；再次 PUT upsert 同一 `owner`，`id` 不变。
