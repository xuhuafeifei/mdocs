# 登录 / 注册弹框 — 需求分析

> 一句话：去掉「注册 / 登录」双 Tab，**主界面即登录**，注册降级为登录下方的一行文字入口。
> 状态：**已同意**（2026-09-13）· 已落地。

## 背景

访客首访（或未登录）时弹出 `VisitorRegisterDialog`，原实现是**顶部双 Tab：注册 | 登录**，且**默认停在「注册」Tab**。

问题不在美观，在**引导方向**：

- 默认看到注册 → 用户顺着"注册"的思路走，不会去找登录
- 但 mdocs 的实际使用场景里，**回访用户远多于新用户**（换设备、清 Cookie、恢复身份）
- 双 Tab 把注意力劈成两半，两条路径都变得不明显

产品判断：**默认露登录**。新用户看到「没有账号？」自然会去注册；老用户一步到位。

## 目标

1. **默认显示登录界面**（密码登录 / 恢复码 两个子方式，保留）
2. 登录表单下方一行：**「没有账号？点击注册」**
3. 注册流程内保留 **「已有账号？点击登录」**，可随时切回
4. 不引入 Tab 组件，不引入路由

## 非目标

- 改注册/登录的**接口契约**（`registerVisitorApi` / `loginWithPasswordApi` / `recoverVisitorApi` 不变）
- 改密码规则（仍为可选、≥4 位）
- 加"记住我"、OAuth、邮箱验证等
- 改 `phase` 状态机（仍是 `loading` / `needsRegister` / `ready`）

## 验收

1. 首访弹框**第一眼是登录**，不是注册
2. 登录页底部有「没有账号？点击注册」，点击进入注册第一步
3. 注册第一步（填名称）底部有「已有账号？点击登录」，点击回登录
4. 注册第二步有「← 返回上一步」，回注册第一步
5. 登录/注册两态**不共存**（无 Tab 栏）
6. 切换页面时清空上一个页面的错误提示

## 依据

- 组件：`src/web/app/VisitorRegisterDialog.tsx`
- 调用：`src/web/app/App.tsx`（`phase === "needsRegister"` 分支）
- 接口：`src/web/services/endpoints.ts`（`registerVisitorApi` / `loginWithPasswordApi` / `recoverVisitorApi`）
- `map/frontend.md` → 「登录 / 注册弹框」
