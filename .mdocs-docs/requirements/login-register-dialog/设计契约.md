# 登录 / 注册弹框 — 设计契约

> **状态**：已同意（2026-09-13，**已落地**；含一处遗留见文末）
> 未经「已同意」不得开始写代码。

## 方案摘要

用**单页状态机**替代 Tab：

```text
page: "login" | "register" | "register-password"
                  ↑ 默认 "login"
```

```text
┌─ 登录（默认） ─────────────────────┐
│  [用户名+密码] [恢复码]   ← 子方式   │
│  ┌──────────────────────────┐     │
│  │ 用户名 / 密码 → [登录]     │     │
│  └──────────────────────────┘     │
│      没有账号？点击注册 ←──────────┼─ 切到 register
└───────────────────────────────────┘

┌─ 注册① 填名称 ────────────────────┐
│  名称 → [下一步]                  │
│      已有账号？点击登录 ←──────────┼─ 切回 login
└───────────────────────────────────┘

┌─ 注册② 设密码（可选，≥4 位） ──────┐
│  密码 → [完成注册]                │
│      ← 返回上一步                  │
└───────────────────────────────────┘
```

### 与旧实现的差异

| 项 | 旧 | 新 |
|----|----|----|
| 顶部 | 双 Tab「注册 \| 登录」 | **删除 Tab 栏** |
| 默认态 | `tab = "register"`（注册优先） | `page = "login"`（登录优先） |
| 注册入口 | 顶部 Tab | 登录底部「没有账号？点击注册」 |
| 登录入口 | 顶部 Tab | 注册①底部「已有账号？点击登录」 |
| 状态变量 | `tab` + `registerStep: 1 \| 2` | `page` 三态（更直白） |

### 保留不变

- 登录两种方式：用户名+密码 / 恢复码
- 注册两步流与"密码可选"的说明文案
- `props.onSubmit` / `props.onRecover` 回调签名
- `busy` / `localError` 处理；`switchToLogin` / `switchToRegister` 清空错误

## 测试要点

1. 打开弹框：**第一眼是登录**（用户名+密码），无 Tab 栏
2. 登录底部「没有账号？点击注册」→ 进注册第一步

7. 恢复码方式：空码 → 提示"请输入恢复码"
8. 页面切换时 `localError` 被清空
9. 注册成功 → 进入主界面

## 遗留问题

### 「注册完成后立刻切回登录」实际未生效（死代码）

需求原文要求**注册完成后切回登录界面**。`submitRegister` 里也照此写了：

```ts
await props.onSubmit(registerName.trim(), pwd || undefined);
setRegisterName(""); setRegisterPassword("");
setPage("login"); setLoginMode("password");
setLoginName(registerName.trim()); setLoginPassword(pwd || "");
```

**但这段不可达。** `props.onSubmit` 即 `App.handleRegister`，其最后一步是 `setPhase("ready")`：

```ts
await initDomainsAndTree(...);
setPhase("ready");   // ← 弹框随即卸载
```

而 `VisitorRegisterDialog` 只在 `phase === "needsRegister"` 时渲染。所以 `await onSubmit(...)` 返回时组件已被卸载，后续 `setPage("login")` 等全部无效。

**实际行为**：注册成功 → 后端建会话（`registerVisitorApi` 自动设 Cookie）→ **直接进入主界面**，不经过登录页。

**这意味着「切回登录」在设计上是自相矛盾的**：注册即登录，没有"注册完还要再登录一次"的场景。

**待拍板，二选一**：

| 选项 | 含义 | 代价 |
|------|------|------|
| A（推荐） | 删掉 `submitRegister` 里那段死代码，契约明确写"注册成功即登录，直接进主界面" | 与需求原文措辞不一致，需你确认 |
| B | 让注册**不自动建会话**，注册成功只建账号并回到登录页，用户手动登录一次 | 改后端 `registerVisitorApi` 语义 + Cookie 行为，影响面大 |

当前代码状态 = A 的行为 + 一段 B 的残留代码。
