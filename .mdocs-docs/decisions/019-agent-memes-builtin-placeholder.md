# 019 — 表情包走内置占位符，不走 MCP 插件

- **状态**：accepted（2026-11-03，人审）
- **上下文**：mdocs 已有通用 MCP 客户端（`src/server/mcp/mcp-client.ts`，stdio + Streamable HTTP，按访客隔离租户 MCP），
  也能通过插件流水线装第三方 MCP。看上去「把 dsh-meme 包成 MCP server」是现成路径。
- **备选**
  1. MCP 插件：把表情包能力做成 MCP server，用户安装后工具名 `mcp__meme__send_meme`。
  2. 内置工具 + 占位符：模型输出占位符，前端换图。占位符里放 **资源 id**（不是分类）：
     id 已在正文里，刷新/重开/重启都能重放同一张，不需要随机与 seed。
- **决策**：选 **2**。表情包是「对话体验」而非「能力扩展」：
  - MCP 只解决工具可调用，解决不了「图库管理 UI」与「消息里的图片渲染」这两处深耦合前端的活；
  - 图库要按访客隔离，外部 MCP 进程是全局的，隔离要另做；
  - 占位符方案让模型零认知负担（只认识「id + 一句描述」），不占工具槽、不产生 tool 往返延迟、不污染上下文；
  - 图库用文件维护（`meme.json` + 图片），系统库只读可覆盖，租户库随访客隔离。
- **后果**
  - 需要在 `assembleSystemPrompt` 增加 `memes` 段落（可被「提示词诊断」统计）；
  - 前端渲染层要能吃占位符（同一套解析也适用于未来的其他内联标记）；
  - 第三方想接入自有图库仍可走 MCP，属于附加通道，不是主路径。
